# 开发集成

本文件只负责项目落地。切图来源/导出/准入由素材规则负责，交互由交互规则负责，数值与完成标准由视觉规则负责。

## 项目与设计系统

先读取项目约束、技术栈、字体、组件、token、已有改动与构建命令。复用现有组件须核对实际视觉和行为，名称相同不代表同一个图形或状态。设计数据是本次还原依据；已有 token 与设计值不一致时记录冲突，不以“用了正确 token”豁免像素、属性或几何门槛。

默认只改本次页面/组件。修改公共组件、全局 CSS/变量、主题或第三方覆盖样式前检索消费方并评估影响；已有明确授权覆盖时继续，否则先完成局部可行部分并就具体共享修改取得确认。不要为本次页面随意新增依赖、改路由配置、API 或构建系统。明确设计内的导航与交互可使用现有机制实现，不等于重写业务。

真实字体与字重必须加载。对无障碍、未覆盖状态/断点或设计内部矛盾，先完成有证据的部分；需要改变设计意图或扩大范围时说明具体冲突。键盘、焦点、语义控件和 reduced-motion 的处理按交互规则执行。

## 正式素材存放和命名

只有素材规则确认通过的最终文件才能落盘引用。先遵守现有项目规范；无规范时：通用资源放 src/assets/images，页面/组件私有资源放使用方 images 子目录，确需绝对 URL 的资源放 public。不要为了统一目录迁移无关既有资源。

输出使用描述内容的 kebab-case，可为图标添加 -icon；保留设计 Export suffix 和来源追溯，路径冲突按素材规则稳定区分。此处是开发产物命名，不要求设计师改 Figma 图层名，也不能依据 _ic/_bg/_bt/_export 判断导出意图。

不得提交临时 URL、中间 PNG、报告、快照或差异图。任务结束只清理有来源记录的临时产物，不删除用户资产。

## 图片与 SVG 引用

- 图形必须有可追溯的 Figma 来源；禁止手写 SVG、Emoji/Unicode、图标字体或 CSS 临摹来顶替设计图形。普通布局、纯色/简单渐变、圆角等按设计用 CSS 实现，不把所有 CSS 都误判为伪造素材。
- 现有图标组件只有来源和图形、颜色、透明度、状态均经核验且满足素材要求时才复用；不凭名字选择。
- 项目已配置 SVGR 且图标适合组件化时可使用；否则用现有图片方案。不强制其他框架安装 React/SVGR，不把合法 SVGR 编译产物误判为手写图形。
- 单色 SVG 需要动态控色时，只在证明保持原有视觉后使用 currentColor，并保留原始值供验证。保留 fill-opacity、stroke-opacity、整体 opacity、clipPath、mask、渐变、路径与 viewBox；多色图形、品牌 Logo 默认保持原样。任何转换后重新验证，禁止批量删除透明度或蒙版填充。
- 容器和资源显示尺寸明确，保持设计比例与 viewBox；响应式 auto 只有在确定容器约束和比例并验收通过时使用，不能让固有尺寸意外撑开页面。
- 带阴影/模糊/描边的导出区分布局槽位与渲染出血；按实测偏移建立外层布局槽位与内层出血区域，避免把较大的渲染图硬压进布局框。

## 修复与验证次序

按视觉规则的 L0–L5 顺序排查。先核对本轮改动、资源与环境，再查父级公共偏移，最后查局部数值。不要通过对子节点不断加 margin 掩盖父级错误。

修复值必须来自节点声明、变量或标注。截图/diff 用来定位问题，不从像素反推颜色、间距、渐变或透明度作为权威值。属性读不到时换合适的读取通道，仍读不到则 unverified。

实际浏览器验证不可用时只做可执行的静态诊断，不声称完成。运行项目已有构建或聚焦测试；构建通过只证明可运行，最终报告必须同时满足视觉与交互规则。

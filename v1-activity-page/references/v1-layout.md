# V1 PC 尺寸与布局

设计画布固定宽 **1920px**。固定PNG画布、控件定位框与可见造型分别处理：画布约束导出和页面布局，不要求可见主体成为填满画布的方框。曲线、非矩形轮廓、开口边缘、分层形态或参考明确支持的其他造型可在既定画布内设计；保持文字与操作安全区、主体比例及用户规定的间距。按钮可见宽高要求只检查外接范围，不要求填满四角或所有像素。下表的“输出画布”是本 skill 最终 PNG 的像素尺寸；线上示例的原图可能是 2 倍尺寸或由浏览器缩放。模块依确认的顺序上下紧贴，不再插入额外空白。独立前景资产在外轮廓或安全边保留真实透明像素，主体内部可有实色、渐变及材质填充；“透明PNG”不表示整块面板必须镂空。模块背景、头图、Banner 与概率弹窗背景保持不透明。

**输出切片与视觉场景分开规划。** 先取得用户本次选择的背景方式，再按下表导出模块背景。选「整体衔接」时，将头图及相邻连续模块设计成同一张1920px宽母背景，再按累计 y 坐标切片；不要逐片重新缩放或独立居中裁剪。例如头图600px＋套餐＋盲盒＋两项任务的整页母背景高2557px，依次切为600／520／806／631px；不能把600px头图独立生成后接到1957px内容母图上，母背景保存在 `design/`，`assets.json` 列头图和三张标准背景切片。选「按模块区分」时先设计各区明显不同的底色／明度，再将背景放入共同坐标的组合母图，联合完成每处过渡后原像素导出；不要求两区底色相同，但跨界图形必须完整，不允许独立裁切造成断口。两种模式均按[跨界组合与导出](#两种模式的跨界组合与导出)执行。两种方式都保留现有素材角色、模块高度、前景尺寸及间距。

尺寸与功能以本文件的模块规格为准。用户确认的输出规格优先于示例原文件像素；布局依据不作为新活动的默认画风或视觉参考。

整体衔接必须制作从头图到页尾的完整连续背景，母图包含头图和全部启用内容模块，统一设计当前KV的场景、材质或图形与内容留白；按功能导出切片只是交付方式，不改变整页背景的完整性。按模块区分采用依据相容运营整页、模块或有效背景局部参考设计、层次丰富且内容清楚的独立模块底景，允许章节底色切换，但跨界图形仍须在同一组合母图内完整设计后导出，避免每区各画一张照片或完整场景。两种模式保持上面的尺寸、间距和模块结构，具体背景组织见[活动氛围与内容焦点](art-direction.md#活动氛围与内容焦点)。

按模块区分时，先按[模块配色与分区验收](art-direction.md#分块模式的上下分区)将KV配色分配为上下章节的独立色面，允许显著深浅和相容色相变化，不要求同光照或场景连续，每对交界必须有明显的大面积底色／明度差异，不能仅用近似色号；留白、纹理、图形密度和标题分组只能辅助，不代替底色差异。分割线仅在确有作用时采用，不要求在必备底色差异之外再同时增加边界结构，不因无线判失败。隐藏前景及忽略小纹理后仍须辨认各区起止。采用的色带、切边或收口仍包含在原有背景尺寸内，不新增间隔块、不更改模块高度与内容起点。分区方法在样张阶段确定，用户确认后正式拆分不得自行补线。选择与逐对验收按[分块模式的上下分区](art-direction.md#分块模式的上下分区)执行，整体衔接不套用这项分块要求。

## 头图比例适配与完整KV保留

**原KV保护区与一次适配。** 先实际查看原图，原样保存到本次制作档案的design/source/并记录路径、尺寸与SHA256。原KV是不可拆开的原画图层：人物、产品、品牌、文字、纹理、光影及原有边缘处理均保持原样，默认仅允许整图等比缩放、整体定位和原图外新增区域的延展。头图高度、衔接或高清要求不授权重绘内部；仅用户明确指定对象与改动范围时才例外，不能将原图已有裁边或消散误判为待修缺陷。

扩图实际输入原KV及其放置矩形，明确只生成外部新增区域。工具意外修改保护区时，将原KV按同一整图变换原样合回，仅采用外部延展；衔接修复在新增侧完成，不侵入原图羽化、调色、改字或移动人物。原图、适配结果分别保存，A／B／C共用同一次合格头图适配；三套差异来自各自内容区设计，不为每套重画KV。样张和最终回填都核对保护区内容、相对位置与自然比例。正常等比采样不算改画，不承诺缩放后文件字节与原图相同。


**用户输入的高度定义最终头图画布，不代表允许裁切原KV。** 此规则适用于所有主题及两种背景模式。读取原图实际宽高W、H，与1920×本次高度h比较比例，而不是只比较1080和600等高度数值；原图永久保留。比例一致时直接等比缩放。比例不同时默认完整等比容纳，再延展空出的背景：缩放系数为min(1920/W, h/H)，原KV完整落在目标画布内，人物、产品、文案、品牌、上下边缘及原有装饰均不裁掉、不拉伸。

- 根据原构图放置完整缩放后的KV，并记录缩放与位置；扩展方向由实际空缺确定，横向更宽时通常补左右，不固定只补某一侧。新增区域延续原图的环境、图形、肌理与光影，不用黑边、空白条、模糊放大底图或突兀纯色块代替适配。低频平面KV可延续原有色面；不因此添加本来没有的复杂景物。图片编辑以原KV为实际输入，保护已有画面、准确文案和品牌，新增区域不复制核心主体或标题。延展改变了已提供内容时须修复，不能把整张重画当作完整保留。
- 例如1920×1080到1920×600，完整原图等比显示约1067×600，横向剩余约853px由背景延展承接；两侧对称时各约427px，实际位置可随构图安排。例子不是默认尺寸或固定摆放，原图宽度不同须重新计算。
- 检查实际1920px头图的主体辨识、标题和说明可读性以及整体构图。完整保留导致主体或文字过小、延展不能自然成立时，说明取舍，逐项询问用户选择提高头图高度还是允许重新构图；不能偷偷裁切、拉伸、放大后溢出隐藏，或自行改变已输入高度。用户明确选择重新构图后，保留原内容与KV身份，在既有本轮3套样张中展示调整并说明改变，再由用户手动确认才制作正式素材；不额外增加候选图。裁切仅在用户明确允许后进行，记录允许的范围，不把重新构图授权等同于删除内容的授权。
- 将原图尺寸、目标尺寸、适配方式、缩放、位置／延展区域及必要的用户选择写入现有design/analysis.md，沿既有来源链保留原图和适配后母版。先完成头图比例适配，再形成整体衔接母背景，从适配后头图的真实下边缘延续到内容区；上下内容全部放在头图切片范围内，不把原KV下方藏到套餐等模块。母图切片只是在已完成构图上分割交付，不得截掉尚未适配的原图。
- 最终hero为1920×h，浏览器按该尺寸完整显示；不对比例不符的原KV使用object-fit:cover、background-size:cover、固定高度overflow:hidden或局部source crop冒充尺寸适配。上述限制针对头图，不改变其他模块原有规格。对照原KV、适配后头图与最终浏览器首屏，核对原内容完整、比例、文字准确与可读性、延展自然且无重复主体；未获明确裁切授权却丢失内容，或实际显示二次裁切时必须修复。沿用现有kv_identity验收结论记录结果；尺寸正确不能代替完整性验收。

## 样张与交付共用工作素材

两种背景模式均按[最终背景与轻量前景样张](shared-assets-workflow.md)执行：样张前用最终比例的轻量前景定位内容，自动设计、同屏检查与返修实际背景，通过后完成最终背景母图及原像素切片；选中后只为该方案生产正式前景、状态和装饰。背景直接复用，实际盒体出来后允许局部融合修补，不能整页重画。最终工作集验收冻结后按working_source与哈希复制交付。所有既有V1尺寸、标题输入、分区差异、接缝及融合要求保留。

## 模块标题素材

标题文案按[用户手动输入规则](../SKILL.md#模块小标题由用户手动输入)在本轮生成前逐项取得；套餐、盲盒与任务分别提示默认「套餐购买」「盲盒抽奖」「获取更多抽奖机会」，实际输出须与用户输入或明确选用默认一致。未输入不能自行定稿，其他启用模块同样询问。下面的示例只说明字段与引用结构，不授权代填文案。

每个启用的套餐、抽奖、任务、礼包及平铺活动规则模块需要恰好一张独立透明标题PNG，抽奖按本次玩法选择角色。所有模块共享同一标题母版、画布与显示尺度，只替换完整文案；画布按最长标题及效果安全边确定；普通模块标题按[正常显示比例](art-direction.md#模块标题的正常显示比例)以44px名义字号和480×64px页面显示画布起步，合理调整文案长度与安全边，不为加入标题更改V1模块高度及内容间距。高清导出尺寸与实际显示尺寸分别记录。

| 标题角色 | 所属HTML模块 | 数量 |
| --- | --- | --- |
| `package.title` | `data-module="package"` | 有套餐时1张 |
| `blind.title` | `data-module="lottery"` | 盲盒模式1张 |
| `marquee.title` | `data-module="lottery"` | 跑马灯模式1张，与盲盒标题不混用 |
| `task.title` | `data-module="task"` | 有任务时1张，不是每项任务一张 |
| `gift.title` | `data-module="gift"` | 有礼包时1张，不是每个礼包一张 |
| `rule.title` | `data-module="rule"` | 仅`rule_inline_enabled: true`时1张，与其他章节共用标题母版 |
| `banner.title` | `data-module="banner"` | 仅已启用且确认需要独立章节标题时可选1张 |

文件单独存放在`assets/titles/`并逐张列入`assets.json`的`assets`。标题项填写导出像素`width`、`height`，页面显示像素`display_width`、`display_height`，完整`text`及相同的`title_style`母版标识。两组尺寸等比，全部标题共享显示尺度。下面以2倍导出、480×64页面显示说明字段：

```json
{"role":"package.title","file":"assets/titles/package-title.png","width":960,"height":128,"display_width":480,"display_height":64,"text":"套餐购买","title_style":"current-activity-title-v1"}
```

页面在对应模块原有标题位置使用语义标题容器，图片标记`data-role="module-title"`与素材角色`data-title-role`，`src`指向清单图片，`alt`等于完整`text`；不另叠可见HTML标题。示例：

```html
<section data-module="package">
  <h2><img data-role="module-title" data-title-role="package.title"
    src="assets/titles/package-title.png" alt="套餐购买" width="480" height="64"></h2>
</section>
```

CSS显式采用本次清单的显示尺寸，例如本例标题图使用`width:480px;height:64px;object-fit:contain`，不能用`width:100%`撑到容器宽度。全页缩放与标题内部放大分别处理；浏览器实际显示与清单一致，文字与装饰等比。

脚本检查模块标题数量、画布、真实透明背景、统一母版标识、导出与显示比例、HTML尺寸、标题文案字段及页面对应模块引用；CSS最终生效尺寸与可见字级仍须浏览器复核。标题必须包含在素材文件夹内交付。字形、字号、描边、阴影和文字准确性按[统一模块标题素材](art-direction.md#统一模块标题素材)视觉核对，不能凭标识相同认定风格一致。

## 两种模式的跨界组合与导出

**按模块区分允许明显的底色切换，不允许把样张中的曲线、笔刷或图形截成水平断口。** 视觉模式决定底色与章节关系，交付切片坐标只决定文件范围；两者不能混为一谈。两种模式的最终背景均须形成1920px宽、按实际页面累计高度定位的组合母图，完成跨界设计后再导出。按模块区分的母图仍保留每对相邻区必备的大面积底色／明度差异，不改成同色连续底景；分割线仍按样张选择，可有可无。

### 从样张到最终规格

1. 先按用户确认样张建立最终V1坐标的背景组合基准。每对相邻区保留样张中的实际过渡、两侧纹理关系及章节色面；提供所选样张的跨界局部作为真实图片输入，不仅口头说明“自然衔接”。尺寸适配在共同画布里安排留白，不能把每个模块当独立图片各自等比缩放、居中裁剪或封口。
2. 对每处交界，同时查看上下至少120px的1920px全宽区域，复杂图形扩大到覆盖其完整走势；将这一区域作为一个编辑对象，联合处理两侧与中央。分段生成的重叠只是工作上下文：在同一整页坐标内合成一次，删除重复区域；不能两个模块各自画顶部／底部收口。此制作区域不是额外候选样张，仍沿用现有用户确认流程。
3. 分区底色可以在经过设计的完整轮廓处切换。笔刷撕边的两侧轮廓、斜线、色带、图形尖角及主题纹理应自然穿过切片坐标，或在母图内按原设计完整收住；不能让曲线某一侧突然变成全宽水平线，也不能将切片最上／下行当作图形的造型边缘。对于样张明确设计的直线色块边界，可完整保留；判断针对无依据的图形截断，不把直线本身一概判错。
4. 先看完整组合母图及其跨界区域，对照样张恢复全部标题与内容检查，再导出。母图已经有断口时回到该跨界区域编辑；仅把两张有断口的背景拼成一张母图，不算修好。局部返修不重新生成无关模块，也不靠新增分割线、模糊、渐变、负间距或CSS蒙层遮缝。

### 统一原像素导出

两种模式均在 assets.json 填写 background_mode 与 background_master，字段沿用下节示例；按模块区分使用 segmented，整体衔接使用 continuous。background_master 指最终实际组合母图，并列出从头图开始的全部1920px背景切片累计坐标。非1920px素材保持既有规格与显示规则，在整页母图中保留其实际显示区域作为上下文，不擅自更改其尺寸。

从本skill全局目录运行 scripts/export_background_slices.py <页面目录>，按清单从最终母图直接裁切全部1920px背景；导出器不缩放、不独立裁剪重构、不重新生图、不改变颜色。必须先完成母图设计，工具无法修复母图本身的坏接缝。切片后不能另行修改单片；需要修复时编辑母图，再重新导出所有受影响切片。

### 两种模式都逐缝验收

正式阶段对选中方案的所有真实交界按下节 seam_reviews 的格式保存本次真实1920px浏览器纯背景截图；候选阶段仍查看全部交界，但使用同批纯背景预览及必要放大局部，不提前为三套整理逐缝交付证据。正式截图要求：左右端与中央全部覆盖，交界上下各至少80px、高至少200px；复杂轮廓扩大截图范围。纯背景截图须与最终母图同坐标区域保持原像素一致；与母图不一致时先检查cover、缩放、重复背景、overflow、clip-path、蒙版和叠层定位。不得用母图裁片冒充浏览器证据。

每处依次对照“已确认样张的过渡 → 正式母图 → 原像素切片拼合 → 真实浏览器”。观察需明确写出两侧与中央的轮廓是否完整、有无水平断口或重复、按模块区分的底色差异是否仍明显、恢复标题后是否压线。像素相等只证明导出与定位一致；如果母图本身有截图中这种被水平截掉的笔刷／斜线，仍记revise，不因同源切片通过而交付。

## 模块分割线唯一归属与标题避让

本节适用于两种背景模式中实际采用分割线的交界；没有分割线时不新增线条，也不要求填写线条数量、归属或标题至线条的间距。按模块区分是否用线先依[分块模式的上下分区](art-direction.md#分块模式的上下分区)在样张阶段决定。分割线指分隔相邻章节的撕边、笔刷、色带、曲线或其他实际分区图形，不把普通背景纹理当成分割线，也不强制为没有分割线的样张新增线条。保留用户确认样张的分隔数量、形态、粗细和标题关系；不能把样张的一条转场在拆分后复制成上下两条。

### 一处交界只制作一次

- 拆分前在现有 design/analysis.md 的元素归属记录中，逐条写明分割线位于哪两个模块之间、最终整页坐标范围、来自样张的哪处，以及由哪个背景文件承接。先按最终 V1 布局完成跨界组合，再导出；不能分别提示上一块画底部分割线、下一块画顶部分割线。
- 整体衔接：每条分割线只绘制在连续母背景中一次，按累计坐标采用互不重叠的半开区间 [top, top+height) 切片，每行像素只进入一片。曲线跨界时，两片分别承接同一曲线的上下部分，拼回后是一条完整图形；不得把完整线条同时补到两片中，也不复制上下文重叠区域。分段生成的重叠仅用于编辑与合成，正式母图不得重复保留。
- 按模块区分：不论有线／无线，先在[组合母图](#两种模式的跨界组合与导出)共同处理每处交界；仅对样张实际有线处制作一次完整线条，无线处沿用明显底色差异与既定留白，不补封边。优先完整放入一个模块的背景范围，另一模块承接底色与材质，不再画第二条收口；归属按已确认样张确定。若曲线确需跨界，在共同坐标中设计一次，再分别导出互补部分，不能独立生成两条相似的线。章节底色可以不同，不等于允许跨界图形被水平截断或重复；统一从组合母图裁切，不独立重画单片边缘。
- 分割线归背景，不进入标题 PNG、卡片、盲盒底板或独立装饰，也不通过 HTML/CSS border、伪元素或额外叠图重复画一次。背景中已有线时不再叠一张同形分隔素材。背景恢复标题遮挡区域时只补回原有线条，不重画一条并行线。保留标题自身的小底板、字效与配套图形，不把它们误删成分割线。

### 在生成背景前留出标题净空

- 按最终页面显示尺寸，在模块顶部既有预留区内先定位独立标题，记录标题文字、底板、描边及可见配套图形的实际范围；不能只按 PNG 透明画布或文字基线判断。标题位置和尺度与整套母版一致，仍遵守既有 V1 内容起点、模块高度和间距。
- 同时提供分割线轮廓和标题可见范围作为背景编辑的布局约束。在标题覆盖的横向范围检查分割线的实际走向；标题全部可见部分与分割线保持明确净空，默认在1920px页面显示尺度留至少16px，已确认样张留白更大时沿用该关系。不允许线条横穿标题文字、贴住标题底板或被标题强行压住来隐藏重复线。
- 净空不足时，先在跨界组合中调整分割线走向、厚度或位置，为标题保留干净的底景，再重新导出受影响背景。标题仅可在既有顶部预留区内协调位置，不下推卡片、奖品、任务信息行或列表，不缩小标题来迁就错误分割线，也不增加模块高度、负间距或遮缝蒙层。若必须明显改变用户确认的构图，按既有改稿确认流程处理。

### 拆分后按真实组合检查

依次对照已确认样张、正式跨界背景组合、素材原尺寸拼合和真实1920px浏览器页面：

1. 暂时隐藏所有前景，逐条查看头图至首模块及后续所有相邻模块的交界。核对无线交界没有新增线条，有线交界只出现样张确认的一条分割线，无重影、并行复本、重复纹理、断口或左右端错位；需要跨界的线条拼成完整轮廓。不能只检查各张背景单独是否好看。
2. 恢复全部独立标题、实际内容与操作，逐个检查标题文字及配套图形是否压线、标题至内容是否保持既有间距。检查实际显示尺寸和整页缩览，不以标题图层在上方、文字仍可辨为通过。
3. 在现有逐缝证据或 background_comparison、component_comparison 中保留能看清分割线与标题关系的局部；在现有 background_design、content_composition、export_fidelity 观察中写明逐处数量、归属、拼合结果和标题净空。按模块区分同样填写真实组合母图与全部交界的浏览器证据，底色差异与图形完整分别检查。

出现双线先定位重复来源：母图已有双线时编辑跨界区域；导出重复时重切；页面重复时清理重复背景、叠图或伪元素。标题压线则修复背景避让与既有预留区内的排布。问题未解决记 revise，重新回填和截图后再交付；来源一致、尺寸通过或同源切片均不能代替此项视觉检查。

## 整体背景切片与接缝验收

**本节的母图清单、原像素导出及逐缝浏览器校验适用于两种模式。** 按模块区分先依[跨界组合与导出](#两种模式的跨界组合与导出)完成具有明显底色差异的组合母图，再复用下面字段；不因此要求上下同色或同场景。下述整页场景延续要求仅属于整体衔接。

整体衔接的最终母图必须包含头图及全部启用内容模块，覆盖从首屏到页尾的完整背景；分段制作时首段必须包含头图与首个内容模块，头图高度仍为用户输入值。KV正式文案、品牌与核心主体保留，先按[头图比例适配与完整KV保留](#头图比例适配与完整kv保留)完成头图适配，从适配后头图的真实下边缘延续本次KV的场景、纹理、图形与空间关系，统筹整页构图并为实际内容留出可读区域。允许主题场景贯穿整页，不强制在头图后转为纯色或简洁模块底景。分段须有足够上下文重叠，真实边缘的色值、形状及纹理一致并合成最终完整母图后，才按全页坐标切片。不要直接拼接两张只是风格相似的图片，也不在错误接缝上临时叠加渐变、CSS模糊或遮罩。纯色和非场景KV同样核对边缘色值与纹样位置。

正式母背景先按[样张到成品的设计保留](design-quality.md#样张到成品的设计保留)核对已确认背景的场景、肌理、图形层次与转场；同源切片不豁免母图本身的设计丢失。母图只统一校正一次到最终1920px宽和累计高度，切片随后不再缩放、居中裁剪、独立调色或重新生图。把母图保存在 `design/page-background-master.png`，在 `assets.json` 记录切片来源：

### 首屏与首模块先联合验收

每套候选先将本次已适配的实际hero与第一个内容模块按最终坐标放在一起，叠回标题和实际比例的轻量前景。执行者先检查这个组合，通过后再扩展其余模块；这是内部制作检查，不额外让用户选小样，也不先生成低清整页再重画模块。首模块制作输入包含实际hero下缘及足够上下文，不能只拿KV的颜色或不含下缘的风格局部代替。

两种模式都检查首屏到内容区的视觉关系。整体衔接从真实下缘延续可见色面、曲线、透视、虚实和光感；不能在每个模块顶部重新开始一遍场景，例如上方已经是近景水面，下方却从天空和远处地平线重新起画。这个例子只说明空间重置问题，不把海浪设成所有主题的要求。按模块区分允许明确章节变化，并继续保留相邻区的大面积底色差异，但须依据本次设计完成转场，不把两张独立海报直接硬接；分割线仍可有可无。两种模式均不要求不同章节所有物件或镜头相同。

检查完整hero＋首模块组合以及覆盖真实交界上下文的全宽局部；同时核对左、中、右的形状、材质与场景是否突然跳变。文件同源、边缘像素接近和页面没有空隙均不能证明衔接成立。明显的全宽截口、重复地平线或无设计依据的场景重置记为revise，由执行者在首模块／跨界背景区域修复；保护头图已认可人物、文案和构图，不改它们迁就新背景。保持既有头图高度和模块尺寸，不用遮缝条、全局模糊或CSS渐变掩盖。修复后更新实际母图、切片和组合预览，沿现有逐缝证据记录，不新增用户审批。

### 跨边界构图与逐缝验收

**整体衔接的模块切片边界是交付坐标，不是画面的章节收口线。** 弧线、波浪、地形、色带、肌理与场景在完整母图坐标中自然延续，形状可以跨越切片边界；不能把每段曲线压平在模块顶／底边，或在边界处突然截断、补一条全宽直色带再声称连续。主题本身的地平线、原有平面色带等可以保留；验收针对无依据的模块截口，不把所有直线或颜色转换一概判错。此项仅用于整体衔接，按模块区分仍遵循已确认的章节边界。

母图制作前记录每条真实模块边界的累计y坐标及跨界元素。分段生成须同时提供上一段实际边缘、所选样张中的转场局部和跨边界构图，将接缝两侧及完整曲线作为同一编辑区域；上下文覆盖足够的形状范围，不仅对齐最后一行颜色。不让生成器把两个片段各自画成闭合的顶部／底部收口。先合成并检查完整母图的全宽跨界区域，再切片；同源切片无法修复母图内已形成的硬边。

依次核对三处：所选样张的原转场、正式母图中的同一边界、真实浏览器中的同一边界。母图就有断层时编辑完整跨界区域，保留本次设计并重新导出受影响切片；母图自然而切片不一致时重切；切片一致而浏览器有断层时检查实际背景定位、重复、cover裁切、模块边框／间隔、背景色及叠层裁边。跨界图形不得被每个模块的overflow或蒙版截断；应在连续背景母图／共享坐标层处理，不添加遮缝条、模糊、负间距或渐变蒙层掩盖问题。影响已确认设计的改稿仍按既有确认流程执行。

正式交付检查所有边界，覆盖头图→首模块以及每一对后续模块，不能只截首屏或只看最漂亮的抽奖区。保留真实1920px浏览器纯背景视图的逐缝截图：各条截图宽1920px、高至少200px，接缝上下各至少80px上下文，靠近页面顶／底且不足80px时覆盖该侧全部可用范围，复杂曲线应扩大范围，并包含左、中、右完整横向区域；再恢复业务内容检查承托、遮挡与整体关系。截图来自本次真实页面，不以母图裁片冒充浏览器结果。这些是内部验收证据，不增加候选样张或交付素材副本。

background_master.seam_review继续保留接缝总览；新增seam_reviews逐缝记录本页累计坐标top、截图在页面中的起点capture_top、file、status及observation。每条记录观察曲线／色面是否自然穿过交界、纹理或场景是否断裂、浏览器是否出现额外截口。仅可写实际检查结果；任何问题未解决写revise并停止正式交付，修复后重新截图。只含头图的连续母图没有内部接缝时列表可为空；其他所有内部切片边界均须记录，含非1920px模块在母图中占用间隔的两端。校验器核对覆盖与证据尺寸／状态，不能自动证明曲线自然或截图坐标记录属实，仍须实际查看。

## 盲盒奖品展示

盲盒玩法生成前，用户须手动输入奖品数量，确认名称与顺序，至少提供最长名称；不能推断、默认或沿用旧数量。数量为正整数；用户明确输入0时表示不展示奖品，不生成展示底图。没有真实名称时取得占位授权，按待配置排版，并说明以后换成长名称需重新核对，不能伪称已通过真实最长名称验收。

每个奖品必须同时规划**上方图片展示区和下方名称区**。确认奖品实图是否已提供；没有实图时保留该完整区域，以明确的图片待配置占位展示，不自行编造奖品，也不去掉图片区做成名称长条。底图为独立透明PNG；奖品实图是内容，置于上部，使用object-fit:contain或等效方式保持比例，不裁切关键物件、不挤压变形；名称位于其下方，完整换行。

**上图下名两区必须有清楚视觉区别。** 在同一KV画风内，通过不同明暗/填充、独立名称底板、分隔线或合理留白建立上部图片区与下部名称区；不能让上下看起来是两块同样的面板，只靠内容位置区分。具体色彩随KV确定，不固定上深下浅。下部名称区是信息底板，不做操作按钮，不加图标或箭头。生成提示词明确两区比例与区别，在最终小尺寸查看图片和名称均清楚。

1. **先定空间与内容。** 盲盒保持317×296显示尺寸、模块y=192，主按钮及概率入口继续使用原V1位置。两侧奖品适度向盲盒收拢，但与盒体保留明显、舒展的留白，不能将“稍微近一点”理解为紧贴；间距依据用户示意、卡片尺寸及整体构图确定。底板是盲盒背后的局部衬板，内侧奖品卡在前景压住左右边缘，部分探出板外；外侧奖品可完全在板外。不要求奖品全部位于底板内。底板尺寸可随奖品数量、卡片规格和行列布局调整，但仍作为局部衬板，不扩成共用地板或整组大框。以完整盲盒的可见范围确定包裹下限与中心，再结合奖品布局及留白决定宽高和压边关系；不能因收近奖品而削减包裹高度，详见下方验收。模块背景在最下层，底板在盲盒与奖品卡后面，边框经过卡片背后时由卡片遮住，不能绘制到图片和名称前面。标题、主按钮及概率入口仍须避让。
2. **左右数量均衡。** 默认左侧ceil(N/2)、右侧floor(N/2)，按用户顺序先左后右；左右宽度、卡片规格和间距一致，每侧奖品组在盲盒主体附近垂直居中。奇数两侧相差一张即可，不重复或虚构奖品补齐。数量为1时仅放一侧，并保持整体视觉平衡；用户指定顺序时记录实际分配。
   **以盲盒为主体控制主次。** 奖品卡保持辅助层级，但不能以“明显小于盲盒”为由持续缩小；按下节实际显示比例起排，通过位置、对比和装饰重量保持盲盒主次，不让浅色名称板或粗边框形成比盲盒更强的卡片墙。每侧3个时，可用一列上下两张、另一列单张居中的错落组合，左右镜像、整组围绕盲盒中心；内外列关系按用户示意确定，当前参考为外侧上下两张、内侧单张居中并压住底板边缘。其他数量重新比较错落或整齐分组，保持图片与文字清楚；不沿用固定卡片尺寸，也不通过放大盲盒突破其V1显示规格来补偿奖品过大。
3. **根据数量、图片和最长名称定一套单卡尺寸。** 先留出可辨认的图片展示区，再以实际字体测量名称，检查换行、最长不可断单词和行数；卡片总高度等于图片区高度＋间隔＋名称区高度＋上下安全边，不可只按文字算高。图片是卡片上部的主要内容，名称通常居下并支持多行。少量奖品优先较大的卡片；数量增加时比较多行、多列，适度缩小但保留图片和可读文字。长名称可加宽或增加名称区高度，图片区也须维持合适比例，避免横向拉长成文字标签。数量与名称同时增加时协调列数、宽高和行数，不机械套公式，也不把图片缩成小图标来迁就原来的长条框。
4. **名称可完整换行。** HTML使用可换行的名称容器，可用white-space:pre-line、overflow-wrap:anywhere及适合当前语言的断行；不强行单行，不用省略号、裁切或藏溢出掩盖长名称。固定易读字号后合理调整卡片宽高及名称区行数；名称与上方图片区域不能重叠。真实长名称超过当前卡片容量时重新布局，不挤占图片区域。
5. **再生成底图。** 将单卡宽高、上方图片区、下方名称区及间隔写入design/analysis.md与生图提示词，导出相应比例的透明blind.prize-card，按原比例显示。底图与本次KV同一画风，装饰克制，两区留净，不烘焙名称、实物图、数字、符号或奖品清单。图片和名字逐项叠入，不把两侧全部奖品合成大图。
6. **检查容量与协调。** 在1920px浏览器中检查每项名称完整、卡片在模块内、互不遮挡，与盲盒/标题/主按钮/概率入口无冲突；奖品卡压住底板边缘属于有意叠层，不判作碰撞，不要求卡片全部被底板包含。检查底板位于卡片背后、边框不会透过或盖住图片和名称，盲盒主体不被奖品遮住；底板内区覆盖完整盲盒且中心对齐，额外留白允许为0，奖品可适当叠压底板，不能用“奖品不必全在板内”豁免盲盒包裹。整页缩小查看时盲盒仍是抽奖焦点，奖品两侧平衡、适度收拢但不拥挤，盒体与奖品之间留白明显。记录数量、完整名称、最长名称的测量、单卡尺寸、两侧位置、行列数和间距。若确认数量及长名称无法在固定模块内清楚排完，展示具体布局限制并请用户选择减少展示数量或调整展示方式，不擅自漏掉奖品、改模块高度或过度缩小字号。

### 奖品卡与实图的实际显示比例

区分PNG导出像素、卡片在页面的显示尺寸、卡内图片区以及奖品本身可见范围。只把图片导出得更大，或只放大装饰外框，不能解决奖品看起来小。 样张中的奖品卡也按同一规则制作，不能因“前景为示意”先用小号卡片占位。候选与正式页面使用同一V1显示尺寸，不在示意里放大、交付时再缩小。

未指定奖品卡尺寸且展示1～6项时，在1920px页面中优先以每张约200～240px宽、220～260px高起排，常规图片区以约160×150px起步，再依据实图比例、最长名称、异形安全区和实际空间调整；这些是内部布局起点，不是固定输出尺寸或让用户填写的新参数。四项优先左右各两张，六项可用原有错落分组，充分利用两侧空间，不为贴近盲盒把所有卡压进中心小范围。其他数量自动比较行列与错落方式，先调整排布与间距，再考虑缩小；不改盲盒317×296显示规格或擅改模块高度。 对常见1～6项，默认优先在上述范围的中上段起排（约220～240px宽），不能因为有6项或为了让盲盒显大就自动降成窄小卡片；先用足两侧可用宽度、调整内外列和留白。确需低于200px宽时须有实际空间／长文案测量依据并确认正常尺寸可辨，不把这个例外当默认。测量卡片可见主体而非透明画布；缩略总览的缩放由页面统一承担，不再单独缩小奖品组。

实图按完整物件等比contain；根据实际主体范围控制缩放，避免图片文件自带的大面积透明空白或留白使物件变成小图标。常规主体在不裁切前提下让其较长方向占图片区可用对应边约75%～90%，细长或特殊形状结合识别度调整，不强迫两个方向都填满。允许剔除无内容透明外围，但不裁掉奖品本体、包装、文字或有意义阴影；不明确的白底区域不能盲目裁除。缺少真实奖品时以同尺寸图片区明确占位，不能将小占位图标当实际奖品大小已验收。

样张与最终预览均在真实1920px浏览器查看整组奖品及单卡局部，再看整页缩览。实际测量卡片显示矩形、图片区和物件可见范围，记录在现有design/analysis.md及对应视觉对照；只有导出尺寸或DOM容器大不算通过。核对奖品能识别、名称完整、图片仍为卡片主要内容、两侧不拥挤且盲盒仍突出。图片太小先排查二次缩放、透明留白和过量内边距，再调卡片及分组，不靠增大导出分辨率或放大盲盒处理。无法容纳确认数量时沿既有容量处理规则报告，不悄悄漏项或缩成图标。

assets.json在盲盒模式记录blind_prize_count和按展示顺序排列的blind_prizes名称数组。展示数量大于0时必须包含恰好一张blind.prize-card，记录width、height；0时不生成该素材。示例字段仅说明格式，不是默认数量或尺寸：

```json
{
  "blind_prize_count": 4,
  "blind_prizes": ["奖品名称一", "奖品名称二", "较长的奖品名称示例三", "奖品名称四"],
  "assets": [
    {"role": "blind.prize-card", "file": "assets/blind-prize-card.png", "width": 220, "height": 230}
  ]
}
```

HTML左右奖品容器分别标记data-role="blind-prizes-left"与data-role="blind-prizes-right"，每个单奖品容器标记data-role="blind-prize-card"，卡内上部图片区标记data-role="blind-prize-image"、下部名称标记data-role="blind-prize-name"，均位于data-module="lottery"内。图片区放本地奖品img或明确的待配置占位，名称节点只含奖品名称。校验脚本核对声明尺寸、真实透明、数量及名称；图片比例、文字无溢出、换行及主次关系仍以浏览器检查为准。旧输出未声明奖品展示字段时仍可校验，新的盲盒制作须完成上述确认与记录。

### 奖品展示形式与复用

上图下名是内容关系，不要求每项都有封闭外框。按KV和相容参考选择气泡承托、独立名称条、轻卡片或开放式组合；不能把奖品统一做成厚重面板，也不因开放式而省略名称承托、边缘精度及组合设计。实际奖品可见尺寸、长名称换行、两侧排布及主体层级仍按上节验收。

素材清单仍只生成一张共用blind.prize-card，整张透明画布覆盖该展示项的图文排版区域；可将承托仅绘于下方名称带或局部，其他区域透明，奖品实图及HTML名称独立叠放。不增加每项独立底图，不通过裁窄画布、放大边框或缩小实图伪造尺寸合规。气泡、名称条及开放式只是可选形式，不成为所有活动的固定模板。

## 局部底板的动态尺寸

盲盒局部底框直接绘入 blind.background，宽度、高度和宽高比仍按本次奖品数量、卡片尺寸、行列、最长名称及构图动态确定。变化的是交付归属，现有底框设计完成度和盲盒关系继续保留；历史示例不作为默认尺寸，不单独输出 blind.backdrop。

先测量完整盲盒主体，含蝴蝶结与盒盖，按下节底板类型共同规划承托区域。对称包裹框以完整主体同中心规划填充内区，可贴合边界、额外留白允许为0，不能为贴近奖品把包裹高度缩到盲盒露出；平面图形或实体承托按各自构图及接触关系确定尺寸。底框是局部衬板，不扩成包住所有奖品的整组地板；内侧奖品可以压住边缘并探出，外侧可完全在板外，奖品和盒体之间仍留明显空间。

有实体台面时另按[盲盒与承托面的透视和落点](design-quality.md#盲盒与承托面的透视和落点)核对视角、可承载盒底的深度及接触边；包裹和居中约束仅针对背后的对称包裹框，不用于把脚下台面居中到盒身。

所有尺寸、位置及纹理比例调整在同一背景与前景组合中完成，不靠CSS拉伸背景迁就底框，也不移动盲盒绕过背景内底框失配。同步核对原有承托类型、透视／平面叠层、环境连接、光影、奖品遮挡及标题／按钮避让，主体显示尺寸和V1间距保持原规则。

在 design/analysis.md 记录底框在最终 blind.background 内的区域、尺寸、中心及选择依据。合入背景后仍作为独立设计对象记录并验收，不能只记录背景宽高。按[成组制作及融合验收](design-quality.md#底板与背景成组制作及融合验收)建立组合基准，去掉盒体、奖品、文字和按钮时保留底框及其环境承接，再按共同坐标恢复完整前景并对照确认样张。

## 底板包裹与居中验收

底框默认保留在 blind.background 中，blind_backdrop_layer 为 background，blind_backdrop_enabled 默认true；不生成或引用独立 blind.backdrop。只有用户明确取消底框本身时才设 blind_backdrop_enabled: false，并记录非空 blind_backdrop_omit_reason；并入背景不属于取消。未取消时必须执行下面测量和融合验收，不能因底框没有DOM节点或透明PNG而跳过。

盒体范围从 blind.art 的实际alpha可见区域及浏览器显示矩形换算，包含蝴蝶结、盒盖及突出部分，忽略孤立噪点与极淡阴影。底框范围从最终 blind.background 实际可见轮廓测量，记录源PNG坐标 visible_bounds=[左,上,右,下]；再根据实际浏览器中背景显示矩形映射到模块坐标，不能取整张不透明背景的alpha范围或计划值冒充底框。backdrop_inset 是该局部底框边缘到填充内区的实际厚度，可为0；非规则轮廓另以真实组合复核，矩形覆盖不能代替所有可见边缘检查。

样张制作前自动选择并记录support_type，选择依据来自当前KV、相容参考与实际组合，不能为了绕过失败校验临时更改类型：

- enclosing_frame（对称包裹框）：填充内区须完整覆盖盲盒，允许贴合且无额外余量；与完整可见主体水平、垂直同中心，容差3px，不能只按盒身或透明画布中心定位。
- graphic_backing（平面图形衬托）：按构图、视觉重心与遮挡关系验收，不要求矩形完整包裹或数学同中心；允许主体探出，但底板不得抢过盒体、割裂主体或侵入奖品和操作区。
- physical_support（实体承托）：按视角透视、承载深度及真实盒底接触验收，不把台面中心对准盒身中心，也不要求台面包住盒子全高。阴影与反射按接收面与当前画风处理。

同一设计若兼有包裹框与台面，support_type记enclosing_frame并额外验收实体承托，不能选择较宽松的类型略过已有结构。所有类型仍保留真实轮廓测量、最终盒体绑定、完整组合截图及融合对照；奖品可压底板边缘，但线条须在实图和名称后方。

保存 design/blind-layout-check.json。art 和背景矩形来自实际1920px浏览器，visible_bounds 来自本次最终背景内的真实底框轮廓；数值只说明格式，不作为下次默认：

套餐卡上方优先留给可编辑的套餐名称、权益和价格，形成连续、稳定的文案承托面；不放突兀色块、亮色顶部带、强光斑或嵌套面板切开文字位置。按[套餐卡的连续文案区](design-quality.md#套餐卡的连续文案区)默认用一块连续主底面，确需分色时最多两块，第二块只放下方购买按钮附近；不在顶部或中部新增色带、面板，不强制分色。质感、边缘和角部细节避开文案范围，细腻表面仍可保留；同一张卡内部的购买按钮位于底部，与文案保留清楚间距。套餐卡及其按钮分别导出，不得把“立即购买”画进卡片背景。多张套餐卡按上述间距排列，按下节复用同一张卡片底图和同一张购买按钮底图；`assets.json`各角色只列一次，不按套餐实例重复登记。

### 多套餐复用同一套素材

同一活动的同一方案中，无论一个还是多个套餐，都只设计／生成一张package.card和一张package.button，全部套餐实例引用相同文件；不因套餐名称、价格、权益或等级不同而默认多出样式，也不将同一图片复制成多个文件来凑数量。各实例的内容、购买入口及必要业务标识分别保留，复用的是视觉底图，不合并不同套餐的内容或操作。

package_count记录页面实际套餐数量，不是图片数量。启用套餐时assets.json、工作素材清单及来源记录中package.card、package.button、package.background各一项，多个DOM实例复用同一路径；未启用套餐时这三个角色均为零。既有套餐标题仍按模块标题规则独立输出一张。页面实际卡片及购买按钮实例数仍等于package_count，不能只展示一张卡就声称已复用。

A／B／C各自使用本套设计的一套卡片与按钮示意，并在本套内复用，不要求三套候选共用同一设计。用户选中后只精细制作该方案的一张卡片和一张按钮，之后直接复用；不提前为每个套餐生成。以最长名称、最多权益行和价格／按钮文案检查同一母版的安全区，再回填全部套餐检查一致尺寸、间距与完整内容。套餐底图的连续文案面、最多两块且辅助色面靠下、按钮独立及原V1规格继续适用。

### 任务条可辨识与无框信息行

**任务条是独立的可见信息承托，用户名／次数行是无框文字。** 两者不要套用同一种面板结构；700×120任务条的尺寸与排布、160×60任务按钮的右距32px继续按既有规则执行，各类边缘仍独立设计。

任务条先放在本次真实模块背景上确定内部填充、明暗面积和表面密度，让整条主体在正常显示尺寸下容易辨认，再完成细节与轮廓。可以依据KV和相容参考调整主体底色／明度、填充不透明度、肌理密度或局部承托，与紧邻底景形成清楚层次；不固定浅底、深底、材质或边框形式。不能只加一条细描边、发光线或角部装饰，却让内部填充仍与背景融为一体。外轮廓及安全边保留真实透明，信息承托区保留必要填充，不为了透明PNG交付把条内整体做得过透；背景纹理穿透到影响任务区辨认时调整底图。

任务名称与条件在承托面上保持清楚的文字对比，按钮与右侧承托协调。背景和文字、任务条和模块底景是两项不同的检查：白字清楚、按钮醒目不能代替任务条主体可辨。可操作和已完成状态逐一放回页面核对；已完成可降低按钮强调度并更换HTML状态文字，但任务条主体和任务信息仍须可辨，不对整条容器设置低透明度、整体变灰或模糊来表达完成。

任务用户信息行保持既定“用户名 → 我的抽奖次数 → 中奖记录按钮”的顺序与位置。用户名与次数只用HTML文字直接排在模块底景上，没有独立底图或共同底框；`task-account`只是布局容器。容器及用户名／次数节点不设置面板填充、背景图、描边、箱形阴影或用于包裹信息的伪元素，也不将此类面板预画进`task.background`或连续母背景。通过正常字色对比、局部背景细节控制、对齐与留白保障可读，不以新增底框补救。中奖记录保留独立`lottery.record`按钮底图；它自己的按钮主体不属于应去除的信息行底框。

样张展示前及最终浏览器回填时做三项核对：

1. 在实际700×120显示尺寸及整页缩览查看每条任务，主体与邻近底景形成清楚层次，任务名称／条件／行动均可读；半透明填充有设计依据，但不能融进底景。
2. 临时隐藏任务文字和按钮，保留任务条底图，确认主体仍容易识别；只剩细框时修正填充及邻近底景关系；右侧仍有按钮状包裹区时移除，再恢复文字／按钮。不能仅将素材放在白底或黑底上验收。
3. 同时查看两种任务状态和信息行。检查用户名／次数及其共同容器的实际背景、边框、阴影、伪元素，并查看底景图片；确保无信息行面板，中奖记录按钮正常呈现。

把任务区域实际截图纳入现有`component_comparison`，在`component_craft.observation`记录主体分离、文字可读、两种状态及无框信息行的观察。需要调控邻近底景时同时回查`background_design`。任一项不成立记录`revise`并返工，再按现有样张确认与交付流程继续；文件尺寸、alpha存在或CSS某个属性正确都不能代替这项视觉检查。

### 异形底图的文字安全区

套餐卡、任务条等可以采用异形轮廓，制作顺序必须是先定可读内容，再给外围设计造型。先在最终V1显示尺寸内用实际文案／授权占位排好字级、行高、换行、段间距、按钮及安全净空，固定连续内容区域；再让曲线、切角、凸起与主题装饰围绕它设计。内部信息面可以规整，外轮廓仍保持异形和材质特色，不要求内容也沿着波浪弯折或挤进凹口。先排版只是内部布局依据，不把普通线框当成最终素材。

装饰的空间来自内容以外的剩余区域，不从正文、价格、按钮及必要留白中挤占。优先在少量局部形成主题识别，其他边缘保持相对安静；不默认把四边、四角、价格区和按钮周围同时堆满厚边框、波峰或多层包裹。宽高固定且内容较多时自动降低装饰的高度、厚度、数量和内侧侵入幅度，不通过扩大透明画布再缩小整件来保留全部装饰。具体造型随KV变化，不把海浪、圆角或任何风格设为禁用。

出图后按实际显示检查内部可用面，不能把PNG矩形画布、alpha外接框或容器padding当成文字安全区。核对真实轮廓，排除透明外围、厚边框、凸起、切角、高对比亮边及操作区；实际可用内区必须容纳预先排好的内容及净空。若与预留区域冲突，优先编辑侵入的装饰和内边缘，不接受不断缩小安全区、缩字、压行距或移动内容作为补救；合理的内容换行与排版调整仍可进行，但不能专为迁就装饰牺牲阅读。

由执行者记录每种底图的可用文字区域，使用最终显示坐标的[x,y,width,height]写入现有design/analysis.md，并在页面布局中实际使用。安全区由真实底图核对，不直接套历史模板；同组复用同一母版，两种状态内轮廓不同时检查两者共同可用区。一般组件内边缘至文字以8～12px视觉净空起排，粗描边和强高光按实际效果扩大；任务条的上下留白按下节14～18px起排，不把一般净空值当成压缩任务正文的目标。画布外圈透明不算净空；数值用于起排，实际仍须舒展，不能仅以字形未压边判通过。

任务条保持700×120、按钮(508,30)至(668,90)。按[任务条正文高度与上下留白](#任务条正文高度与上下留白)先保证“名称1行＋说明2行”的三行容量和必要留白，再设计外围；正文安全区在独立按钮左侧并避开左端装饰。长名称、实际需要的换行、可操作和已完成状态分别检查，不能通过缩小字号、压缩行高、裁切或移出信息面凑齐。空间不足先收减task.row侵入的边框与装饰，保留画风、可用异形轮廓和固定按钮位置。

检查实际页面层级：底图置于内容后方，文案与按钮有明确内容层；装饰可叠层但不得覆盖字形。排除祖先overflow、clip-path、mask或固定文本高度裁掉字头／字尾；异形裁剪应作用于需要裁剪的图片层，不能连正文一起裁掉。提高z-index只能解决叠层遮挡，不能解决字贴着亮边、落在透明凹口或缺少承托；这几种问题分别处理，不用白块或额外蒙层盖住原设计。

候选样张展示前与正式回填后都加载实际字体、叠回完整文案，先与出图前的内容布局比较字号、行高、净空和可用宽高，确认没有因装饰被迫缩水；在真实尺寸查看每行首尾、顶部和底部；候选先查常态的真实文字安全区，所需两种状态在选定后的正式阶段完整检查；可临时显示安全区与文本行边界定位，最终移除调试框。测量文字行范围而非只测外层容器，配合真实截图核对装饰覆盖、裁切与对比。候选观察纳入该套集中问题清单和有界修正，正式阶段再将局部纳入component_comparison，问题记入content_composition／component_craft并修复；不得用空白底图、短占位文案或“文字在最上层”代替实际验收。

### 任务条正文高度与上下留白

任务条的120px总高度包含透明边、尖角、装饰和厚边层，不代表文字有120px可用。优先保证中段连续信息面的实际高度与舒展感；简单款已满足时保持原样，不统一加高任务条或改变模块间距。

生成前按最终显示尺寸和实际字体，以“任务名称1行＋说明／条件2行”共三行作为常规容量基准，预留名称与说明的段间距、说明行距及上下留白，不能只按两行总高度制作。短文案仍自然排一至两行，不强制补空行；真实文案超过三行时按实际换行另查容量，三行不是截断上限。未知文案也用内部三行示例检查可用宽度和高度；测试文案不烘焙进素材、不当作用户业务内容交付。

可用三行文案示例作三行排版检查：“加速游戏：”／“每天加速《示例游戏：特别行动》，每天加”／“1次抽奖机会”。此例只检验行数和长短，不固定后续活动的游戏、任务或奖励；实际预览应按本次字体、可用宽度和完整文案正常换行，不为复刻示例断点强插换行或缩字号。说明文本允许换行，不能用固定单行高度、nowrap、两行总数截断或省略号藏掉最后的奖励信息。

上下视觉净空分别以约14～18px起排，按实际字号、字形和边框调整。所需连续内区高度至少容纳文本块的实际排版高度加上下留白；文本块高度含行高、换行及行间距。净空从实际文字到最近的内边框、斜切、强亮边或侵入装饰计算，不从PNG画布、透明区域、外轮廓尖端或CSS容器计算。沿正文覆盖的整个宽度检查最窄位置，不能只量卡片中央最宽的一处；名义padding达到数值但字形仍贴边同样不通过。

中段信息面应足够厚实并保持连续，文字在实际可用内区内整体垂直排布，不机械对齐整张PNG中心。异形优先放在两端和外轮廓，允许材质与少量装饰，但上下边不得向正文收拢成细长缝隙。内区不足时优先加厚中段信息面、减薄上下多层描边、降低装饰高度和内侧侵入；在原700×120画布内解决，不拉宽卡片、缩小文字、压行距或扩大透明画布后缩小整图，也不在右侧补按钮槽或包裹底座。

候选展示前和正式回填后均用真实字体检查“名称1行＋说明2行”的三行较长示例，并兼查短文案，并覆盖本次真实文案需要的换行；候选查常态，不提前生产状态素材，选定后的正式阶段再覆盖两种状态。记录现有analysis安全区中的可用内区高度、文本块高度及最小上下净空，候选复用集中检查截图，正式截图纳入component_comparison；确认不只“没遮挡”，而是上下有舒适余量、正文面没有因装饰变成窄长条。失败记入content_composition／component_craft并修复侵入部分，不要求用户给出美术方案、不新增选稿步骤。机械PNG尺寸通过不能证明这些关系成立。

### 任务条的连续文案区

任务名称、说明、条件和奖励后续由用户添加或替换。task.row底图在名称与说明／奖励的可用区域保持连续、明暗稳定的文案承托面，不烘焙业务字段、竖向分隔线、列边框、立柱式色条或占位字，也不在HTML／CSS中用border-left、border-right或伪元素补出固定列分割。不能将某次样张的字段布局当成底图里的固定栏位，文字通过排版、留白和字级组织，实际文案或授权占位叠回检查长短变化与换行。

任务条的连续底面延续到右侧按钮下方，不另切右侧行动色块，不生成按钮包裹框、凹槽或底座。质感来自与KV相容的细腻表面、整体外轮廓与边缘，按钮本身承担操作强调；不以连续或单色底面为理由强行补分区。用户名／抽奖次数仍只有文字且无底框；模块章节背景的分区要求不套到卡片内部。

### 任务按钮位置与底图配合

**先固定按钮，再设计任务条背景。** 700×120px是任务条的最终外框；160×60px任务按钮距外框右边32px，垂直居中。因此按钮左上角为`(508, 30)`，右下角为`(668, 90)`，中心为`(588, 60)`。右距指按钮定位框到任务条外框的距离，不是按钮内文字的padding，也不是到整页右边的距离。可操作与已完成状态共用这个位置。

生成`task.row`前，把这套坐标写入简报，并提供700×120布局示意作为几何参考，画风参考当前KV。为按钮保留清楚净空，底面自然延续到按钮下方，不预画按钮、包裹色块、斜切操作分区、凹槽、外框或独立底座，也不通过CSS补出。正文安排在左侧连续文案面，用字级、间距和留白分组；整条外轮廓与端部装饰避开正文和按钮，不迫使按钮偏移。隐藏独立按钮后若仍有明显按钮状槽框或专属色块，修复task.row而不改动160×60、右距32px、top30px规格。恢复可操作与已完成按钮分别检查，保持一个清楚的操作主体。

任务条可见主体应延续到画布的预定左右边缘；有切角、圆角或柔和阴影时，以按钮中心高度附近的主体右边缘检查视觉间距。避免在右侧额外留一大段透明空白，使定位框满足32px但实际视觉间距明显失真。按钮自身继续遵守最小且均衡透明安全边要求，不用扩大透明画布或偏移可见主体修正位置。

页面任务条使用`position: relative; width: 700px; height: 120px; box-sizing: border-box`，背景按700×120显示。按钮定位使用`position: absolute; right: 32px; top: 30px; width: 160px; height: 60px`，定位框不额外加margin、padding或位移。若用flex实现，同样确保包含右padding后任务条总宽仍为700px，并核对最终矩形；不能变成700px内容宽再额外加32px。

先将背景小样、独立按钮及真实或授权占位文案回填成完整任务条，在实际700×120显示尺寸核对：外框宽高、按钮右距32px、上下各30px、正文不挤入操作区；正文按[正文高度与上下留白](#任务条正文高度与上下留白)核对三行容量与真实内区。按钮下方为连续底面，无额外按钮包裹区，文字面无烘焙或CSS叠加的竖向分隔线。两种状态逐一检查；底图轮廓侵入内容时修复任务条背景，不改按钮的固定间距。PNG尺寸校验不能替代这项页面与视觉验收。

任务模块标题与任务列表之间是一行 **用户名 → 我的抽奖次数 → 中奖记录按钮**。用户名与次数用无底框的 HTML 文本直接展示，信息行没有共同面板，仅中奖记录有自己的独立按钮底图；未知时分别写“用户名：待配置”“我的抽奖次数：待配置”，不要复制参考截图里的账号，也不要编造剩余次数。信息行可在模块 y=150px 附近起排，高 60px，首条任务仍从 y=255px 开始。它属于任务模块，不在盲盒或跑马灯旁重复出现。抽奖模块在棋盘／盲盒及主操作下方放“*奖品概率”下划线文字入口；弹窗图按需制作。礼包模块的领取记录是另一项内容，不能套到抽奖任务中。

为便于校验，抽奖区标记 `data-module="lottery"`，任务区标记 `data-module="task"`。概率文字标记 `data-role="prize-probability"`；任务用户信息行标记 `data-role="task-account"`，其中用户名、次数和中奖记录分别标记 `data-role="username"`、`data-role="draw-count"`、`data-role="lottery-record"`。这些是 HTML 结构标记，不显示在页面上。

## 活动规则模块与浮动入口

**启用规则。** 新输出在`assets.json`记录`rule_inline_enabled`和`rule_floating_enabled`两个布尔值，默认分别为false和true。平铺模块只有用户主动要求时启用，并在本次分析记录该要求；选择平铺时默认关闭浮动入口，用户明确要求两种同时展示时两者为true。默认流程不询问是否增加平铺、不预生成其背景及标题。浮动入口沿用209×64px和视口右侧top:400px，不占章节高度；关闭时页面及素材清单均不保留该按钮。既有仅浮动的旧交付未声明字段时继续按旧格式校验，不据历史页面推断本次启用。

**规则区布局基准。** 规则区在任务区下方，1920px模块内正文宽900px、水平居中（左边距510px），字号18px、行高30px、正文顶距150px、底距90px；示例正文高510px、模块高750px。这是布局依据，750px不作为固定高度，具体主题、条款及标题烘焙方式不作为通用设计；当前Skill仍使用独立标题PNG。此布局基准不替代新活动生图前的本轮专业设计搜索。

**标题与正文。** `rule.title`位于模块顶部既定标题区域，使用其他模块同一title_style、画布和显示尺度，只换本次确认文案；正文从模块y=150px开始，居中的900px文本容器内部左对齐。普通正文以18px/30px制作，支持段落、序号和自然换行；文本颜色随本次KV背景保持清楚对比，不固定黑色或白色。不额外生成规则卡片、整组表格或大框，背景直接衬托文本，阅读区避免强图形和高频纹理。

正文可由用户手动输入或粘贴，后续由后台配置；正文输入为选填，未提供、空白或跳过时自动使用明确的“活动规则正文待后台配置”占位，不要求再次授权、不阻断制作。启用平铺后按[入口说明](../SKILL.md#活动规则的两种展示方式)提示一次：提供具体规则可以更准确地适配模块与背景高度。离线交付用`assets.json.rule_text`保存本次实际文本或该占位，并在`<section data-module="rule"><div data-role="rule-content">…</div></section>`内呈现同一内容，标题图片仍用`module-title`标记。正文可用纯文本加`white-space:pre-wrap`、段落或列表准确表达；不把正文生图、截图、转轮廓或写进标题，不直接拼入未经处理的后台HTML。只约定可替换的内容和容器，不修改线上后台、不新增接口或鉴权逻辑。参考页条款不能当本次业务内容；未给正文时不编造时间、概率、奖励或限制。

**模块高度与背景。** 在真实1920px浏览器按900px宽、18px/30px及实际字体测量全部段落的正文高度（含段间距），取整后模块高度为150＋正文实际高＋90。制作同高的1920px不透明`rule.background`，记录正整数height；不为迁就背景缩字、限行、隐藏溢出或截断条款。启用时从三套样张阶段纳入本套背景母图、逐缝检查及最终切片，两个背景模式继续各自的规则；模块总高及所有后续坐标同步更新。后台更换文案导致增高时须重新测量，并延展／重出对应规则区背景与相关母图切片，不能拉伸纹理或遮住多出的文字。只有占位时如实注明尚未验证未来长正文容量，不伪称后台任意文本均可直接容纳。

验收启用状态、两种入口是否按选择出现、规则标题与其他章节一致、正文为完整可编辑文本、长段落及长词换行、底部90px净空和背景衔接。真实正文尚未提供但已使用明确占位时，允许按占位状态交付，并注明补齐正文后需复核背景高度；文本缺失是指实际正文和明确占位均未呈现。图像代替正文、未启用却出现平铺模块或多余规则资产均不能通过。配置示例仅说明主动选择平铺后的字段，不授权默认启用：

```json
{
  "rule_inline_enabled": true,
  "rule_floating_enabled": false,
  "rule_text": "活动规则正文待后台配置",
  "assets": [
    {"role":"rule.background","file":"assets/rule-background.png","height":270},
    {"role":"rule.title","file":"assets/titles/rule-title.png","width":480,"height":64,"display_width":480,"display_height":64,"text":"活动规则","title_style":"current-activity-title-v1"}
  ]
}
```

上例270px只对应测得30px高的一行占位；实际条款按真实高度计算，标题文案仍须按统一手动输入规则取得。

## 礼包与可选元素

礼包每行最多 4 张，卡片宽 201px，列间 31px、行间 20px；卡片区顶部留 28px、模块底部留 33px。领取记录文字存在时，在卡片区下方留 28px，行高 38px。中奖播报存在时占 660×72px，下方留 58px；它会使抽奖内容下移，应复查背景是否覆盖完整。仅浮动方式的活动规则入口不占模块高度；主动启用平铺时，规则模块按[独立布局](#活动规则模块与浮动入口)计入整页高度。

## PNG分辨率与PS置入尺寸

交付PNG默认统一72 PPI，assets.json记录export_ppi: 72；用户明确指定其他目标PSD分辨率时按该值统一，不根据生成工具默认元数据猜测。PPI与像素尺寸分别校验：像素宽高继续按V1，改变PPI不得重采样、放大、缩小或改变透明度。PNG的pHYs使用像素／米，72 PPI对应约2835像素／米；1000像素／米是25.4 PPI，不是72。整数换算允许约0.02 PPI误差，不把72.009误判为尺寸异常。

全部业务PNG、模块标题、独立装饰和背景母图执行同一标准；不只修前景或只修背景。背景切片脚本会写入目标PPI；其他生成／编辑途径在输出后检查，不依赖其默认值。若同时有EXIF等分辨率元数据，核对单位与数值一致，不能保留冲突标记；不删除无关色彩配置、版权或其他元数据来解决PPI。

可使用[scripts/normalize_png_ppi.py](../scripts/normalize_png_ppi.py)仅更新PNG的pHYs，保持其他数据块、压缩图像数据、像素及alpha不变。先用 `python <skill目录>/scripts/normalize_png_ppi.py <工作素材目录> --recursive --ppi 72` 检查，再追加 `--apply --backup-dir <输入目录之外的备份目录>` 执行；自定义PPI则使用用户指定值。只指定本轮工作／交付素材目录，不递归改历史候选或用户原KV。脚本遇到另有EXIF分辨率的文件会停止，需先查清并准确统一相关字段，不绕过检查或盲目删除元数据。

在候选背景冻结、最终盒体hash绑定和最终工作集冻结之前完成分辨率规范化，之后才记录hash并复制交付。修复已有交付时保留旧版本与原始批准记录，仅更新受影响的工作副本、交付文件、当前清单及必要绑定，记录元数据变更和像素不变证据；不能改写原候选的批准hash冒充原文件。图像视觉未变不需重新生图，字节hash变化仍需如实更新。

PS目标文档也须使用相同PPI，且置入过程可能因超出画布或已有变换发生缩放；统一PPI不保证所有PS设置下自动1:1。未实际打开PS测试时只报告文件元数据、像素与alpha检查结果，不声称PS操作验收通过。网页显示尺寸、导出像素尺寸与PPI是三件事：高清标题或装饰仍按其导出尺寸置入，不能用修改PPI隐式代替既定显示比例。

## `assets.json` 与校验

本节“页面目录”指制作档案内的页面根目录，包含`index.html`、`styles.css`、`assets/`、`assets.json`及默认生成的`decorations/`；现有校验器、相对路径和角色字段不变。整页截图保留于制作档案作证据，对外1920px预览复制到唯一“正式素材”目录旁；纯图片成品目录不运行完整页面校验、不放代码或技术清单。平铺、去重与来源映射按[清楚的素材交付](material-delivery.md)执行。以下示例假设用户本次输入头图高度为600px：

```json
{
  "lottery_style": "marquee",
  "lottery_slots": 8,
  "task_count": 2,
  "gift_count": 0,
  "package_count": 0,
  "decorations_enabled": true,
  "decoration_manifest": "decorations/decorations.json",
  "assets": [
    {"role": "hero", "file": "assets/hero.png", "height": 600},
    {"role": "marquee.background", "file": "assets/marquee-background.png"},
    {"role": "marquee.title", "file": "assets/titles/marquee-title.png", "width": 960, "height": 128, "display_width": 480, "display_height": 64, "text": "抽奖", "title_style": "current-activity-title-v1"},
    {"role": "task.title", "file": "assets/titles/task-title.png", "width": 960, "height": 128, "display_width": 480, "display_height": 64, "text": "抽奖任务", "title_style": "current-activity-title-v1"},
    {"role": "marquee.center", "file": "assets/marquee-center.png"},
    {"role": "marquee.highlight", "file": "assets/marquee-highlight.png"},
    {"role": "marquee.prize", "file": "assets/prize-01.png"}
  ]
}
```

实际清单须列出**每张** PNG；示例中的 8 格奖品还须补齐另外 7 张。没有某模块时，对应数量填 0，`lottery_style` 填 `null`。`hero.height` 必须等于用户本次手动输入并记录在 `design/analysis.md` 的高度；Banner 填最终 `height`；模块标题填写按本次母版确定的width、height、display_width、display_height、text与title_style，其他角色的尺寸由校验脚本按表推导。礼包每件的三态都要列出；任务条与按钮共用时，各种素材在清单中只列一张 PNG，HTML 可多次引用。脚本也检查页面引用的文件是否存在；全部校验与视觉验收通过后，直接交付该文件夹，不生成同名ZIP或重复目录。

正式交付还须填写`design_evidence`，指向记录实际KV、参考图片输入、组合样张及每张业务素材来源的JSON；格式与检查边界见[整页设计样张与真实输入记录](planning-and-references.md#整页设计样张与真实输入记录)。参考只有文字说明、缺少实际图片输入或未保存组合对照时，不得作为完成版交付。校验成功只说明规格、引用与证据结构完整，不代表视觉质量合格。

业务素材列在`assets`，独立装饰逐张列在`decoration_manifest`指向的清单，不套用业务角色的固定画布。`decorations/decorations.json`中的路径相对于该清单所在目录，尺寸是实际导出值，建议显示宽度和用途按本次页面决定：

```json
{
  "assets": [
    {
      "name": "本次装饰名称",
      "file": "decoration-01.png",
      "width": 1024,
      "height": 1024,
      "suggested_display_width": "按本次页面填写",
      "suggested_use": "按本次留白区域填写"
    }
  ]
}
```

默认清单非空，每张PNG均为真实透明前景，`decorations/`还包含`prompts.md`和素材总览`index.html`。以上1024×1024仅说明字段，不是固定装饰规格。用户明确不要装饰时，在`assets.json`记录`decorations_enabled: false`和非空的`decorations_omit_reason`；字段省略时仍按默认启用校验。制作档案保留独立装饰子文件夹；正式素材目录只平铺其中已验收的独立图片。

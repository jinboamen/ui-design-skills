# 活动页视觉分工

主 KV 是第一屏头图，承担活动主题和最强视觉记忆。下面的模块是同一场活动的功能区：按当前 KV 建立**媒介、造型、线条、光影、材质、色彩、排版和控件之间的共同规则**，但使用不同的信息结构和视觉焦点。不要每一屏都重复头图的大物件、道具组合或镜头构图。仅共享颜色仍可能像不同作品拼接；所有判断以本次 KV 的实际表现为依据，不套用过去活动的画风。

## KV优先的参考适配

**优先级：用户明确指定的视觉方向 → 本次主KV的画风与整体氛围 → 相容参考的设计方法。** 参考可以帮助制作得更精致，不能把整页换成参考的另一套风格。主KV不是仅放在第一屏的图片，也不是只提供主题名与几个色号；它决定内容区的媒介、色彩面积关系、光感、虚实、材质与字形气质。不强制逐区复刻KV物件和镜头，但整页应能被识别为同一活动的延续。

先用画风锁定表记录可见KV依据，再为每个参考标明“可借鉴的方法、必须按KV调整的部分、不相容而不采用的效果”。参考的题材和颜色相近，不能自动证明其硬软轮廓、材质、明暗、光影与KV相容。视觉参考不相容时重新寻找；仅结构有价值的参考可以用于布局，不用于生图的画风或材质。不能先把风格不相容的参考用于生成，再靠改色补救。

背景与控件的正向简报须解释怎样延续KV的可见特征。局部强调色不自动铺满所有按钮和标题；分块模式可将KV主色、辅助色、强调色及推导的深浅承托色分配为不同模块底色，允许明显的明暗或色相切换，按整页配色与内容对比判断，不要求各模块延续KV相同亮度。白字／高光不自动决定背景色，浅底也不因KV整体较暗而被禁止。材质与体积感按KV确定，不因题材名称自行联想到厚金属、糖果质感或其他无依据效果。平面、摄影、插画、三维等媒介均适用这些判断，不将本次KV的具体颜色或表现固化为下一次模板。

生图时同时提供KV视觉依据和经过相容性筛选的真实参考图片，并清楚标注各自角色：KV控制画风、配色关系、光感与整体气氛，参考控制适合本次的布局、肌理处理和细节完成度。连续整页背景直接参考完整KV延续画面；独立模块与前景可用能代表KV画风的非主体局部，避免复制头图主体。不能只给第三方参考图片，而把KV压缩成一句文字风格词。

小样阶段将KV、主要参考和回填标题／卡片／奖励／按钮的小样同屏对照，记录两项结论：“是否真正采用参考的方法”及“是否延续KV的整体效果”。任一项不成立都先修正，不批量生成。整页完成后逐区检查背景、统一标题、卡片、抽奖主体、按钮、任务及装饰的媒介、色彩重量、光感、虚实和材质，尤其检查最后的任务区是否另换一套风格。模块差异可以来自功能、同一配色体系内的明暗和清楚边界，不能来自互不相关的气氛。

这项视觉核对不等于要求整页像素复制KV，也不能用色号相同、文件尺寸正确或母版标识相同代替。参考对照用于确认借鉴方法，KV对照用于确认整页身份，两者不能相互替代。

## 前景控件与画面物件分开推导

具体单件制作按[单件素材的设计与质感](design-quality.md#单件素材的设计与质感)取得清楚的控件局部，先完成组件母版的边缘、表面与信息分组，再扩展同组素材。用户已认可的背景与配色作为局部迭代基准，避免用换风格代替提升完成度。

这是适用于不同题材的运营设计方法。先区分KV中“被拍摄或绘制的物件”与“品牌及页面设计语言”：人物、产品、服装、设备或建筑的材质用于理解主视觉，不直接决定按钮表面、卡片边框或标题字效。只有品牌设计、KV图形处理或相容的真实界面参考明确支持时，才把某种实体材质转为控件语言；仅有题材名称、同色号或一件同材质物件，不构成充分依据。

为本次前景记录四种职责：

- 主视觉/实体素材延续其摄影、插画或三维表现。
- 模块标题优先呼应KV正式标题与品牌字形的字重、比例、边缘和排版；不从照片中的物件推导立体字效。
- 卡片、按钮、任务条及底框按信息承托与操作层级设计，引用实际查看的相容界面控件；保留参考的轮廓节奏、边缘处理、层次和内容关系，具体可以是平面、立体、开放构图或完整衬底。不要把所有参考都简化成色块加细线；厚薄、材质与复杂程度由KV和参考共同支持，不固定增减。
- 独立装饰可为与主题相符的物件，也可为品牌图形、插画形态或纹样；不因实体道具容易生成而整套选用道具。

统一活动身份是色彩角色、字形、比例、光感和视觉重量相协调，不要求摄影背景、三维物件与网页控件全部使用同一种材质。平面控件与摄影/三维主视觉可以形成有意的媒介分工；不能因此自动判为失配，也不能把物件的写实细节迁移到每个文字面板。

先生成有代表性的标题、卡片、主行动、任务条及底框小样，回填文字并与背景同屏检查。明确记录控件形态来自哪项品牌/图形依据及哪处真实界面参考。若前景像来自另一种页面、厚边框和物件细节比内容更突出，或标题字效与KV正式标题气质不符，先修改前景，不以配色一致或“KV中有这种材质”为理由通过。使用有细节的控件也须证明其与本次整页协调；没有固定的平面、金属、卡牌、节庆或其他默认答案。

## 参考设计特征的保留与适配

固定交付规格不决定设计形态。先在选中的近期相容参考里指出使它成立的具体设计：标题字面比例与字距、控件轮廓及边缘变化、底景与内容的叠层、材质和明暗组织、留白与信息组的关系。不要把“参考某站、使用同配色”当完整简报，也不要把“克制、平面、易读”翻译成所有控件都用矩形细框。矩形或平面可以是经过设计的结果，不能作为无依据的默认模板。

在本次分析用一张简短表把设计转成可观察的制作要求，针对实际启用素材填写：

| 素材 | 参考的可见特征 | 本次保留和适配 | 放回页面的检查 |
| --- | --- | --- | --- |
| 统一标题 | 字面比例、字重节奏、字距、文字与配套形态的关系 | 延续KV字形气质，适配完整文案，保留明确的标题组织；无依据的英文、编号及字符不加入 | 看字形、轮廓和层次是否仍有参考依据，不能只比较颜色或PNG尺寸 |
| 卡片／奖品展示 | 外轮廓、边缘分段、内容区与强调区、图片和名称的组织 | 在既定画布和上图下名等功能规则内保留参考特点，不统一画成一个细框空面板 | 实际文字和奖品回填后，内容与造型是同一组合，不是散落在装饰框中 |
| 按钮／任务条／底框 | 可辨认的轮廓、局部厚薄、填充与光影层次、与信息组的关系 | 保留参考有用的表现，结合KV与功能层级重新设计；32px右距、底框包裹等要求继续满足 | 原参考、组合母版、单件及回填结果同时比较，指出具体保留和损失的设计特征 |

生图先描述要实现的设计特征与组合关系，再列必要尺寸、文字安全区及确实需要的排除项。安全区是实际文字与操作区域，不是一整张卡或整页中间全部空白；外围和非正文位置仍可保留相容参考的结构、材质及主题图形。不得让通用提示词反复覆盖素材特征，例如不看参考就给每件写“普通矩形、薄边、完全平面、中心大面积空白”。

实际图片输入同时包含KV、清楚的参考组件局部及本次已成立的组合样张。几何示意用于锁定坐标与宽高，示意的普通矩形不是最终造型；生成时明确以参考及组合母版确定可见形态。标题、卡片和按钮不能仅由几何示意从零生成。独立生成后通过编辑保持母版的关键结构，不逐件重新自由设计；缩放、裁切及透明画布校正时检查细节和比例是否丢失，不靠额外描一个方框补齐画布。

验收逐项指出参考中采用的具体特征在结果里是否仍可见。若参考具备字形设计、轮廓变化或层次，而结果退成普通文字、矩形细框、均匀色块，即使配色一致、来源记录完整也属于设计转化失败；先编辑组合样张或对应素材，不继续批量制作。另一方面，不为避免方框无依据地添加异形、复杂边框或效果；判断标准是本次参考的设计逻辑和KV的一致性，不是形状复杂度。没有实际查看原参考、组合母版与回填结果时，不能记录“设计质量通过”。

## 画风锁定表

从本次 KV 观察并记录下表，作为**每个模块**的生图提示词和 CSS 的共同依据。每套样张同时按[整页协调规则](design-quality.md#整页协调规则)确定背景与前景协调的造型气质、光感及字形关系，分别记录各类轮廓、边缘和结构，不要求共用边缘，不能仅列配色。不适用的项目标为“不适用”；不确定的项目保持宽泛，新增设计写明推导依据。仅排除与本次 KV 明确冲突的表现，不沿用上一活动的排除项。表中的媒介和元素举例用于帮助观察，不是预设风格选项。

| 项目 | 记录与复用的内容 |
| --- | --- |
| 绘制媒介 | 观察插画、三维、摄影、平面或混合媒介的实际角色；混合媒介记录各自用途与搭配关系，下方模块延续这套关系 |
| 造型与线条 | 区分品牌图形、界面控件与实体物件；确定本方案背景图形、标题配套形态和控件之间的造型气质联系；各类独立设计轮廓、转角／转折、线条与边缘，按显示尺度适配，注明功能依据，不共享边缘模板；不把实体轮廓照搬到每个控件 |
| 光影与材质 | 分别记录画面物件与品牌/界面设计的阴影、反光和表面表达；物件有立体光影不代表控件也须立体，按各层职责延续搭配逻辑 |
| 色彩分工与比例 | 主色、辅助色、强调色、内容承托色及大致面积关系；记录KV依据和用于哪些模块、控件或装饰，控制冷暖、明暗与饱和度节奏，不只列色号 |
| 共享视觉特征 | 有合适纹样时再提取，不强制数量或每区装饰；无纹样时可复用字形、几何比例、留白节奏或色块关系 |
| 字体与控件 | 优先观察KV正式标题和品牌字形；卡片、按钮与状态根据相容界面参考设计，共享视觉语法但按用途区分，不把“统一”理解为复用同一底图或同一种实体材质 |

把“共享什么”和“每区不同什么”分开写。KV 可提供笔触、色彩、光影、纹样、字体及空间感；每区的信息结构和前景焦点随功能变化，不要求每区另设镜头。按模块区分时，摄影或三维KV可以将非内容区的画面表现简化为网页底景，但保留其光感、虚实、材质气质与媒介关系；是否加入平面层由本次KV和相容参考决定，不能只靠配色换成另一套不相容的控件风格；协调的平面界面可以承托写实主视觉，不要求控件复刻实体物件的材质；整体衔接时，按KV制作完整连续的整页背景，保留整页场景与空间关系，不强制改成平面底景。独立模块或前景的风格参考优先选非主体局部；制作整体连续母图时可以直接参考完整KV进行衔接编辑，不将其核心构图重复复制到每区。

默认制作顺序按[最终背景与轻量前景样张](shared-assets-workflow.md)：三套最终背景配轻量前景示意，样张实际使用这些背景并遵守最终V1比例；用户选中后只精细制作一套前景，标题、状态及装饰正式PNG在此阶段完成。背景直接复用，必要盲盒底框及阴影修补限于局部，最终回填仍须对照所选样张。

## 统一模块标题素材

每次完整生成都为启用的套餐、盲盒或跑马灯抽奖、任务、礼包及平铺活动规则模块单独制作标题透明PNG。每个模块一张带完整文案的标题，**只变文案，设计样式统一**；不是只有空底板加普通HTML字，也不是在每张模块背景中重新画标题。头图原有主标题不另套模块标题，浮动规则入口不是章节标题；Banner已有原图不额外加字，只有确认需要独立章节标题时才生成`banner.title`。

**标题参考纳入本轮共用集合，实际查看后再生成。** 按[按设计缺口组织搜索](planning-and-references.md#按设计缺口组织搜索)优先使用已选整页、模块或独立组件中的清楚标题局部；只有缺少可用标题方法时定向补搜，不另设2～3个标题案例配额。依据本次KV字形气质、媒介与主题，记录来源、实际可见的字形／描边／层次／配套图形及具体借鉴点；不从摘要猜设计，不复制第三方标题或标志，不把本次参考固化为长期模板。只维护Skill时不生成标题。

在`design/analysis.md`列出用户本次手动输入或明确选用默认的完整标题、对应素材角色及实际回复；按[标题手动输入规则](../SKILL.md#模块小标题由用户手动输入)逐项获取，未给定时先询问，不能自行提出文案后直接定稿。套餐／盲盒／任务的默认填写提示分别是「套餐购买」「盲盒抽奖」「获取更多抽奖机会」，用户自定义优先且原样使用，不编造优惠或口号。写一份共同母版简报：字形、字号、字距、字重、主填充、描边、阴影／材质、配套几何形态、统一画布、安全边及页面显示尺寸。具体形式优先从KV正式标题/品牌字形与本次标题参考推导，不因照片物件具有某种材质而添加相同字效；不固定立体金属、白字、发光或其他效果；不额外添加英文副标题、大编号或装饰性文字。

### 模块标题的正常显示比例

以下针对内容区的章节标题，不改变头图主标题。统一标题需要有设计，但它的职责是分区与引导阅读，视觉重点仍属于套餐、奖励及主要行动；不从宣传KV或参考首屏照搬巨型字，也不因为标题独立生图而做成一条海报。

在1920px页面中，普通模块标题以**44px名义字号**为起点，通常在40～48px内结合KV字形与相容参考调整，实际字形主体高度约34～44px；用回填后的可见文字核对，不把PNG透明画布高度当字高。正文与卡片信息的字级按功能设计，章节标题不因正文小就继续放大。用户明确要求大型章节标题时按其方向调整并记录依据，不能默认继承此前活动的大字号。

常见4～8字标题的整张素材默认以**480×64px页面显示画布**起步，包含文字、配套图形及效果安全边；文案较长时优先调整画布宽度及装饰长度，不增大字号，也不缩放短标题到相同文字宽度。普通标题总显示高度通常控制在56～72px；这些是本次设计的默认起点，不用宽空画布把字压小，不裁掉参考中有作用的细节。各模块保持同一字号、画布与显示比例。

装饰线、切角或配套形态辅助文字，不通过过长横线、大色带、厚重描边或外光扩大整套标题的视觉重量。具体形态仍从KV和参考确定；有需要的线条与字面协调，避免把原本普通章节标题拉成巨大横幅。检查标题与下方内容的关系，防止标题高度逼近任务条、抢过卡片或挤占模块顶部空间；标题位置、模块高度和业务内容位置继续按V1，不靠挪卡片给大标题腾地方。

**导出像素与页面显示尺寸分开记录。** 例如1倍PNG为480×64，页面显示480×64；需要2倍清晰度时导出960×128，仍显示480×64。标题清单的`width/height`记录导出像素，`display_width/display_height`记录实际页面尺寸；HTML尺寸及CSS按后者，等比显示，不用天然大图尺寸、`width:100%`或整区宽度自动撑大标题。参考截图先按其真实页面比例理解字级，不把搜索大图的像素当网页字号。

母版阶段在1920px实际尺寸和整页缩览检查，并与卡片、主按钮及任务条同屏：文字清楚、分区明确、上下留白自然，第一眼仍能看到业务内容。标题偏大时先降低整套母版的字形与配套图形的显示尺度并重新排版，保持字形与细节清楚；不能只换PNG画布、保留同样大字，也不能增加透明留白后仍以同样大的可见字交付。最终检查所有标题的浏览器实际宽高与字号重量，避免CSS再次放大。

以最长标题规划能够容纳所有文案的同一画布与显示尺度。短标题在同一画布居中，字形与字号保持，不拉伸字或逐张缩放到同一宽度；阴影、描边与配套图形不裁边，不用特别宽的空画布把实际标题压成小字。先做母版小样并放回实际背景，再通过参考母版编辑／替换文案生成其余标题，不让工具逐张自由重设风格。每张PNG包含真实透明外部与可见完整标题，可单独摆放，不包括模块场景或其他业务内容。

逐字核对错字、缺字、重复字、标点和文案顺序；生图文字有误就修正并复核，不交付伪文字。把全部标题并列及分别放回页面，检查字号、字距、字面高度、配色、描边厚度、材质、光向和配套图形一致，差异只来自标题长度。标题在不同模块背景上都清楚，必要时统一调整整套描边或阴影，不为单个模块换一套样式。确认可读且不会抢走奖励与主行动焦点；沿用原标题区域，不改V1模块高度、卡片和任务位置。

标题母版必须实际输入本次KV字形依据及清楚的标题参考局部，或引用已使用这些图片的本次组合样张。重点设计字形比例、字重、字距和与内容组的关系；普通默认字体加单色色带不能仅因导出PNG、标题一致就通过。参照[整页设计样张与真实输入记录](planning-and-references.md#整页设计样张与真实输入记录)，先在完整组合中验证标题，再生成其余文案。

标题图片的完整文案是“图片无文字”的明确例外；模块背景仍无文字，其他业务文字仍由HTML提供。页面用语义标题容器内的`img`展示，并以完整`alt`保留文案，不另叠一层可见HTML标题造成重复。标题字段与结构标记见[模块标题素材](v1-layout.md#模块标题素材)。文件、尺寸、透明度与引用可由脚本检查；实际字形一致及文字正确仍须视觉验收。

## 配色分工与整页层次

先按[设计转化与视觉验收](design-quality.md#配色与组件一起设计)制作包含文字的组件总览，在真实背景上比较颜色角色、面积及视觉重量；色号表不是配色结果。

每次生成先从当前KV建立本次配色表，并写入`design/analysis.md`。主色负责活动识别和整体联系；辅助色丰富卡片、奖励与模块重点；强调色突出购买、抽奖等行动；低对比的内容承托色保证名称、价格与条件清楚。记录颜色来自KV的哪些部位、用于何处和大致使用面积，不预设固定颜色数量或面积比例。KV本身色彩克制时，可用其明暗、邻近色及饱和度变化建立层次，不为凑颜色强加无依据的色相。

| 对象 | 配色分工 |
| --- | --- |
| 标题及共同控件语言 | 保持活动识别色与整体联系，可通过深浅、填充或背景衬托形成节奏，不要求每个标题换色 |
| 套餐卡与购买按钮 | 正文区低对比、可读；多卡可用协调的冷暖或深浅变化帮助比较，购买按钮与卡片底色拉开层级，不自行暗示未提供的优惠或推荐等级 |
| 抽奖主体与奖品卡 | 主体和主行动保持最强焦点，奖品图片区及名称区使用协调的辅助色，避免所有层都用相同边框色和填充 |
| 任务条、状态及辅助入口 | 信息承托区细节更安静，但任务条主体须与底景清楚分离；在KV的总体明暗内利用填充、深浅和饱和度区分承托、操作与状态，不固定浅底或深底。两种状态都保留条目可辨性；用户名／次数仅文字，无独立或共同底框，中奖记录保留自身按钮；同组任务仍可复用样式 |
| 独立装饰 | 分散使用KV中的辅助色和强调色，小面积呼应各区；装饰丰富颜色的同时，卡片和按钮也须有合理分工 |

首轮背景生成及候选展示前，先按[内容区背景的亮面与视觉主次](design-quality.md#内容区背景的亮面与视觉主次)叠入实际前景检查亮面面积和局部对比；不把KV主角高光扩成内容区的大面积环境光，不以提曝光换取清晰，背景不能抢走卡片与操作的视觉重点。

样张确认后，将本轮已经成立的背景明暗、亮面面积、纹理强度及前景突出程度作为正式制作基准；每次背景编辑先核对外露背景区域，再回填实际组件对照。按[明暗气氛与前景层级继承](design-quality.md#样张的明暗气氛与前景层级继承)验收，不能因空背景要展示细节而提亮底景，也不把所有主题统一压暗。章节底色差异与主体突出程度须同时保留。

每条生图提示词除共享画风外，还要写该素材的颜色角色、主要填充、边框与强调部位，并说明需与哪项内容拉开层级。避免所有素材直接套同一套主色边框与浅底组合。不同功能的素材通过冷暖、明暗、饱和度和面积关系建立变化，仍须像同一活动；主行动的高对比保持集中，正文与大面积背景克制。选择「整体衔接」时不为区分模块逐片独立调色，继续从连续母图无重采样切片。

生图前将卡片、抽奖主体、购买／抽奖按钮和任务条的小样同屏比较；完成后在整页缩览及实际显示尺寸检查：内容区是否有清楚的色彩节奏，主行动是否突出，正文是否易读，任务状态是否可辨。若不同功能反复出现相同边框、填充和饱和度而失去层次，调整相关素材；若高饱和色铺满全页或新增配色脱离KV，也需调整。记录实际视觉检查结论；PNG尺寸和透明度校验不代表配色验收通过。

## 出图前先写模块简报

先用占位色块与 HTML 内容排出整页，再为每个被选中的模块分别确定：用户在该区要看什么、内容留白、前景素材放在哪里。按用户已确认的 [背景方式](planning-and-references.md#背景方式由用户选择) 安排连续底景或模块章节。表中的视觉角色描述内容功能，不要求每区另画场景；选择按模块区分时也要保持同一活动的视觉语法。

| 模块 | 本区主要呈现 | 背景与前景的分工 |
| --- | --- | --- |
| 套餐售卖 | 套餐选择、价格、权益和购买行动 | 模块背景按[套餐背景规则](design-quality.md#套餐背景以信息阅读为中心)用环境、留白和周边元素突出信息，默认不加卡片外的台子或托盘；以下文案面与行动承托均指卡片内部。名称、权益和价格在上方连续文案承托面内，以字级、间距和字色建立层次；不以顶部亮色块或嵌套面板切开文案区。默认连续底面，按KV确需分色时最多两块，第二块仅在下方购买区域，不能顶部或中间另加色带／面板；上方保留稳定的细腻表面与文字范围外的边缘设计；“立即购买”是独立透明按钮底图，不能与卡片背景合成 |
| 盲盒抽奖 | 抽奖主体、两侧奖品图与名称、行动按钮、中奖提示 | 带清晰「？」的盲盒为焦点；两侧每项为上图下名称的完整卡片，底图尺寸随数量、图片区和最长名称确定，名称HTML换行；无实图仍保留图片区，不做名称长条，背景支持内容与行动 |
| 跑马灯抽奖 | 奖品格子与中心抽奖入口 | 背景退后，棋盘和奖品成为视觉中心；每个奖品是独立透明图，不把 KV 分割到格子里 |
| 抽奖任务 | 任务类型、状态与领取按钮 | 更克制的背景与整齐的任务条，让文字和状态一眼可读；避免大型叙事插画压住功能信息 |
| 礼包领取（仅用户主动启用） | 礼包内容及未领／已领／领完状态 | 礼包区与卡片状态形成清楚对比；三态的形状与色彩应可辨，不用同一张头图裁三次 |
| 普通 Banner | 承接上一模块或提示次要活动信息 | 有独立上传图就按原图使用；需要生成时做新的辅助画面或信息条，不复刻头图主构图 |

这些是角色分工，不限定具体风格。可以沿用 KV 的暖冷关系、材质、边框、光效或小型品牌符号；相邻模块应有明暗、密度或构图节奏变化，整页仍像一场统一的活动。

## 活动氛围与内容焦点

背景素材保持无文字、无数字、无装饰性字符，不加入大号章节序号、英文角标、无意义代码或伪文字。此要求同时适用于页面叠加层：不要把同样的背景装饰改成HTML或CSS再放回页面。模块标题以统一设计的独立透明PNG排入HTML语义标题容器，完整标题文字是独立标题素材的例外，不画进背景；说明和按钮文案等其他真实内容用HTML排入；不自行补英文副标题或标题旁的装饰符号。按实际KV确定的低对比材质、纹样、色块与边框可承托内容，不能用文字和符号填补留白。KV中已有的正式活动文案、任务顺序编号以及盲盒「？」识别图形分别按内容与功能保留。

**默认目标是有主题与设计层次的运营活动网页。** 头图承担最强主题表现，下方模块承托套餐、奖励、参与入口和任务，也需保留来自KV的视觉特征。活动表现由主题造型、统一设计标题、卡片层次、奖励展示与主行动共同建立；不靠每区重画热闹场景，也不把“背景克制”当成纯色底加普通卡片即可完成。文字区保持干净，模块整体可以有协调的图形、材质和明暗层次。

**「按模块区分」采用适度丰富、可读且分区明确的底景。** 先设计基础色彩与明暗，再按KV和内容加入有作用的图形层、局部衬底、轻纹理或边缘主题元素；不把纯色／单一渐变设为所有活动的默认终点。标题、正文与操作所在区域细节少，非内容区域可以更有表现力，但不四角堆物或整屏碎片。整体衔接仍制作完整整页背景，允许KV主题场景贯穿页面；两种模式均保证内容清楚，不把安全区的低对比要求扩展为全页没有变化。

### 丰富但清楚的运营设计

每个模块简报同时回答“哪些区域必须安静”与“本区的主题与层次由什么体现”，明确正向设计，不只列禁用项。可按功能考虑三类视觉作用，选择适合当前KV的组合，不机械叠加所有效果：

这些设计方法是用于分析参考的候选工具，不是自由添加效果的菜单。先按[参考驱动的设计与生成](planning-and-references.md#参考驱动的设计与生成)查看共用参考集合中对应的运营模块或背景设计局部，按[背景肌理与表现形式有据可查](planning-and-references.md#背景肌理与表现形式有据可查)提取实际肌理、层次与边界，再适配当前KV；不先想象效果再寻找理由。

背景同时以KV图片和相容的真实参考图片约束，区分底景和前景各自的表现，按[参考图片输入与相似性验收](planning-and-references.md#参考图片输入与相似性验收)做并列对照。不因颜色相近就自行替换参考的材质、细节尺度、图形结构或空间关系；前景的强调色与材质也不自动成为背景主结构。具体现象先按KV确定视觉方向，再按相容参考判断借鉴方法，不预设固定颜色、明暗或绘制媒介。颜色一致但肌理、结构和视觉重量明显不同，仍属参考使用失败。

| 视觉作用 | 可选的设计方法 |
| --- | --- |
| 基础组织 | 有方向的明暗、大色块或协调的主辅色关系，为内容建立位置与分组；不把全区铺成同一种颜色和材质 |
| 区域承托 | 局部衬底、图形形态、低频轻纹理或柔和局部光影，帮助标题、套餐组或奖励成为整体；按需使用，不每区套同一大框 |
| 主题识别 | 当前KV有依据的轮廓、材质、纹样或独立装饰，在非内容区形成可辨主题；不重复整张KV场景，不靠无关道具与字符补设计 |

套餐以清楚的选择与购买为重点，卡片正文安静但边缘、强调区和材质可以精致；抽奖可围绕奖励设置局部视觉重心，盲盒底框归抽奖背景并继续遵守完整包裹、居中及融合要求；任务用更清楚的条目和状态收束整页节奏，不要求任务区与抽奖区同样热闹。模块之间变化来自视觉重量、层次与功能，不只换底色或装饰位置。标题整套样式仍统一，只替换文案。

从实际查看的PC参考中提炼内容区如何在保持清楚的同时建立设计层次，不只借鉴最空的底色或最复杂的海报。背景肌理和表现形式追溯到清楚可见的参考区域，配色与主题适配当前KV；不能用“合理推导”给无依据的背景特效找理由。纯平面KV可沿用参考的字形、比例和色块组织，不强制描边、金属、立体与光效。

小样恢复标题、卡片、奖励、文案和按钮后检查两种失败：背景太复杂抢走内容，以及过度简化成普通矩形卡片铺在单色上、丢失KV主题和参考的有效层次。与KV和相容参考同屏核对，先确认KV气质延续，再核对借鉴方法；复杂时恢复相容参考的细节强度与留白，单调时补回参考中确实存在的色块、图形或材质组织，不自行堆光效、粒子或装饰。先修正小样，再批量生成。此项为视觉验收，不使用固定装饰数量、效果数量或像素得分代替。

**结构先于装饰。** 先统一标题与内容的对齐轴、卡片分组及留白节奏，遵守V1控件尺寸与间距，让用户能顺着“活动主题 → 套餐／奖励 → 参与行动 → 任务”阅读。套餐以卡片与购买为焦点，抽奖以未知奖励和主行动为焦点，任务以条件与状态为焦点；只使用已确认的模块和真实信息，不为运营感编造优惠、排名、日期或口号。局部衬板按内容需要使用，不给每个模块套一个巨大的装饰外框。

**整体衔接制作完整整页背景；按模块区分制作有设计层次、分区清楚的独立背景。** 整体衔接先按[头图比例适配与完整KV保留](v1-layout.md#头图比例适配与完整kv保留)适配原KV，再从适配后头图的真实下边缘向页尾延续，根据当前KV统一设计场景、材质、纹样与空间层次，可以是连续主题场景，也可以是符合KV的连续平面图形；不能自动退成纯色模块底景。头图与全部启用内容模块共同组成母图，接缝的形状、纹理与色值实际连续。按模块区分保持每对背景明显的底色／明度差异，通过标题与分组表达章节；允许颜色切换，不允许笔刷、斜线或曲线被切片边缘截断。正式背景按[两种模式的跨界组合与导出](v1-layout.md#两种模式的跨界组合与导出)先完成共同坐标的组合母图与交界，再原像素导出，避免一章一张照片。不得在错误接缝上临时加CSS渐变、模糊或遮罩冒充衔接，按[整体背景切片与接缝验收](v1-layout.md#整体背景切片与接缝验收)执行。

### 分块模式的上下分区

本节仅适用于「按模块区分」：从本次KV提取一套活动配色，为各模块分配清楚不同的大面积背景色面。统一的是活动视觉体系，不是每个模块的底色、明暗或同一个空间场景。相邻模块必须有一眼可辨的底色／明度差异，标题、前景、留白及细线不能代替这项要求；不以“统一气氛”为由将所有模块压成近似色底。

**先分配模块配色，再设计每区背景。** 在本套design/analysis.md记录KV的主色、辅助色、强调色及可由它们推导的浅色／深色承托色，标明来源、各区选色及大致面积。允许深—浅—深、暗底—强调色底—暗底、相容的不同色相分区，颜色可以有较大的明暗反差；这些是可选组织方式，不是固定顺序、颜色或必须突出抽奖区的模板。暗色KV也可以设计浅色模块，KV中的辅助／强调色可以经面积与前景对比设计成为某区底色，不只限于按钮点缀；不能自动铺满所有模块。全套仍需有明确的活动主色联系，不随机添加无依据的颜色。

**用界面设计维持统一，不用连续场景维持统一。** 标题母版、组件语言、对齐、主题图形、边缘处理及相容的材质表现建立整页联系；不要求各区同曝光、同光照环境、同地平线或同镜头。摄影／三维KV可在内容模块转化为相容的色面、纹理与局部主题图形，不要求每区重新生成一张山谷、树林、海岸或室内场景。需要场景局部时让它服务于该区色面与内容，不能以几张不同场景图加卡片充当模块设计，也不能把整页做成一张贯穿树林／山谷而只靠标题分区。

**色面清楚，设计层次按需保留。** 各区先有足够面积、相对稳定的底色承托，再安排纹理、图形叠层、边缘装饰及局部主题元素；深浅两种底色都可精致、丰富，不能因采用色块分区就一律退成无设计的纯色底。也不为证明丰富而强加密集景物或高频纹理。按内容调整聚散与留白，不重复同一种包围构图，不给套餐新增专属台子。前景在本区底色上须清楚突出：浅色底不等于背景抢眼，判断看局部对比、信息可读性及焦点；高亮反射或复杂场景抢眼也不能只靠全区压暗补救。

**明确边界与完整收口。** 相邻底色可在完整的水平直边、斜切、主题图形轮廓或笔触收口处切换；无需把颜色渐变混合到看不出模块。直线色面边界本身不是错误接缝。跨界图形有意延续时才检查对应部分完整承接，不要求所有背景物件跨模块延续。分割线可有可无，底色已分明即可无线；采用时按[唯一归属与标题避让](v1-layout.md#模块分割线唯一归属与标题避让)制作一次，不双线、不压标题、不插入额外空白横带。所有转场保留在既有模块尺寸内。

各套A／B／C分别规划上述配色分工，在各模块生成／编辑输入中写明本区主底色、相邻区底色、边界方式、主题层次及内容安全区，同时输入KV与相容参考。不能只写“同一画风、稍微换色”；也不能把三套方案之间的差异当作同一方案内部的分区。保持实际高清背景＋轻量前景流程，执行者完成设计和返修，不让用户额外选择配色或指导每个模块。样张选中后锁定实际背景、色面与边界，直接复用；必要局部融合编辑不改动无关分区。按[跨界组合与导出](v1-layout.md#两种模式的跨界组合与导出)形成共同坐标母图并原像素切片；共同母图是组装与导出依据，不代表必须画成连续场景。

展示前在整页缩览和实际尺寸检查，并写入现有background_design、color_hierarchy及content_composition观察：

1. 临时隐藏标题和全部前景、忽略细纹理后，相邻模块仍能通过大面积底色辨认起止；如果只有同一片树林／山谷／水面与近似色雾气，只靠标题识别，记revise，重新分配并落实章节色面，不能只加分割线。
2. 恢复前景后，颜色能追溯到本次KV配色体系，标题和组件属于同一活动，内容突出且阅读清楚。深浅反差、色相变化和完整直边不单独判失败；无依据的配色、失配材质、独立场景拼贴或内容被淹没才需修复。不要用“同明暗／同环境”作为统一性门槛。
3. 逐缝检查有无图形意外裁断、重复边缘及标题压线。设计明确的色面切换须保留，不能为了衔接将深浅差异抹平。

上述分区与统一性必须同时成立，不以单张漂亮、尺寸正确或来源同一KV代替验收。整体衔接仍按连续母背景规则执行，不套用本节的逐区色面切换要求。

### 背景生图简报与验收

先按[背景设计直接借鉴参考](design-quality.md#背景设计直接借鉴参考)落实参考的底层肌理、色面、图形叠层、光影虚实与收口，再写以下功能和制作约束；不让笼统的“安静、低对比”把参考的有效背景表现全部抹掉。

每条内容背景生图简报明确以下四项，避免只写“同画风、精美、有氛围”：

| 简报项 | 必须明确的内容 |
| --- | --- |
| 功能与焦点 | 本区要展示什么、希望用户做什么；最强焦点属于哪些前景内容 |
| 安全区 | 从页面骨架取得标题、卡片、奖品和按钮区域的实际位置与范围；这些区域低对比、无复杂图案 |
| 底景 | 本次KV依据、背景模式与明暗组织；整体衔接写整页场景／图形如何延续，分块写本区底色层次、主图形位置与走向、留白形状、视觉力度及主题识别，相对相邻区的具体变化、共同材质与上下边界 |
| 点缀与排除 | 主题元素及允许位置；按模块区分默认排除独立风景照、电影式景深、每区新镜头和透视舞台；整体衔接保留整页场景表达，不套用这些场景排除项。两种模式均避免遮挡内容的碎片与强光，以及背景文字和烘焙的UI内容 |

用户选择整体衔接，即授权按当前KV制作完整连续整页背景，无需再询问是否允许场景化。分块模式可直接设计有依据的局部材质、主题图形与边缘元素，不因它们有体积感而另行询问；只有用户明确要求某区使用完整场景画面时，才放宽避免独立风景照的背景形式，仍需保留安全区与操作焦点。

**小样与整页按实际内容验收。** 把标题、价格或授权占位、奖品及操作文案叠回页面，在实际1920px尺寸与整页缩览查看：第一眼是否落在内容与主行动上；信息是否成组对齐；相邻模块是否像同一个网站；背景是否仍比前景安静。整体衔接检查完整背景与真实连续性，主题场景贯穿整页不判为违规；按模块区分对照选定参考检查主题层次、模块边界与阅读清晰度；若像照片／海报拼贴，减弱复杂场景，若像单色卡片模板，补足有作用的图形、色彩或材质层次。两种模式若内容只是零散摆在壁纸上，均需调整分组与局部背景密度。纯背景视图用于查接缝和装饰，不单凭空背景的漂亮程度通过。视觉结论写入本次分析，尺寸与透明度校验不替代这些判断。

## 盲盒主体的设计完成度

`blind.art`是抽奖区的主视觉物件，不属于任务按钮或信息卡的控件模板。造型、包装结构、表面、主题图形及光影按当前KV与本次有效主体参考完成设计；不能把针对UI的“平面、克制、少装饰”限制机械套到盲盒，默认只生成均匀盒体加问号。

生成简报应明确本次盒体的具体设计及参考出处，例如已采用的盖体／封装关系、结构接合、包装细节、主题识别处理、面与边的层次和表面光感；只采用与KV、参考及真实造型相关的做法，不强制每盒添加绑带、机械零件、蝴蝶结、金属、划痕或发光。平面主题也可有精确的造型及包装图形设计；结构与识别必须在既定显示尺寸成立，不靠追加背景光效代替盒体设计。

用户已经认可的盲盒按[保留已认可素材，按对象改进](design-quality.md#保留已认可素材按对象改进)沿用原素材，不重新抽图去配合新卡片。验收对照原素材及对应主体参考，问号清楚、材质有颜色、背景漂亮均不足以证明主体完成；有依据的主体特征丢失或降级为基础几何占位时不能通过。与原素材一致的质感精度和与本次整页的主次关系分别检查，背景内底框继续按V1定位、覆盖与融合要求制作。

## 盲盒问号标识

盲盒底框默认保留，直接绘入blind.background，不单独输出blind.backdrop；底框与盒体、奖品和按钮先在最终V1坐标中共同设计。底框依然是局部衬板，可有实色、渐变或材质填充，不扩成包住全部奖品的大框；底框填充内区完整包裹盒体含蝴蝶结与盒盖，同完整可见主体水平、垂直同中心，允许零额外留白。奖品可压住边缘并探出，但线条始终在图片和名称后；保持盒体与奖品留白，底框不抢主焦点。继承确认样张的承托结构、转折、环境连接、光影与空间／图形关系，去掉前景只补遮挡区域，保留底框设计；盒体、奖品和按钮继续独立。按[成组制作及融合验收](design-quality.md#底板与背景成组制作及融合验收)恢复全部前景，对照样张和最终组合；底框在背景里存在或包裹成立都不能代替融合。主体位置／尺寸或奖品排列变化时同步编辑背景内底框及相关光影，再按[V1包裹与居中验收](v1-layout.md#底板包裹与居中验收)测量和截图，不能放任固定背景失配。用户明确取消底框本身时才记录关闭，不把不导出PNG当取消。

`blind.art` 的盒体正面或主要可见面必须有清晰可辨的「？」图形，让人直接识别为未知奖品的盲盒。问号随当前 KV 的媒介、造型、材质和光影设计，可以是印刷、浮雕、镶嵌或其他合适表现，不固定颜色或风格。将它直接生成在盲盒 PNG 中，保持与盒体透视一致、轮廓完整、对比足够；不只画在底座或背景上，也不以普通锁扣、灯条或装饰纹样代替。

每条盲盒生图提示词明确写出“盒体主要可见面上有醒目的完整问号图形，包含下方圆点”。使用“无文字／无字母”约束时明确问号图形是例外，活动名称和操作文案仍留给 HTML。校正为 317×300px 透明 PNG 后，在页面 317×296px 显示尺寸及整页预览中检查问号仍能辨认；问号缺失、像其他符号、被遮挡或过小看不清时，调整提示词并重新生成盲盒素材。

## 按钮按用途分别设计

页面内容较少时，跨模块复用同一按钮会占据明显的视觉比重。先在本次 `design/analysis.md` 列出所有实际出现的按钮：所在模块、功能、重要程度、状态、固定画布、造型差异和素材路径。任务模块内部可共用任务按钮；跨功能层级不复用同一张底图。

- **层级与复杂度**：不同按钮分别出图，但层级区别可以通过实心/描边、明暗、线条重量和留白建立。独立样式不等于每个按钮都要新增外框结构、立体边或道具；保持同一套界面语言，避免为差异化变成多套风格。
- **主行动**：抽奖、购买等按各自内容建立视觉重点；从当前 KV 推导轮廓、边框结构、内部构图或装饰位置，不固定为某一种立体、发光或金属样式。套餐购买按钮与套餐卡分别出图，但同一方案无论多少套餐均只出一张卡片底图和一张按钮底图供全部实例复用；按钮底色与套餐卡正文区有足够对比，中间为HTML文案留净。
- **任务行动**：同一个任务模块的多个任务可共用一张任务条背景、一张可操作按钮及一张已完成按钮。任务名称、说明与操作文案由 HTML 区分；有明确视觉需求时也可分别制作任务条或按钮，不强制差异化。两种状态均遵守下方的饱满形状与对称要求。任务条保留连续底面，按按钮距右边32px的固定位置留出净空，不另画操作包裹色块、凹槽或底座；先回填独立按钮验收，不挪动按钮迁就底图；按[任务按钮位置与底图配合](v1-layout.md#任务按钮位置与底图配合)生成和检查。
- **辅助入口**：中奖记录、活动规则按各自位置和重要程度设计独立样式，与主行动拉开层级。“奖品概率”仍按 V1 规定保留为下划线文字入口，不为增加变化改成图片按钮。
- **启用浮动方式时，活动规则按钮必须醒目**：正常状态下即可发现入口，按钮主体与周围背景有清楚区分，文字与按钮底色有足够对比，完整清晰、易读易点。辅助功能不等于低可见度；不能用过低对比、过淡透明度或仅悬停强调来满足要求。外观跟随当前KV与界面语言，不固定颜色、材质或光效，也不以闪烁或夸张动画代替清楚的设计。按209×64px实际显示尺寸回填“活动规则”文案，在头图及滚动经过的各模块背景上检查始终醒目；检查固定入口完整可见、可点击且不被装饰遮挡，未通过时修改底图或配色后重新验收。
- **中奖记录与任务操作的区别**：二者即使都是160×60，也须分别设计。与任务可操作及已完成底图对照，从外轮廓、内部填充、边框结构中建立在实际尺寸仍清楚的差异；只去掉小灯条、改文字或微调颜色不算独立造型。不能把任务状态图当成中奖记录。差异遵循当前KV的控件语言，不固定为某种配色或形状；不依靠箭头、图标、偏心装饰制造区别。生成前分别写简报，验收时与真实任务条同屏检查。
- **抽奖主按钮的文字居中**：生图提示词明确要求左右对称的外轮廓、相等的端部与文字内边距，以及与画布中点重合的干净文字区；不使用单侧图标、指示灯或凸出结构。装饰可成对或位于中轴，不固定为某种机甲或发光风格。透明留白也保持均衡；按最终显示尺寸叠加真实操作文字，检查外轮廓中心、文字区中心与文案中心重合，左右视觉重量均衡。底图失衡时修改底图，不靠给文案加单侧padding或位移凑居中。
- **中奖记录与任务按钮的形状**：`lottery.record`、`task.button-available`、`task.button-claimed` 均按 160×60px 的比例设计可见主体，填充按钮区域，仅留最小透明安全边。提示词明确要求饱满的按钮高度、左右对称的外轮廓与边框、平衡的透明留白，以及没有文字、箭头、图标、勾号或单侧装饰的干净中心。不得将细条居中放进高画布，也不得用非等比拉伸补高度。任务与记录仍按功能区分层级，不因此整页共用一张底图。
- **状态变化**：同一按钮的可操作、已完成等状态保留基本身份，不同状态分别导出。任务按钮用明暗、填充及 HTML 状态文案区分，不加勾号、箭头或其他图标；状态切换时可见主体的轮廓、尺寸和位置保持一致。不要为了变化把同一个功能的状态做成互不相关的按钮。

验收记录与任务按钮时，在最终 160×60px 显示尺寸逐张查看透明 PNG 和页面中的真实文字。核对非透明主体是否接近整个宽高、左右视觉重量与安全边是否均衡、文字是否水平和垂直居中；不能只检查 PNG 文件尺寸。页面使用等边内距及正常居中排版，禁止单侧 padding 或文字位移补偿图形不对称。过细、留白过大、带图标或偏心时重新生成底图。

生成提示词中的比例是**可见按钮主体**的比例，不只是图片画布比例。尺寸校正后，以排除半透明外阴影的主体边界检查，可见宽度和高度都应至少达到画布的90%，在160×60画布中分别不少于144px与54px；适量透明安全边与切角仍可保留。若文字提示仍生成细条，给图片生成工具提供正确比例的简单布局轮廓作为几何参考，再按当前KV绘制成品；不要拉伸旧图凑比例。可操作与已完成状态也按同一轮廓核对。

所有差异都在固定画布内完成，沿用本次 KV 的媒介与表现逻辑。批量出图前将本次各功能层级的按钮小样放在一张对照图中，并回填到页面检查主次关系。任务内部复用属于同一层级；若抽奖主按钮、任务按钮、记录和规则入口只是同一底图改色或缩放，继续调整。若差异使它们像来自不同活动，也需调整。

## 生图提示词与验收

- 头图：可用 KV 作为直接图片参考，并保留其主要构图；最终画布为 1920px 宽、用户本次指定的高度。原图比例不符时按[头图比例适配与完整KV保留](v1-layout.md#头图比例适配与完整kv保留)默认完整等比容纳并延展背景，不自行裁切；过小或构图不成立时先确认高度或重新构图选择，再在既有3套样张内展示。检查原内容完整、文字准确且可读、比例不变形，不以保留主要构图为由删掉其他原内容。需要可编辑文案时预留位置，由 HTML 添加。
- 其他背景：每条提示词包含本次画风锁定表和用户确认的背景模式，以及上节的功能与焦点、安全区、底景、点缀与排除四项。整体衔接以完整KV为衔接依据，设计贯穿所有启用模块的完整整页背景；按模块区分使用简洁独立模块底景，风格参考可取KV非主体局部，避免每区再次生成独立风景或海报。主体内容另行叠入，不适用的材质、光效或纹样不补造。
- 透明前景：按[背景承托与组件的分层归属](design-quality.md#背景承托与组件的分层归属)单独制作，并按[光影逐项归属与回填](design-quality.md#光影逐项归属与回填)区分主体受光、接触／投射与环境照明；清理主体轮廓不能一并丢掉交互光影；输入完整模块与本件局部，明确本件的物件／状态、自身表面和附属设计、画布与安全边，指定本次实际存在的环境层、底板及邻近组件由哪些层承接，不因分层措辞额外生成模块舞台，不能因位于主体后方便全部带进本件PNG。奖品、按钮、任务条、礼包卡不能靠裁切头图得到。按钮提示词写清主行动、任务、辅助入口之间的造型与层级差异，并保留本次 KV 的材质表现和边框语法；任务内的同状态按钮可共用素材。
- 先做跨至少两个相邻模块的背景小样与一个前景小样，放回页面，在**同一张 1920px 截图**里与头图比较。若偏离本次确定的媒介关系或控件体系，或重复头图构图，重做小样，暂不继续批量生成。
- 继续制作时检查相邻模块：选整体衔接时检查背景切片接缝和视觉元素是否自然接续；选按模块区分时检查章节转换是否清楚、是否仍像同一活动。临时隐藏标题和控件看纯背景，确认实际做法符合用户本次的选择。
- 整页验收：缩小查看整页时，先判断是否像**同一活动的网页**，再看套餐、奖励、任务与主行动是否清楚成组，背景是否退后。检查颜色关系、造型、卡片与按钮语法连续；安静平面底景与立体前景可以搭配，不因媒介简化而判失配。整体衔接验收完整连续母背景、真实接缝与场景中的内容留白；按模块区分若像一块块照片，减少复杂场景；若过于单调，对照参考补足主题与设计层次。两种模式若反复复制KV核心构图或背景争抢注意力，调整局部密度与内容组织，不强制整体连续背景改为纯色；若控件像来自不同活动，重做失配控件。尺寸和透明度校验通过不能替代这一步。

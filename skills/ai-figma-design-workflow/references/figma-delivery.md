# Figma 制作与验收

写入或修复设计稿时阅读。依据实际项目选择适用项，不把移动端控件习惯套到网页或后台。

## 写入前的确认条件

默认依据用户已确认的对应视觉样张落稿。用户明确要求“直接生成/修改 Figma”或跳过样张确认时，可依据该授权直接制作，不要求补一轮样张确认。记录适用范围及授权依据；没有确认也没有直接制作授权时，先交付样张等待确认。直接制作仍需完成联网研究、独立 UI 设计及实际验收，不能省略视觉设计。

## 原始内容逐项核对

开始制作时，从原型、需求或原稿列出实际文案、数据、提示、操作入口及已给出的状态，与最终界面逐项核对。新增视觉不意味着新增产品内容。

- 禁止擅自编写标题、辅助说明、占位提示、角标、统计数据、成功/错误提示或说明性小字；也不能把外部参考的文字、数据和控件入口搬进当前产品。
- 原始内容不完整时，明确指出缺失项；必要时向用户询问。未获授权前，缺失不在产品界面中用虚构内容或“待补充”等文字填补。
- 测试布局使用的长文案、测试数据及验证节点必须还原，不能混进正式交付。
- 用户明确要求补充或修改内容时按对应授权执行，记录来源和范围。
- 这里要求严格保留业务与内容，原型的粗糙颜色、字号、间距与控件外观仍须单独设计。

## 组件属性与复用

| 差异 | 优先表达 |
| --- | --- |
| 标题、说明、条目名称、按钮文字 | 同一组件的文字属性 |
| 描述、次按钮、标记、辅助操作显隐 | 布尔属性 |
| 头像、图标、插图或其他可替换子组件 | 实例替换；真实图像保留图片资产 |
| 尺寸、选中状态、语义类型等实际视觉差异 | 同一组件集的变体 |
| 选择器 | 当前值、展开状态与菜单选中项一致 |
| 结构与用途实质不同 | 必要的独立组件，不强行合并 |

不要为文字、显隐与状态的每种组合创建一个变体。暴露有用的嵌套属性并在外层实例实际修改测试；属性未绑定到对应节点不算完成。

复用优先采用有效母版实例及对应变量/样式。创建前检索相同结构与用途的组件，重复 UI 使用同一母版实例；纯文案、图片或业务名称变化通过属性表达，不新建母版。新建组件需在当前功能中有复用或状态维护价值，不把一次性说明文字都做成组件。验收比较结构、样式和用途，不能只凭名称判断是否重复；必要的新状态收进同一组件集，避免重复和变体组合膨胀。

合并重复母版前核对实例的文案、资产、状态、覆盖属性、布局与连接；迁移成功后再删除无用途的旧节点。改变全局母版前确认影响范围，不为局部需求误改其他页面。

## PC Hover 状态

- PC 页面包括桌面网页、后台和桌面应用。本轮新增或修改的可交互控件应交付 Default / Hover，优先复用原规范；没有 Hover 时单独设计与产品一致的视觉反馈。
- 适用对象包括按钮、链接、菜单/导航项、可点击卡片/列表项，以及具有悬停反馈的其他操作入口。静态文字、装饰、不可交互容器无需增加 Hover；禁用状态不添加暗示可操作的悬停反馈。
- 使用同一组件集的状态变体，例如 State=Default / Hover；保持文案、图标与尺寸属性复用，不把 Hover 建成互不关联的独立组件。状态变化不应无故造成跳动或挤压布局。
- 多端项目仅在 PC 版使用 Hover。移动端不要求悬停视觉，不为触屏专门添加 Hover 状态或悬停连线；共享库已有 Hover 变体不必删除，但移动端画面不依赖它。
- 在同页组件区域展示 Default / Hover，切换实例并查看实际截图。样张可展示必要控件状态对照，不为每个悬停效果复制完整页面。
- 画出 Hover 与配置 While hovering 等原型触发是两项工作。本规则要求前者；后者按用户交互需求执行，已有连线按原规则保留。未配置/未验证触发时，只能报告“已设计 Hover 状态”，不能报告“Hover 交互已完成”。

## 布局与层级

- 主要内容使用水平/垂直 Auto Layout；文本和内容容器适当使用 Hug contents，可用空间用 Fill container。
- 固定尺寸用于规范明确的图标、头像、控件高度、列宽等，不为压住布局问题把所有高度锁死。
- 横纵排列、不同间距、对齐、滚动或定位语义需要时允许嵌套；纯包装层应省略。
- 装饰、关闭图标、蒙层等可用绝对定位；正文和主要控件应由真实布局驱动。
- 容器设置宽度、最小/最大尺寸及必要留白，检查父容器变化对 Fill/Hug/Fixed 的影响。主内容与应延伸的内层容器设置 Fill container，避免仅最外层变化、内部仍固定宽并全部挤在左边。同级等分卡片/列采用一致的 Fill 分配与间距；规范要求固定的侧栏、控件或图标保持其合理尺寸。设置内容最大宽度时，达到上限后按设计居中，不无故只留下右侧大块空白。
- 宽度变化时根据设计使用换行、重排、最小宽度和必要滚动，不让控件互相覆盖。需要不同端布局时在对应画框分别表达，不以“用了 Auto Layout”代替实际自适应效果。
- 每层 Frame 都应具有明确的布局、对齐、间距、裁切、滚动、定位或组件边界作用；没有作用的重复包装层应合并。不得只为给每行字命名而套 Frame。
- 页面/屏幕画框默认无装饰圆角；内部卡片、控件、浮层沿用对应规范。
- 多端设计按任务要求检查实际重排。声明“支持响应式”前验证相应尺寸，不用两张静态截图作为全部证明。

平台适配：
- 桌面网页与后台：内容最大宽度、列栅格、侧栏、工具栏、表格密度、按钮宽度分配与用户指定断点相匹配。
- 移动界面：按目标设备/产品规范处理画面宽度、安全区、导航、触控尺寸和底部区域。
- 桌面应用：按要求处理窗口结构、工具面板与内容区；不擅自套用手机底栏。
- 长页面：高度由内容决定；分段或滚动方式以当前需求为准。

## 四周内边距强制验收

此项为交付必检，不得以“已启用 Auto Layout”或仅检查元素间距代替。

- 逐个核对本轮页面内容区、卡片、弹窗、按钮及其他内容容器的上、下、左、右 Padding，使用对应正式规范或本轮设计依据；不统一猜测固定值，也不强迫四个方向相等。
- 同时看属性数值和实际可见内容的位置，检查文字、按钮、图标与容器边缘的距离。内层固定尺寸、对齐/约束错误、绝对定位、文字换行或尺寸变化，都可能导致数值存在而视觉仍贴边。
- 在较窄、基准、较宽画框及长文案、按钮显隐、变体切换后复查四边，确认留白符合规范、不意外归零，也不挤出或裁掉内容。
- 检查底部操作区、安全区、首尾列表项及弹窗内容的顶部/底部距离；文本和图标在按钮内也需保持设计要求的留白。
- 明确的通栏背景、满版图片、分割线、蒙层等允许按设计依据贴边。验收要区分有意的贴边设计与内容错误贴边，不为避免贴边而随意缩小素材或增加包装 Frame。
- 优先直接修正对应 Auto Layout 容器的 Padding、对齐、尺寸与约束；避免用空白文字、占位矩形、手动坐标或冗余画框补边距。
- 非预期贴边视为验收失败：修正后再次检查受影响尺寸与状态，记录检查范围、边距依据及结果。临时测试文案和尺寸应还原。

## 弹窗、抽屉与菜单

最终场景中展示实际父界面和遮罩，组件母版区只用于维护。居中弹窗随内容增高仍居中；抽屉与底部面板维持对应边缘定位。过长内容按既有规范限制可视高度并处理滚动，不让操作按钮消失在画面外。

蒙层使用准确的变量/透明度，避免重复叠加。菜单锚定触发控件，检查画面边缘、层级和裁切。关闭、取消、确认、跳过等行为按需求区分。

按钮尺寸与排布沿用项目：移动端可能等宽/撑满，桌面端可能按内容宽并靠右。不得强制所有单按钮占满或所有双按钮等宽。隐藏次按钮后重新分配空间，避免空位。

一种简洁弹窗结构是“根容器 → 内容区 + 按钮行 + 绝对定位关闭图标”；仅在需要不同布局时增加分组，不强制所有弹窗使用同一个结构。

## 图片比例、透明 PNG 与原生绘制

- 图片、logo 和 icon 保持原始宽高比与正确的几何形状。照片/配图按用途使用等比适应或等比裁切；不能非等比缩放来塞满容器。裁切后仍需保留必要主体，不能因过度裁切改变含义。
- icon 优先使用规范固定尺寸或等比缩放，保留路径比例与描边视觉粗细；容器 Fill 不代表图标本身也要被拉宽。调整画框宽度时检查嵌套实例的缩放约束，避免连带变形。
- 配图、照片、复杂插画和产品主体可使用透明背景 PNG 填充或作为独立图片层；保留 Alpha 通道，避免把透明底变成白底或附带原型背景。保留必要清晰度，不放大低分辨率图冒充高清。
- 文字、按钮、卡片、输入框、表格、布局容器、可绘制装饰和普通 UI 图标尽量用 Figma 原生文字、形状、矢量和组件表达，保持可编辑。SVG 导入后应为真实矢量；不可整块栅格化控件或把文字烘焙进配图。
- 验收时同时看实际图像主体与节点比例；方形头像框或裁切框不意味着允许内部图片被压扁。检查透明 PNG 的边缘、背景、主体和缩放后的视觉。

## 图标、图像与特殊轮廓

线性业务图标优先复用现有矢量；同组统一视觉粗细、端点、转角、尺寸和颜色。指定某枚作为基准时只调整需要修正的图标。

用户要求 SVG 时交付实际矢量路径，不将位图重命名为 SVG。照片、封面和插图等允许作为图像资产；整页截图不算原生设计稿。

异形卡片的特殊轮廓与内容布局分离，特殊顶部与边角保持稳定，中部随内容伸缩，底部跟随。描边形成连续外轮廓、不出现拼接线；不得整体拉伸造成圆角和凹口变形。随内容增长仍需优先可见的状态或切换入口放在稳定易读的位置，具体位置按业务决定。

## 设计依据验收

新设计应记录白名单内实际查看的具体 UI 案例、可核验的入选依据与借鉴点，不能只写平台名或用随机网站充数，并区分业务原型、正式 UI 和视觉参考。检查制作输入未把原型图当作样式依据；未完成研究且无明确免搜索授权时，不进入新视觉制作。视觉验收以适用的确认样张、正式规范和本轮设计方向为准，原型仅用于业务内容核对。仅对原型换色、加圆角和投影不能算完成独立 UI 设计。

## 关键验证

根据改动进行实际验证并还原测试内容：
1. 与来源或批准样张对照画框、栅格、字体、间距、控件尺寸、圆角与颜色。
2. 短文案换长文案，检查换行、增高、截断策略、按钮挤压和浮层定位。
3. 变化相关显隐/选中/展开状态，确认实例属性有效且显示一致；PC 控件额外切换 Default / Hover 检查视觉反馈与布局，移动端不做 Hover 必选验收。
4. 对同一画框实际执行 Resize 而非整体 Scale，分别检查目标范围内较窄、基准及较宽尺寸。主内容应随可用宽度延伸，等分列/卡片保持等宽，达到最大宽度后正确居中，内容不因内层固定尺寸僵硬靠左；同时逐个检查内容容器的上、下、左、右 Padding 与实际留白，以及换行、重排、溢出和图片/icon 不变形；非预期贴边须先修正再复验。记录测试尺寸和实际结果，然后还原测试内容与目标尺寸。
5. 检查组件引用、重复母版、冗余 Frame 和字体可用性，避免无意拆散实例或静默替换字体；确认重复 UI 已复用，必要状态可切换，透明配图之外的界面内容尽量保持原生可编辑。
6. 截图查看关键状态；尤其检查四周实际留白、多列对齐、页面边缘、滚动内容、遮挡和菜单裁切。确认非预期贴边已经消除，有意贴边的背景/图片等符合设计依据。
7. 删除测试节点，清理获准移除的辅助区域时修复其引用和跳转。

缺字体、工具失败或输出不完整时如实记录。写入重试前查询真实状态，防止重复创建。成功返回不足以证明成品正确；要有当前文件节点和可见截图作为交付证据。

# Figma 页面视觉精度与最终验收

开始实现、修复、还原走查及声称完成前完整读取。本文件是视觉属性、截图环境、像素阈值、节点覆盖和最终完成条件的唯一权威位置。

执行等级、代表签名与缓存失效见 [增量流程](efficient-workflow.md)；正式素材取证与准入见 [素材规则](asset-extraction.md)；交互与状态范围见 [交互规则](interaction-fidelity.md)。默认与严格模式均执行本文件全部质量门槛，严格模式额外证据按增量流程补齐。

## 排查顺序 L0–L5

| 层级 | 检查对象 | 主要证据 |
| --- | --- | --- |
| L0 资源与完整性 | 正式来源、实际实例、倍率、Alpha、漏项、伪造图形、原子边界 | 源清单、文件、准入报告、代码引用 |
| L1 视觉结构 | 内容呈现、排列、换行、层叠、真实 DOM 与覆盖 | 截图加节点/实现映射 |
| L2 几何 | 尺寸、坐标、间距、出血与裁切 | DOMRect、布局属性与间距账本 |
| L3 文字 | 逐字符与 text run、真实字体、字重、行高、字距 | Figma 原始值与实际 computed style |
| L4 颜色与效果 | 颜色、Alpha、渐变、描边、阴影、混合 | 原始属性、computed style 与截图 |
| L5 状态与最终细节 | 圆角、蒙版、交互状态、动效和最后修改后的证据 | 对应专题检查及最终证据包 |

先修会影响下层的资源、结构、环境或父级错误。资源检索中的 svg/path/clip-path 等命中只是线索，不能误伤 SVGR 编译产物、真实设计文字、既有组件或图表。资源遗漏以 Figma 源节点为分母，不能只查已经导出的文件。

图像与数值互不替代：截图用于定位结构与外观差异，实际属性和几何用于定量校验。CSS 写对但运行时不对仍失败；源码读取不能代替 computed style。合法不同写法按计算后的值及视觉结果比较，例如等效的单位行高不因源码形式不同被误判。

## 截图环境与定位

先根据设计侧真实根与模块确定视口、DPR、截图范围和布局原点；按 [工具接入](tool-access.md) 获取未被静默缩小的基准。区分布局盒和 render bounds，记录阴影/模糊/描边出血与偏移。

对齐主题、滚动位置、滚动条占位、字体加载、动态数据、交互状态与动画帧。静态验收固定动画的对应帧；reduced-motion 可用于对应静态场景，但不得代替正常动效的过程与时长验证。等待 document.fonts.ready，确保实际字体已加载。

差异定位可使用叠加图、坐标区域或辅助降采样预览；最终数值验收必须回到同物理尺寸的原始基准，不能用模糊、缩图、调整阈值或裁掉失败区域制造通过。差异区域定位到节点和网页元素后，修复值从设计属性读取，不能从截图反推。
## 模块坐标与文字

实施前记录一级模块 Node ID、绝对 `x/y`、宽高、上下顺序、模块间距，以及标题、正文、卡片、按钮和图片的边界。绝对定位元素使用所属模块坐标，不误用整页坐标。长页面逐模块读取和截图。

所有可见文字与 Figma 逐字符一致，包括大小写、空格、标点、强制换行、缺字、粘连和设计稿中的错误。没有用户授权时不润色文案。

每个 text run 独立核对：

- 字体家族、真实字重、字号、行高、字间距和基线。
- 文本框宽高、对齐、换行和总高度。
- RGB/HEX、Alpha、节点总 Opacity。
- 渐变类型、角度、全部色标、位置和透明度。
- 描边、阴影、模糊、混合模式和真实背景层级。

Heavy、ExtraBold、SemiBold 必须映射真实字体文件和明确 `font-weight`，禁止浏览器合成粗体。白色 `%`、渐变数字等不同片段必须独立样式，不能依赖 `<b>`、`<strong>` 或父级颜色继承。

## 布局、颜色与层级

逐项核对容器宽高、Padding、Gap、Grid/Flex 列起点、对齐、圆角、模块间距、负偏移、旋转外接矩形、`z-index`、蒙版、混合模式和覆盖关系。总宽度相同但列起点不同仍不通过。

颜色不能只核对近似 HEX，同时核对 Alpha、渐变方向和色标、描边、阴影、模糊、发光以及在真实背景上叠加后的结果。禁止把半透明设计色替换成肉眼相近的不透明颜色。

图标必须来自对应 Figma 节点、Export/Slice 或设计上下文资产；禁止 Emoji、Unicode、CSS 临摹或名称相近的替代图标。验证尺寸、外层容器、方向、镜像、间距和 Default/Hover/Pressed/Disabled/展开状态。

## 间距确定性测量

板块、文字、图片和控件之间的距离必须来自节点属性与坐标计算，禁止根据缩小截图目测，也禁止用一个统一 `margin-top`、`gap` 或累计手调偏移套用整页。

### Figma 测量基准

先区分两类边界：

- **布局边界**：节点的 `absoluteBoundingBox`、Auto Layout 尺寸和参与排版的 Frame 边界，用于计算间距。
- **视觉边界**：阴影、模糊、发光、描边和越界装饰形成的实际像素范围，用于检查遮挡和视觉重叠，不能代替布局间距。

同一坐标根下按以下公式计算：

```text
verticalGap   = next.y - (current.y + current.height)
horizontalGap = next.x - (current.x + current.width)
```

Auto Layout 节点必须同时读取并核对 `paddingTop/Right/Bottom/Left`、`itemSpacing`、主轴/交叉轴对齐、换行和尺寸模式。不能只看两个子节点的截图距离后猜一个 CSS `gap`。

### 内部间距账本

每个关键相邻关系记录：

```text
fromNodeId
toNodeId
axis: vertical | horizontal
coordinateRootNodeId
figmaFromBounds
figmaToBounds
figmaGap
cssSource: padding | gap | margin | grid-track | absolute-offset
browserFromRect
browserToRect
browserGap
delta
```

至少覆盖：标题到描述、描述到内容区、卡片内部行距、卡片之间、按钮与内容、一级板块之间、页头到首屏内容、末项到容器底部。

### CSS 实现约束

- 明确每一段距离由 Padding、Gap、Margin、Grid Track 还是绝对定位负责，禁止同一间距被父级 Gap 与子级 Margin 重复计算。
- 标题、段落、列表和按钮默认 Margin 必须显式重置；不能依赖浏览器默认值。
- 注意垂直 Margin Collapse。需要稳定边界时优先使用父级 Padding、Flex/Grid Gap 或建立新的格式化上下文。
- `transform` 改变视觉位置但不改变普通文档流占位；Figma 使用旋转或缩放时，布局间距和变换后视觉间距必须分别验收。
- 一级板块间距逐对设置和测量，禁止全局 `section + section { margin-top: ... }`，除非已证明所有板块的 Figma 间距完全一致。
- 所有绝对定位值必须相对正确的模块根节点，禁止把整页坐标直接写进局部容器或通过多级补偿偏移凑位置。

### 浏览器复核

在设计稿目标视口和缩放比例下等待 `document.fonts.ready`，再读取对应元素的 `getBoundingClientRect()`。使用与 Figma 相同的节点配对和坐标根计算浏览器间距，写回内部账本。

字体未加载、文字换行不一致、容器高度错误或变换矩阵不同都会让间距测量失真，必须先修正根因，禁止直接对下游板块继续增加补偿 Margin。关键间距 `delta` 必须不超过 1px；截图叠加仍出现明显视觉重叠时，即使布局 Gap 合格也需要检查视觉边界。

## 裁切语义与网页可见边界

文件自身完整和放进网页后完整可见是两个独立门槛。沿可能越界的节点向上检查全部祖先：

- Figma Frame/Group 的宽高、`clipsContent`、蒙版和圆角裁切。
- 网页祖先的 `overflow`、`clip-path`、`mask`、固定高度和滚动区域。
- 图片原始边界、非透明像素边界及旋转、缩放后的最终外接矩形。
- 元素是否按设计意图越过按钮、卡片、模块或一级 Section 继续显示。

禁止给全部 Section、卡片或组件统一添加 `overflow: hidden`。局部按钮需要裁切，不代表包含按钮与装饰图的外层也需要裁切。设计允许越界时使用正确层级的 `overflow: visible` 或独立装饰层；禁止随意增大模块高度掩盖裁切错误。

透明图片原始有效边界正常但网页截图边界变小，仍直接判定为失败。修复后复核相邻模块遮挡、空白、重叠和点击区域。

## 图片 Fill、裁切和负偏移

核对原图尺寸、显示尺寸、宽高比、`FILL/FIT/CROP/TILE`、裁切容器内的 `x/y` 偏移、缩放、圆角和蒙版。不能把“较大图片负偏移后裁进容器”简化成直接拉伸到容器宽度。

正式素材的格式、倍率和 Alpha 以素材规则的准入记录为依据，页面显示不能覆盖素材失败。

## 同尺寸截图和计算样式验收

- Figma 与网页使用相同画板宽度和对应模块高度。
- 超长页面逐模块截图，避免整页拼接产生重复条带或错位。
- 每次修正后生成新截图，不用旧图证明新结果。
- 对比布局边界、文字换行、颜色、透明度、图标方向、图片裁切和模块间距。
- 对完整画板和每个一级模块分别计算数值化像素差；不得只生成对比图、只检查整页平均值或只挑选看起来正确的区域。
- 检查浏览器计算样式；CSS 源码正确但最终视觉受继承、透明度、混合模式、字体加载或覆盖层影响，仍不通过。
- 等待字体加载后，用与 Figma 相同的节点配对逐项复算间距账本；不能只验证模块总高度或整页底部位置。
- 交互模块按内部交互清单验证每一种唯一状态转换，并分别核对默认态和全部可达视觉状态。
- 检查页面身份、非空渲染、框架错误遮罩、控制台错误和资源加载。

内部维护 `Figma 证据 → 网页证据 → 修正值 → 复核结果`，不写入正式项目。

## 数值化像素差硬门槛

比较前必须确认 Figma 与网页截图的物理像素宽高完全一致，并锁定相同的视口、设备像素比、缩放、滚动位置、字体加载状态、交互状态和动画帧。宽高不同、页面仍在动画、字体未完成加载或截图不是最后一次修改后的新结果时，比较直接失败。

完整画板和每个一级模块至少记录以下指标：

```text
width / height
changedPixelRatioAt16: 任一 RGBA 通道绝对差 > 16 的像素比例
meanAbsoluteError: RGBA 每通道平均绝对差，范围 0..255
p95AbsoluteError: RGBA 绝对差的第 95 百分位
diffImage: 任务临时目录中的差异图
status: passed | failed | unverified
```

默认阈值在第一次比较前固定为：

- 完整画板及普通模块：`changedPixelRatioAt16 <= 1%`、`meanAbsoluteError <= 2.5`、`p95AbsoluteError <= 12`。
- 图标、描边、卡片边缘、蒙版和其他关键非文字区域：`changedPixelRatioAt16 <= 0.25%`、`meanAbsoluteError <= 1`；同时继续执行 1px DOMRect、颜色和效果属性检查。
- 任一模块超过阈值即失败；整页平均值不能覆盖局部失败。

只有字体栅格化平台差异可以使用文字抗锯齿蒙版。蒙版只能覆盖已证明文字内容、字体、字重、字号、行高、字间距、文本框和基线均一致后的 1px 字形轮廓，并必须记录蒙版 Node ID、像素面积和蒙版前后指标。禁止蒙掉整个文本框、阴影、图标、边框、图片或失败模块。动态内容也只能按设计明确的动态节点做同样的 Node ID 级蒙版；禁止通过裁剪截图或事后扩大蒙版让结果通过。

阈值不能在看到结果后放宽。环境差异先修正环境或使用本节限定的抗锯齿处理；不得自行降低既定门槛。用户明确要求修改验收标准时单独记录标准变更，不能将已失败的旧证据改标为通过。无法使用可重复的像素比较能力时标记 `unverified`，禁止声称 1:1。

## Figma 可见节点覆盖率硬门槛

覆盖账本必须从 `implementationRoot` 的 Figma 节点全集向网页映射，不能从现有 DOM 或素材目录反向生成。先枚举所有可见、非零且具有独立视觉或布局语义的节点，包括：Text、Image Fill、独立填充/渐变/描边/效果、图标、蒙版、Slice/Export、可见布局容器和交互状态。

每条覆盖记录至少包含：

```text
figmaNodeId / name / type / absoluteBoundingBox
visualProperties: text | fill | stroke | effect | image | mask | layout | interaction
implementationType: dom | css | asset | covered-by-atomic | structural-only
implementationRef: DOM locator、组件位置或正式素材路径
atomicAncestorId
computedStyleChecks / geometryChecks / assetChecks
status: passed | failed | unmapped
reason
```

- `production-atomic` Export 的后代登记为 `covered-by-atomic`，不得重新映射为 DOM/CSS。
- 没有自身视觉属性的 Group/Frame 可以登记为 `structural-only`，但它的布局、裁切和后代边界仍需验证。
- 隐藏和零尺寸节点不进入覆盖率分母，但必须记录排除数量，防止把读取失败误当隐藏。
- 一个网页节点同时替代多个视觉内容时必须逐个保留 Figma Node ID；来源冲突、近似替代和错误复用均记为失败。

完成条件固定为：`covered / eligible = 100%`、`unmapped = 0`、`failed = 0`。即使截图指标通过，只要漏掉一个可见文字、描边、图标、效果或布局节点，也不能声称完成。

## 验收证据包与时效

验收证据只保存在任务临时目录，不写入项目或提交。证据摘要至少包括：

```text
fileKey / linkRootId / implementationRootId / exportIntent
capturedAt / lastRelevantUiChangeAt / buildRevisionOrSourceHash
Figma 与网页截图的路径、尺寸、哈希、视口、DPR、字体状态
整页与逐模块像素差指标、阈值、蒙版记录和失败项
可见节点 eligible / covered / unmapped / failed / excluded 统计
计算样式总检查数与失败数
间距账本条目数、最大 delta 与失败数
clipsContent/overflow、透明素材和资源加载检查
页面身份、控制台、交互清单总数/通过数/失败数/未验证数和构建结果
overallStatus: passed | failed | unverified
```

最后一次相关代码、样式、素材、字体或构建输出发生变化后，旧的网页截图、计算样式、DOMRect、覆盖映射、间距和像素差全部失效；必须重新采集受影响模块，根容器或全局样式变化时重新采集整页。Figma 源节点发生变化时，对应 Figma 截图和节点属性同样失效。

最终答复无需展示完整内部账本，但必须报告截图尺寸、整页及失败模块的数值化像素差、覆盖数量与覆盖率、计算样式失败数、间距最大误差、证据采集时间以及总体状态。证据缺失、过期或 `overallStatus != passed` 时，只能报告未验证或失败，禁止使用“1:1”“精准还原完成”等表述。

## 桌面视口分级验收

对于 1920px 桌面设计稿，常规验收矩阵固定为 1920px、1440px 和 2560px，不包含 3440px 或其他超宽屏。显示器物理分辨率和浏览器 CSS 视口不是同一概念，系统高清缩放通常会把高分辨率屏幕映射到较小的 CSS 宽度，因此不得按每一种物理屏幕尺寸重复制作或逐像素验收 UI 稿。

- **1920px**：Figma 精确基准。每次 UI 修改后都必须在受影响模块执行同尺寸截图、计算样式和间距复核。
- **1440px**：常见较窄桌面兼容检查。验证页面缩放或响应式布局后没有横向滚动、裁切、文字不可读、点击区域错位和高度计算错误。
- **2560px**：大屏安全检查。验证全宽背景连续延展、1920px 核心内容画布居中且不被放大、Header/Footer 铺满策略稳定、横向列表和装饰没有断层或异常裁切。

1440px 和 2560px 只在以下情况自动复验：页面首次实现；修改页面根容器、一级 Section、Header、Footer、全宽背景、横向列表、`overflow`、缩放规则或媒体查询。只修改局部文字、颜色、图标或单个素材时，不要求重复全部视口，只复验 1920px 的受影响模块。

大屏实现优先采用“背景层铺满视口、核心内容层保持 1920px 并居中”的结构。禁止把整个 1920px 页面等比放大到 2560px，也禁止用固定 2560px 宽度配合负 `left` 偏移模拟全宽页头。纯色、渐变和可平铺背景允许自然延展；前景文字、按钮、卡片、透明装饰和非背景切图保持设计尺寸。需要覆盖大屏的照片背景必须核对 `cover` 裁切焦点或使用足够分辨率的正式素材。

3440px/超宽屏不属于默认支持和完成门槛；页面在该宽度下没有专门适配是允许的。只有用户明确要求超宽屏支持时，才增加对应设计与验收。

## 完成门槛

- 可见文字和强制换行逐字符一致。
- 关键边界、列起点和模块间距误差不超过 1px。
- 关键相邻节点和所有一级板块之间均有间距账本，浏览器实测误差不超过 1px，且不存在累计补偿偏移。
- 字体、字重、字号、行高、颜色、渐变和透明度与 Figma 一致。

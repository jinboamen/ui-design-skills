# 最终背景与轻量前景样张

本文件是活动页默认流程：A／B／C各制作最终规格的真实背景，搭配轻量前景示意形成三套完整组合样张；用户选中后只精细制作这一套前景。背景直接复用，不能从样张去除控件后重新生成背景。本流程替代三套完整工作素材流程；不制作三套透明组件、全部状态、独立装饰或完整素材包供用户选择。

## 制作顺序

1. 收齐本次配置和用户手动确认的标题；活动规则默认浮动、平铺默认关闭，用户主动启用时才按[规则模块布局](v1-layout.md#活动规则模块与浮动入口)将规则背景、统一标题及可编辑正文纳入样张和最终交付；先搜索、实际查看并在当前聊天展示参考链接、图片及具体借鉴点，再生成任何背景或示意素材。参考查询与数量统一按[按设计缺口组织搜索](planning-and-references.md#按设计缺口组织搜索)，不按各类素材重复追加配额；搜索来源、默认盲盒、礼包选择、V1尺寸及逐项配置规则保持原要求。
2. 按[同一KV下的三套设计区别](design-quality.md#同一kv下的三套设计区别)为A／B／C确定同一画风内各自的背景与组件做法，不以同一母版换色或微调细节作为三套方案，先在最终V1坐标定位标题、卡片、主体、按钮和文字的可见范围，使用轻量前景示意辅助构图；已有合格前景直接复用。由执行者依据本次KV与实际查看的参考，自动确定各模块的主形状、色面面积、纹理密度分布、虚实及承托关系，按[背景自动设计与返修](design-quality.md#背景自动设计与返修)落实到背景输入。用户仅沿既有流程提供业务配置与选择完整方案，不承担设计判断，也不增加单模块测试审批。
3. 制作本套真实背景，并持续叠回同一比例的轻量前景检查；盲盒有实体承托时，先按[透视和落点](design-quality.md#盲盒与承托面的透视和落点)用本套实际盒体示意固定视角与盒底，再制作可承载它的台面，不独立猜测两层透视；背景可以先起稿，但不能在空背景状态锁死。背景质量、主体突出程度或衔接不成立时，自动返修对应背景区域，保持合格前景不变。按[内容区背景的亮面与视觉主次](design-quality.md#内容区背景的亮面与视觉主次)检查实际前景后方的亮墙、雾光、反射和高对比纹理，不把空背景的清晰或漂亮当作主次通过；每套背景均按最终显示像素制作；可以带相邻上下文分段制作并形成共同坐标母图，母图用于统筹与原像素导出，不要求一次生成低分辨率整页再逐模块高清重绘。两种模式均先通过[首屏与首模块联合验收](v1-layout.md#首屏与首模块先联合验收)再扩展后续背景，展示前完成整页母图、全部交界与原像素切片。按模块区分依[分块模式的上下分区](art-direction.md#分块模式的上下分区)同时检查底色层次、模块构图节奏与画风一致；保留每对相邻区的大面积底色／明度差异，避免同一包围构图重复或为了区别而换成无关场景，分割线按设计选用且唯一归属。套餐背景按[套餐背景规则](design-quality.md#套餐背景以信息阅读为中心)以周边元素和留白衬托信息，默认不生成卡片专属台子或包裹舞台；盲盒承托规则不套到套餐。背景保持独立层，不烘焙业务前景。轻量示意表达实际造型、表面、字形和信息组织，可用少量示意图，不提前制作三套完整透明组件、状态或装饰，不以普通线框或默认灰框冒充设计。
4. 展示前按[丰富背景下的前景力度](design-quality.md#丰富背景下的前景力度)检查主要轮廓、层次和内容焦点，奖品卡同时按[实际显示比例](v1-layout.md#奖品卡与实图的实际显示比例)测量，不把轻量示意做成偏小的普通框或留待选中后再决定设计；再按三套设计区别规则，用实际样张及对应组件局部并排核对设计形式，重复的方案先调整；不强求三种风格或额外制作完整前景。对真实背景执行原尺寸局部、恢复前景的完整模块与整页、全部交界的自动视觉检查，任务条还须按[正文高度与上下留白](v1-layout.md#任务条正文高度与上下留白)检查名称1行＋说明2行的三行容量及真实内区净空，同时兼查短文案，不以画布高度或未遮挡判通过；同时按[奖品实际显示比例](v1-layout.md#奖品卡与实图的实际显示比例)和[异形文字安全区](v1-layout.md#异形底图的文字安全区)叠回文案检查，修复后才用当前背景文件和前景示意在1920px、DPR1浏览器拼出A／B／C三张完整样张。前景示意的生图调用只负责示意层；如果输出夹带背景，只提取其前景并叠回实际背景，不用AI顺带修改的背景代替本套文件。展示前有意返修背景时更新实际背景、母图、切片和真实预览，不仅修改展示截图。明确说明“背景为实际交付版本，前景为待精细制作的设计示意”，只展示三套完整组合及大图链接，不额外让用户逐件或逐模块选择。
5. 等待用户明确选择具体样张版本。冻结该样张、背景与示意清单及实际文件哈希。未选前只做背景、轻量示意及必要布局检查，禁止提前批量制作三套正式前景。整轮否定先重新找参考再重做；局部改稿只改指定方案并重新展示，沿原确认流程。
6. 只为选中方案精细制作一套前景和所需状态、透明边缘与独立装饰。多套餐按[复用规则](v1-layout.md#多套餐复用同一套素材)仅制作一张卡片底图和一张购买按钮底图供所有实例引用，不按套餐数量扩展生图或复制文件；各对象实际附上选定样张、对应前景局部和背景，继承造型、表面、字形、比例及位置，不能仅依据KV自由重抽。组件尺寸、alpha、完整标题及所有既有角色要求在正式阶段落实；用户已明确保留的对象沿用原素材。
7. 正式盲盒先核对是否继承所选示意的视角和落点，偏离先修复；冻结实际盲盒PNG后，按[透视和落点](design-quality.md#盲盒与承托面的透视和落点)先校准背景承托面视角、深度及真实盒底接触，再校准底框包裹、居中、接触阴影及反射；底框继续归blind.background，不单独导出。允许必要局部背景修补，保留原图快照、实际盒体输入和修补范围。禁止重生成整页背景、改变主题、材质、气氛、分区或无关区域。底框与示意盒体的关系先设计，实际盒体出来后再验收，不能借背景已选而放弃融合。
8. 用这套正式工作素材恢复完整1920px页面，逐项对照选中示意，检查造型、比例、文字、气氛、接缝及盲盒融合。普通精度修复按已选设计执行，不另加一次强制审批；需要实质改变已确认背景、造型、布局或用户指定对象时展示一张改稿，沿原规则确认。最终完整预览仍必须展示，不把示意截图当成品截图。
9. 按[PNG分辨率与PS置入尺寸](v1-layout.md#png分辨率与ps置入尺寸)在各素材及背景冻结前统一目标PPI，保持像素和alpha；实际盒体hash与最终工作集hash均在规范化后记录。通过验收后冻结这一个最终工作集，直接复制它的背景、组件和装饰，整理清单及页面路径，交付唯一正式素材文件夹；不得在整理交付时再生图。背景无需从完整样张擦除前景，样张背景自始就是独立实际文件。

用户要求组合不同方案时，先建立一个明确的背景＋前景示意组合并确认，再只生产该组合的一套正式前景；未经展示的混用不能直接交付。背景局部修补不授权整页重做，实际素材制作仍按当前imagegen工具规则执行。

## 冻结与证据

assets.json与design/design-evidence.json均记录production_workflow: background-final-foreground-concept-v1。design_selection继续记录三套proposals、selected_id、round、status和实际用户回复；每项proposal记录id、file、design_summary、background_set，不再要求三套working_set。

background_set指向本套背景＋示意清单；清单内file及所有下述路径相对于页面目录。示例仅展示结构，assets须列全所有启用背景，concept_images可用少量图表达全部前景，不要求拆成完整素材：
```json
{
  "page_width": 1920,
  "page_height": 2557,
  "background_master": {"file": "design/backgrounds/r1/B/master.png", "sha256": "实际SHA256"},
  "assets": [
    {"role": "hero", "file": "design/backgrounds/r1/B/hero.png", "sha256": "实际SHA256"},
    {"role": "blind.background", "file": "design/backgrounds/r1/B/blind.png", "sha256": "实际SHA256"}
  ],
  "concept_images": [
    {"file": "design/concepts/r1/B/foreground.png", "sha256": "实际SHA256"}
  ]
}
```
背景清单只列hero、banner及*.background角色。page_height按实际模块累计计算，不能把示例高度或不完整背景列表直接当记录。批准approval保留user_reply、sample_sha256，并记录background_set_sha256，冻结当时实际清单与文件。

只有选中方案有完整生产工作集。在证据文件增加selected_working_set：
```json
{
  "selected_id": "B",
  "file": "design/worksets/final/B/manifest.json",
  "preview": "design/qa/final-page.png",
  "manifest_sha256": "最终验收后实际清单SHA256"
}
```
其manifest保留page_width、page_height、background_master、assets和decorations结构；所有项记录实际file与sha256，assets列全正式角色，decorations未启用填[]。未展示的备用状态／可选装饰用used_in_preview:false，其他默认为true。最终工作集哈希是内部验收冻结，不伪称用户对尚未展示素材的新批准，也不新增必需确认步骤。

最终assets每项、background_master与装饰各项增加working_source，指向这个选中方案最终工作集的对应源文件；正式文件与工作源字节哈希一致。装饰file沿旧约定相对于装饰清单，working_source仍相对于页面目录。工作来源快照保留在design，正式素材包仍只有一份。

背景继承另在证据文件记录background_inheritance对象：source为选定原背景母图，result为最终工作母图，comparison为实际同尺度对照图，status为pass，observation说明保留的设计及实际观察；local_changes为具体局部修补说明数组，未修改填[]。背景变化须有来源链及对照，不能仅写“融合通过”。

来源方向：KV／参考 → 实际背景和前景示意 → 浏览器候选样张；选定样张／对应示意＋所选背景 → 一套正式前景；所选背景＋实际盲盒 → 必要局部修补后的背景 → 正式背景切片；最终工作文件 → 最终浏览器截图与交付复制。候选与最终预览都记录kind:derived、renderer:browser及实际直接input_images；前景正式制作允许引用选中示意或其完整候选截图，不能引用未选方案，也不能形成未来截图引用循环。

review.composition使用selected_working_set.preview的真实成品截图；review.comparison保留选中示意与成品的实际对照。七项视觉记录、逐缝截图、盲盒art_sha256与contact／support／lighting验收继续适用。示意用于选设计，不能充当正式尺寸、alpha、状态或融合通过的证据。

## 验收边界

校验器检查三套背景＋轻量示意的实际输入、用户选择与冻结、一套最终工作素材、背景继承记录及交付文件复用；历史shared-assets-preview-v1仅保留旧包兼容，不作为默认新制作流程。脚本不能自动证明截图真实、未选方案确实没有被提前生成、修补仅限局部或前景还原得好：仍须检查实际调用和图像，不把字段齐全或哈希通过当成视觉通过。仅维护Skill时不生图、不制作活动素材。

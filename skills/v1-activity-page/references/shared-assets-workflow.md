# 最终背景与轻量前景样张

本文件是活动页默认流程：先按[内容优先的背景构图](art-direction.md#内容优先的背景构图)组织实际内容与轻量前景，再围绕该组合制作A／B／C各自最终规格的真实背景，形成三套完整样张；用户选中后只精细制作这一套前景。背景直接复用，不能从样张去除控件后重新生成背景。本流程替代三套完整工作素材流程；不制作三套透明组件、全部状态、独立装饰或完整素材包供用户选择。

## 样张阶段的工作边界

以下边界统一适用于A／B／C候选；其他章节的质量要求并入同一次检查，不为每条规则另起制作、截图或返修流程。保留三套最终规格背景、真实浏览器合成与用户手动选择，不退回低清整页概念图后重画背景。

- **排版骨架只建立一次。** 复用本轮模块高度、标题位置、文本数据、套餐与奖品排列、任务行及按钮坐标，以同一页面模板的数据切换渲染三套。各套背景、前景造型与材质仍独立设计；轮廓或内容层级不同时，仅覆盖对应内边距、文字安全区及局部排版，不强制三套信息组织相同，也不重新搭建三个页面。共用代码不等于共用控件皮肤。素材组合图用于预览时按实际图像宽高及每件可见范围定位，裁切容器与单件区域一致，不用整个标题槽位代替单件裁切而漏出邻件；回填后检查完整标题、相邻图形串入及按钮文字对比。复用骨架或旧脚本前重新核对这些映射，不把历史图集尺寸写死为本次尺寸。
- **按组件设计选择前景制作方式。** 已有合格素材可直接复用。能在各件目标宽高比与可见层次下完整表达时合图制作，比例悬殊或合图压掉造型和层次时，单独制作该件示意。按实际显示比例预留组件间距，采用可直接叠放的透明组合或按区域裁取／定位示意，只做合成必需的处理。组件从组合图裁出后按自身比例置入既定画布。宽高不合时重做对应素材或按原设计重建，避免拉伸轮廓或压扁局部造型。不逐件反复抠图、修alpha边缘、归一化正式导出尺寸或拆出每个标题／按钮文件，不制作全部状态及独立装饰。示意保留主要轮廓、材质、视觉重量、字级与安全区。模板程序负责固定排版、裁取及回填文字。程序也可实现有依据的组件设计，须保留该方案的造型和视觉层次，不能拿共用渐变按钮、默认框或普通字体加描边当作已经设计的前景。背景始终来自本套真实背景文件，不能用生成的整页合图冒充合成样张。
- **业务文字与复用项一次排好。** 真实内容或授权占位继续用可编辑HTML回填；同套多套餐只引用一套卡片与按钮示意，同类奖品和任务按既有复用规则实例化。组合示意不烘焙业务文案，不逐个奖品或套餐重新生图。标题在示意图中须完整可读且沿用统一母版，独立正式标题PNG在选定后制作。
- **盲盒形体与衬托先检查再展示。** 先按[箱体比例与结构](art-direction.md#盲盒箱体比例与结构)检查实际盒体的长宽深、盒盖与盒身接合、各面透视及等比显示，不能把长扁、歪盖或扭曲当设计差异。 每套按[必选设计与样张检查](design-quality.md#盲盒衬托的必选设计与样张检查)用实际盒体示意与真实背景成组设计，检查可见衬托、盒体轮廓与衬托颜色分离、对应位置／尺度及空间或图形关系；同色融底也须修复。对位以实际叠加及对应类型的可见锚点为准，不凭容器同中心或计划坐标通过；普通纹理和单独阴影不替代。共用骨架不意味着不同造型共用未经核对的锚点。检查并入下述同批预览，不增加完整报告或额外修正轮数；缺失或错位未解决的候选不能标为可选。
- **检查集中，返修按整套计数。** 每套首版完整合成后，一次查看整页、必要的正常尺寸局部、所有交界与文字区；A／B／C并排区别检查使用这批已有图像。先汇总具体问题，再做一轮集中修正；只改有问题的区域，未改区域不重复生成或验收。修正后若还有遮字、断缝、盲盒衬托缺失／错位、比例／透视错误、主题转化未完成、背景或组件退化成通用占位、明显偏离KV或三套设计实质重复等关键问题，最多再做一轮定点修复，随后只复核变更处及其相邻关系。不因细微纹理、高光或装饰偏好反复出图；每套本轮总计最多两轮修正，不能按模块、组件、问题或检查章节分别重置次数。仍有关键问题时停止该套重抽，保留较好版本并如实报告未达标项，不能伪称三套均合格，不新增用户美术审批。工具失败按工具自身规则处理，不借重试启动新的设计轮次；用户后续明确改稿另按其范围执行。

| 工作 | 样张阶段 | 选定后的正式阶段 |
| --- | --- | --- |
| 背景 | 最终规格、必要跨界修复、母图与原像素切片，实际文件进入样张 | 直接复用，只做必要的局部融合修复 |
| 前景 | 少量组合示意、实际比例与信息层级、常态设计及必要高亮示意 | 一套独立PNG、全部所需状态、透明边缘、正式尺寸与PPI、独立装饰 |
| 预览与检查 | 共用骨架渲染三套，集中检查正常尺寸效果、全部接缝及盲盒衬托存在／成组对位；必要局部来自已有预览 | 最终回填、逐缝证据、盲盒最终素材绑定、七项视觉记录及完整交付校验 |
| 来源与记录 | 参考、生成输入及输出路径随调用记一次；实际背景／示意清单、候选截图、简短问题与修正记录 | 补齐选中方案最终素材清单、来源继承、对照与交付记录 |

样张不运行完整validate_output.py，也不为了让它通过而提前制作正式资产或伪造用户批准／最终验收。原像素切片仍由export_background_slices.py及其所需的最小背景清单完成；候选清单不得伪装成完整交付清单。所有接缝仍实际查看，样张阶段用同批浏览器截图查看／放大，不为每条接缝重复整理最终seam_reviews；选中后按正式规格保存。三套背景与示意来源、候选快照及选择时哈希仍保留，以便直接复用和追溯；记录一次即可，不在多个文档重复写观察报告。

在现有design/analysis.md简记搜索、生图、组装、检查／返修各阶段实际耗时，以及各套生图／编辑调用数和修正轮数；利用调用起止时间记录，等待用户回复单列，不计为处理耗时，无法测得就标未知。异步阶段重叠时分别说明墙钟耗时，不把重叠时间相加后声称总耗时。只用于定位瓶颈，不新增报表、脚本、审批或持续计时轮询，不承诺未经实测的提速比例。

## 制作顺序

1. 收齐本次配置和用户手动确认的标题；活动规则默认浮动、平铺默认关闭，用户主动启用时才按[规则模块布局](v1-layout.md#活动规则模块与浮动入口)将规则背景、统一标题及可编辑正文纳入样张和最终交付；先搜索、实际查看并在当前聊天展示参考链接、图片及具体借鉴点，再生成任何背景或示意素材。参考查询与数量统一按[按设计缺口组织搜索](planning-and-references.md#按设计缺口组织搜索)，并按[参考覆盖实际设计缺口](planning-and-references.md#参考覆盖实际设计缺口)确认背景组织已取得可用依据，不能用仅支持控件和间距的参考覆盖背景制作；不按各类素材重复追加配额；搜索来源、默认盲盒、礼包选择、V1尺寸及逐项配置规则保持原要求。
2. 先按[KV到内容区的设计转化](art-direction.md#kv到内容区的设计转化)在现有方向简报明确主题依据、实际落点、背景与组件的具体做法，并写入各次生图输入；设计判断由执行者完成，不增加用户美术配置。按[同一KV下的三套设计区别](design-quality.md#同一kv下的三套设计区别)为A／B／C各自确定同一画风内不同的背景主构图及前景做法。用同一V1排版骨架定位内容。首版生图前并排看每套背景草图的大形、方向和承托区，逐对确认构图区别，再由彩色草图确定章节色面。按模块区分时，首版生成前先用实际比例的底色草图确认两种主底色深浅交替、相邻可辨与隔段主底色一致。各模块先各自安排背景主要形状和元素，生成时附该模块的构图及共用色样。同步确定各类前景的主要填充、文字区、边缘和高光用途。按现有[生图提示词要求](art-direction.md#生图提示词与验收)把这些决定带入首轮生成，再用少量实际设计好的前景组合图像建立内容重心并完成背景；已有合格前景直接复用。每套首版浏览器样张均回填单独完成的[模块艺术字PNG](art-direction.md#统一模块标题素材)，以及各启用的卡片、任务条和按钮示意图像。HTML/CSS按模板排入业务文字与位置。此处确定内容组合。按模块区分时，在此基础上先完成[本套长页构图草图](art-direction.md#分块模式的上下分区)。草图沿用现有排版和分析。由执行者依据本次KV与实际查看的参考，自动确定各模块的主形状、色面面积、纹理密度分布、虚实及承托关系，按[背景自动设计与返修](design-quality.md#背景自动设计与返修)落实到背景输入。用户仅沿既有流程提供业务配置与选择完整方案，不承担设计判断，也不增加单模块测试审批。
3. 依据上一步已确定的内容组合制作本套真实背景，并持续叠回同一比例的轻量前景检查；盲盒有实体承托时，先按[透视和落点](design-quality.md#盲盒与承托面的透视和落点)用本套实际盒体示意固定视角与盒底，再制作可承载它的台面，不独立猜测两层透视；背景起稿须已有上述内容组合依据，不能从独立空景开始决定整页构图，也不能在空背景状态锁死。背景质量、主体突出程度或衔接不成立时，记录问题并纳入本套集中修正，保持合格前景不变；首屏交界等阻断后续构图的问题可先局部修复，该修复同样计入本套轮数。按[内容区背景的亮面与视觉主次](design-quality.md#内容区背景的亮面与视觉主次)检查实际前景后方的亮墙、雾光、反射和高对比纹理，不把空背景的清晰或漂亮当作主次通过；每套背景均按最终显示像素制作；可以带相邻上下文分段制作并形成共同坐标母图，母图用于统筹与原像素导出，不要求一次生成低分辨率整页再逐模块高清重绘。两种模式均先通过[首屏与首模块联合验收](v1-layout.md#首屏与首模块先联合验收)，并按[自动看图、定位和返修](design-quality.md#自动看图定位和返修)检查该组合的实际设计是否成立，再扩展本套后续背景；技术修复不得替代构图验收，未认可的失败构图不锁死保留，展示前完成整页母图、全部交界与原像素切片。按模块区分沿用本套长页构图草图，分段制作须同时附上草图和相邻区已有的实际画面。按[分块模式的上下分区](art-direction.md#分块模式的上下分区)在隐藏前景的整页缩览同时检查章节分色与同一活动的视觉联系，恢复前景后再检查内容主次。套餐背景按[套餐背景规则](design-quality.md#套餐背景以信息阅读为中心)以周边元素和留白衬托信息，默认不生成卡片专属台子或包裹舞台；盲盒承托规则不套到套餐。背景保持独立层，不烘焙业务前景。轻量示意表达实际造型、表面、字形和信息组织，可用少量示意图，不提前制作三套完整透明组件、状态或装饰，不以普通线框或默认灰框冒充设计。
4. 展示前在本批真实截图执行[样张展示前的设计判断](design-quality.md#样张展示前的设计判断)，将制作正确性与设计成立分开，主题转化或组合设计未完成不能作为可选方案。具体检查先按[背景设计完成度与图形尺度](design-quality.md#背景设计完成度与图形尺度)检查主题依据、形状与实际前景的尺度、疏密层次及三套组织差别；分色或中央有底板不等于完成，通用大形状堆叠、无组织大片留空等问题纳入本套现有集中修正，不增加检查轮数。再按[丰富背景下的前景力度](design-quality.md#丰富背景下的前景力度)检查主要轮廓、层次和内容焦点，奖品卡同时按[实际显示比例](v1-layout.md#奖品卡与实图的实际显示比例)测量，不把轻量示意做成偏小的普通框或留待选中后再决定设计；再按三套设计区别规则，用实际样张及对应组件局部并排核对设计形式，重复的方案先调整；不强求三种风格或额外制作完整前景。在上节同一批检查中覆盖真实背景原尺寸局部、恢复前景的完整模块与整页、全部交界，不逐规则另起截图和修复循环，任务条还须按[正文高度与上下留白](v1-layout.md#任务条正文高度与上下留白)检查名称1行＋说明2行的三行容量及真实内区净空，同时兼查短文案，不以画布高度或未遮挡判通过；同时按[奖品实际显示比例](v1-layout.md#奖品卡与实图的实际显示比例)和[异形文字安全区](v1-layout.md#异形底图的文字安全区)叠回文案检查，修复后才用当前背景文件和前景示意在1920px、DPR1浏览器拼出A／B／C三张完整样张。前景示意的生图调用只负责示意层；如果输出夹带背景，只提取其前景并叠回实际背景，不用AI顺带修改的背景代替本套文件。展示前有意返修背景时更新实际背景、母图、切片和真实预览，不仅修改展示截图。明确说明“背景为实际交付版本，前景为待精细制作的设计示意”，只展示三套完整组合及大图链接，不额外让用户逐件或逐模块选择。
5. 等待用户明确选择具体样张版本。冻结该样张、背景与示意清单及实际文件哈希。未选前只做背景、轻量示意及必要布局检查，禁止提前批量制作三套正式前景。整轮否定先重新找参考再重做；局部改稿只改指定方案并重新展示，沿原确认流程。
6. 正式制作以[正式素材的完成标准](design-quality.md#正式素材的完成标准)判断单件、实际回填与整套质量，不以比草稿略好代替成品完成度。只为选中方案按[选定后的前景精修](design-quality.md#选定后的前景精修)明确实际缺口，沿所选布局、主要造型与风格补足可见二级结构、材质及局部装饰；每类先精修一个代表母版，以V1实际同尺寸对照样张，提升明确且净区、整页关系通过后再复用到同类并补齐所需状态、透明边缘与独立装饰。描边、高光、锐化、放大或去字不单独算精修，文字及本次确有的扫码区域保持干净；按[所有素材的有效画布](design-quality.md#所有素材的有效画布)核对可见主体与内容承托，不将放大示意件当完成。多套餐按[复用规则](v1-layout.md#多套餐复用同一套素材)仅制作一张卡片底图和一张购买按钮底图供所有实例引用，不按套餐数量扩展生图或复制文件；各对象实际附上选定样张、对应前景局部和背景，继承造型、表面、字形、比例及位置，不能仅依据KV自由重抽。组件尺寸、alpha、完整标题及所有既有角色要求在正式阶段落实；用户已明确保留的对象沿用原素材。
7. 正式盲盒先核对是否继承所选示意的视角和落点，偏离先修复；冻结实际盲盒PNG后，实体承托按[透视和落点](design-quality.md#盲盒与承托面的透视和落点)先校准背景承托面视角、深度及真实盒底接触，平面图形衬托按确认样张保留构图和遮挡关系，再按[V1底板类型](v1-layout.md#底板包裹与居中验收)校准对应包裹／构图、接触阴影及反射；底框继续归blind.background，不单独导出。允许必要局部背景修补，保留原图快照、实际盒体输入和修补范围。禁止重生成整页背景、改变主题、材质、气氛、分区或无关区域。底框与示意盒体的关系先设计，实际盒体出来后再验收，不能借背景已选而放弃融合。
8. 用本次待交付的全部真实素材恢复完整1920px页面，等待图片与字体加载，按[视觉验收与返工](design-quality.md#视觉验收与返工)实际检查构图、分区、主题表达、排版及选中方案的完整落实，再核对造型、比例、文字、气氛、接缝和盲盒融合。尺寸、脚本或单件检查通过不能代替整页设计判断；修正实际文件后重新回填查看，禁止使用样张或旧截图证明成品通过。普通精度修复按已选设计执行，不另加一次强制审批；需要实质改变已确认背景、造型、布局或用户指定对象时展示一张改稿，沿原规则确认。最终完整预览仍必须展示，不把示意截图当成品截图。
9. 按[PNG分辨率与PS置入尺寸](v1-layout.md#png分辨率与ps置入尺寸)在各素材及背景冻结前统一目标PPI，保持像素和alpha；实际盒体hash与最终工作集hash均在规范化后记录。通过验收后冻结这一个最终工作集，按[清楚的素材交付](material-delivery.md)从该工作集复制背景、组件和装饰，平铺命名、去重并校对映射，交付唯一正式素材文件夹；清单、页面及证据保留在制作档案；不得在整理交付时再生图。背景无需从完整样张擦除前景，样张背景自始就是独立实际文件。

用户要求组合不同方案时，先建立一个明确的背景＋前景示意组合并确认，再只生产该组合的一套正式前景；未经展示的混用不能直接交付。背景局部修补不授权整页重做，实际素材制作仍按当前imagegen工具规则执行。

跑马灯启用时按[跑马灯变体](v1-layout.md#跑马灯变体)先确定948／1178px实际模块高度，三套样张仅表达常态和单格高亮示意。选中后额外精做一张共用高亮PNG，正式页面用本地脚本逐格演示，检查整圈和暂停／继续，再冻结交付；不提前生产三套完整状态素材。

## 冻结与证据

assets.json与design/design-evidence.json均记录production_workflow: background-final-foreground-concept-v1。design_selection继续记录三套proposals、selected_id、round、status和实际用户回复；每项proposal记录id、file、design_summary、background_set，不再要求三套working_set。

background_set指向本套背景＋示意清单；清单内file及所有下述路径相对于页面目录。示例仅展示结构，assets须列全所有启用背景，concept_images可用少量图表达全部前景，不要求拆成完整素材：
```json
{
  "page_width": 1920,
  "page_height": 2557,
  "background_master": {"file": "design/backgrounds/r1/B/master.png", "sha256": "实际SHA256"},
  "assets": [
    {"role": "hero", "file": "design/backgrounds/r1/B/hero.png", "sha256": "实际SHA256"},
    {"role": "blind.background", "file": "design/backgrounds/r1/B/blind.png", "sha256": "实际SHA256"}
  ],
  "concept_images": [
    {"file": "design/concepts/r1/B/foreground.png", "sha256": "实际SHA256"}
  ]
}
```
背景清单只列hero、banner及*.background角色。page_height按实际模块累计计算，不能把示例高度或不完整背景列表直接当记录。批准approval保留user_reply、sample_sha256，并记录background_set_sha256，冻结当时实际清单与文件。

只有选中方案有完整生产工作集。在证据文件增加selected_working_set：
```json
{
  "selected_id": "B",
  "file": "design/worksets/final/B/manifest.json",
  "preview": "design/qa/final-page.png",
  "manifest_sha256": "最终验收后实际清单SHA256"
}
```
其manifest保留page_width、page_height、background_master、assets和decorations结构；所有项记录实际file与sha256，assets列全正式角色，decorations未启用填[]。未展示的备用状态／可选装饰用used_in_preview:false，其他默认为true。最终工作集哈希是内部验收冻结，不伪称用户对尚未展示素材的新批准，也不新增必需确认步骤。

最终assets每项、background_master与装饰各项增加working_source，指向这个选中方案最终工作集的对应源文件；制作档案内最终资产与工作源字节哈希一致；从档案复制到正式素材的文件再记录交付映射和哈希，技术路径不写入对外说明。装饰file沿旧约定相对于装饰清单，working_source仍相对于页面目录。工作来源快照保留在design，正式素材包仍只有一份。

背景继承另在证据文件记录background_inheritance对象：source为选定原背景母图，result为最终工作母图，comparison为实际同尺度对照图，status为pass，observation说明保留的设计及实际观察；local_changes为具体局部修补说明数组，未修改填[]。背景变化须有来源链及对照，不能仅写“融合通过”。

来源方向：KV／参考 → 实际背景和前景示意 → 浏览器候选样张；选定样张／对应示意＋所选背景 → 一套正式前景；所选背景＋实际盲盒 → 必要局部修补后的背景 → 正式背景切片；最终工作文件 → 最终浏览器截图与交付复制。候选与最终预览都记录kind:derived、renderer:browser及实际直接input_images；前景正式制作允许引用选中示意或其完整候选截图，不能引用未选方案，也不能形成未来截图引用循环。

review.composition使用selected_working_set.preview的真实成品截图；review.comparison保留选中示意与成品的实际对照。七项视觉记录、逐缝截图、盲盒art_sha256与contact／support／lighting验收继续适用。示意用于选设计，不能充当正式尺寸、alpha、状态或融合通过的证据。

## 验收边界

校验器检查三套背景＋轻量示意的实际输入、用户选择与冻结、一套最终工作素材、背景继承记录及交付文件复用；历史shared-assets-preview-v1仅保留旧包兼容，不作为默认新制作流程。脚本不能自动证明截图真实、未选方案确实没有被提前生成、修补仅限局部或前景还原得好：仍须检查实际调用和图像，不把字段齐全或哈希通过当成视觉通过。仅维护Skill时不生图、不制作活动素材。

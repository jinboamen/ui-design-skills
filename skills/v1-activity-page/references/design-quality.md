# 设计转化与视觉验收

每次制作及返工读取本文件。目标是让参考中有效的设计在本次页面上实际成立，而非搜到图片后继续使用熟悉的模板。主KV决定本次活动身份，参考提供相容的设计方法；以下流程适用于不同主题和媒介，不预设颜色、风格、材质或形状。

## 先确定设计，再锁定制作

1. 从当前参考实际展示的整页、模块或组件中找出真正影响目标对象效果的特征，例如标题字面比例与图形配合、卡片的信息分段与边缘处理、亮暗色面的面积、主行动与背景的对比、局部肌理的细节尺度。分别写出“原图哪处可见 → 本次怎样使用 → 结果在哪处能看见”，并保留清楚局部。没有观察依据的“高级、精美、游戏感”不构成制作要求。
2. 将这些方法适配KV与已确认规格，先设计标题、套餐／奖励、主行动、任务条和信息行的组合。标题、卡片、按钮不能仅改变长宽；按各自功能设计比例、文字分组、承托、边缘和强调部位，共享字形气质与图形规则。同组任务复用仍允许，矩形、单色及平面也可精致，不强制每件异形、多色或立体。
3. 为A／B／C以轻量前景确定实际内容区域，按下节背景自动设计与返修流程制作真实背景，同屏验收成立后于1920px浏览器截图；按[混合制作流程](shared-assets-workflow.md)执行。
4. 检查背景、示意比例及组合方向，展示三套完整样张取得用户选择；只为选中方案制作正式前景、状态和装饰，背景直接复用，必要融合修补限于局部。正式回填对照通过后复制该最终工作集交付。

设计选择由执行者根据参考与KV完成，不把制定设计语言的工作交给用户；方案由用户手动选定。每次完整制作先按下节生成3套方案并等待确认，不能把此前的业务配置授权或内部验收当作用户选定或正式交付许可。

## 整页协调规则

每套方案先在本次`design/analysis.md`的画风锁定表中确定背景图形、标题、卡片、按钮、任务条、底框及装饰之间的协调规则。依据当前KV中的品牌／字形／图形处理与主要视觉参考，不从题材名称或照片物件直接推导控件。KV没有明确界面语言时，由相容的主要参考建立它，并说明推导依据；整页摄影、插画或三维仍可与经过设计的平面控件协调共存。

| 共同规则 | 本次要确定的内容 | 同屏核对 |
| --- | --- | --- |
| 轮廓与转角 | 可见形态的硬软、转折方式、方向节奏；圆弧、直角、切边或手绘形态按依据选择 | 背景图形、标题配套图形与控件的造型气质协调；各类独立设计轮廓和转角，不要求重复同一种可见形态 |
| 线条与边缘 | 各类独立决定有无描边、线条粗细、边缘断续或连续及内外层次，不共享边缘模板 | 不同边缘的细节尺度和视觉重量与各自功能及整页相容；不要求同样的边线、切角或收口，默认CSS不能覆盖各自母版 |
| 表面与光感 | 色面、肌理尺度、光影方向、反光强弱、虚实及各媒介职责 | 前景和背景的表面气质有联系，文字仍可读；不要求所有对象复制同一材质或全部立体 |
| 字形与比例 | 字重、字面比例、排版节奏及控件与内容的关系 | 标题、名称、说明与行动文案有统一气质和清楚层级；沿用既定标题显示比例 |
| 色彩与视觉重量 | 主辅色面积、边缘和填充的强调程度、对比与密度 | 主行动突出、正文清楚、辅助入口可辨；共同配色不足以替代造型和表面协调 |

每项写清“当前可见依据 → 本方案的整体联系 → 各类独立设计”，有实际可测的转角、线宽或细节尺度时按最终显示尺寸记录。规则用于统筹设计，不把所有元素画成相同外框，也不预设圆润、机械、极简或任何固定风格。不同模块可以改变承托面积与密度；不同用途的按钮仍须有清楚层级，中奖记录与任务操作继续明显区分，但都属于本方案的整体气质。

### 背景与组件的具体联系

在A／B／C各自的画风锁定表里，为每类启用组件写出“背景及参考的可见依据 → 本件实际设计 → 保留的功能差异”。依据必须来自本方案的整页组织及真实参考，不能仅写同色、同主题或统一高级感。记录以下关系并将具体设计句用于本套工作背景、组件的生成／编辑输入和真实预览，不另展示组件候选图：

| 关系 | 必须说明的实际设计 |
| --- | --- |
| 背景 → 套餐／奖品卡 | 背景的形态硬软、方向与层次怎样适配成卡片的构图、分区和视觉重心；填充、边缘与细节尺度怎样与底景相容。套餐与奖品各有结构，不复用彼此边缘 |
| 卡片／背景 → 按钮 | 按钮的轮廓气质、表面与字形怎样融入卡片及底景，同时以适当明暗、面积和信息重量突出行动；不能默认套圆角渐变块或普通矩形 |
| 背景 → 任务条 → 任务按钮 | 条的连续表面、文字排布和独立按钮共同设计，不另画按钮包裹区，按钮在既定右距32px的位置自然落入组合；任务主体清楚分离，同时不变成另一套表单控件 |
| 标题／辅助入口 → 内容区 | 字形、图形密度和表面精度怎样与内容一致；主次明确，规则与记录入口清楚，但不靠移植无关控件制造差异 |

每类至少在造型、表面／光感、字形／排版中说明两方面的具体联系，颜色另按职责分配；这些联系不要求复制同一种轮廓或边缘。例如，硬朗背景中的套餐可以通过纵向信息骨架、克制表面及坚定字重融入，任务条通过横向排版、留白与连续表面融入，按钮通过紧凑轮廓与明确色面融入；柔和背景则另按其参考设计对应关系。这只是判断方法，不将斜切、直角、金属、圆角或任何处理设为通用答案。

明亮卡片、平面按钮、圆弧与直线对比都可以采用。判断看完整参考中该对比怎样服务阅读，以及本次在比例、表面和字形上是否仍有联系；不能把深色背景下的浅色卡片一律判错，也不能以“需要对比”放行像另一套网站表单的前景。卡片无需照抄背景纹理，按钮无需复制背景斜线；不共享边缘、不画成同一个框的要求继续有效。

### 丰富背景下的前景力度

**背景有丰富造型时，前景须有相称的设计完成度和视觉重量。** 套餐、奖品、任务与按钮是内容焦点；不能把背景做成完整主题插画，前景却停在通用浅色框、细描边和普通文字。轻量示意减少的是正式切图、状态和细节输出，不省略组件的主要造型、层次、文字组织与实际显示比例；不得把“选中后再精做”当作前景过弱的通过理由。

在已选参考和KV范围内，逐类设计能在真实尺寸辨认的主体轮廓、边缘转折、面与边的层次、强调色位置及字形重量。丰富可来自有节奏的轮廓、平面叠层或精确的局部细节，不等于更多装饰、色块、厚框或三维特效。前景不必复制背景纹理，但应在同屏时具有相称的主题表达；按钮明确行动，奖品卡突出展示图，任务条和套餐卡保留连续可读的文字面。

先判断失衡原因再修正：
- 前景仍是默认框或设计力度不足：完善对应组件的造型、层次和信息组织；奖品过小按[实际显示比例](v1-layout.md#奖品卡与实图的实际显示比例)调整卡片、图片区和组内留白，不能仅靠压淡背景掩盖。
- 前景已经合格，但背景在内容周围过亮、过密或形成更强焦点：局部修背景，不让两层不断加亮、加粗或加装饰竞争。
- 两者都有问题：分别修改，不因丰富背景而放行弱前景，也不为了衬托无设计的控件把整页删成空底。

套餐最多两块色面且辅助面靠下、任务条无额外按钮槽、三行文字与上下净空等规则继续适用；丰富处理优先放在不会挤占正文的轮廓及外围。保持既定套餐、任务与按钮显示规格，不通过放大所有前景解决主次。

展示A／B／C之前，在每套真实1920px页面与整页缩览中同时检查：卡片组、奖励与行动能否成为内容区焦点，轮廓和层次是否仍可辨，文字区是否舒展。结合周边背景展示已有组件局部；前景像临时占位控件时，`component_craft`和`content_composition`记`revise`并改对应示意，不能仅凭背景完成、配色一致或尺寸合格展示为可选定稿。前景力度合格后，正式素材继承它，不在选定后另换设计。

### 同一体系，各有结构

整套联系来自相容的造型气质、光感、字形、颜色职责与视觉重量；各类素材按功能独立设计轮廓、转角、边缘、信息区比例、局部承托与视觉重心。不同类别不共用边缘模板，也不强制重复框线、切边或角部装饰。不能把同一框体放大缩小后用于套餐、奖品、任务与按钮，也不能仅换颜色或加一枚图标就认定已有差异。不同组件可以各有构图，但要看出它们来自本方案的共同规则。

| 对象 | 保留各自的设计角色 |
| --- | --- |
| 套餐卡 | 围绕名称、权益、价格和购买设计纵向信息层级与强调区，不能直接借用奖品卡的上下两块结构 |
| 奖品卡 | 围绕展示图与名称设计图片承托、上下交界和边缘；与套餐卡的整体气质协调，边缘及展示构图独立设计 |
| 任务条 | 横向组织任务、条件和独立操作按钮；按钮右距32px，整条围绕阅读及操作设计，不把套餐卡简单横拉 |
| 主行动与辅助入口 | 主次力度与表面处理有区别，轮廓或填充可按用途变化；各按钮仍符合既定对称、尺寸和文字安全要求 |
| 标题与主体底框 | 标题引导章节，底框承托主体；分别设计文字与空间关系，不复用卡片外框充当两者 |

同类同组可共用母版以保持识别，例如奖品卡只替换内容、任务条及同状态按钮按既定规则复用；统一模块标题仍只换文案。同一方案的多个套餐必须复用一张卡片底图和一张购买按钮底图，套餐内容与等级差异由HTML文案表达，不据此自动增加样式；按[多套餐复用同一套素材](v1-layout.md#多套餐复用同一套素材)检查全部实例。验收分别看“各类是否协调”和“各类是否具有自己的结构与重心”；只满足其中一项都要修正。

KV与[共用参考集合](planning-and-references.md#按设计缺口组织搜索)共同建立整套设计的协调关系，不要求一个主参考包办全页；各项局部只解决明确的问题。补充控件参考须同时核对轮廓硬软、转角、线条、表面和字形；形态不相容的作品只借信息结构，或重新找参考，不能分别照搬几套控件后靠统一颜色拼合。有意的形态对比可以使用，但须有当前KV／参考的可见依据，并在整页中证明它服务内容和层级；不能事后仅以“功能不同”解释失配。

### 同屏建立，沿母版继承

在A／B／C各自的一张完整整页样张中同时设计背景、标题、套餐卡、奖品卡、主按钮、任务条及主要状态设计、辅助入口；用已有样张的局部查看组件关系，不另生组件总览。前景示意及选中后的正式素材提示词写明上节各类的具体设计，不能只详细描述背景而把前景交给“搭配卡片、按钮”等泛泛指令；无需增加用户审批环节。背景图形和控件双向调整，检查它们的造型气质、表面与视觉重量是否协调，边缘分别按各自功能完成；已有用户明确认可的局部迭代基准则保留，以该基准修正未认可部分。背景可先起稿，但定稿须通过轻量前景同屏检查；背景问题由执行者自动修复，已有合格前景作为固定参照，不为迁就背景改变其造型、大小或位置；选中后的正式前景继承该方向，不分别自由重抽后用改色掩盖不搭。

A／B／C各自是一套协调且符合当前KV的完整方案，可探索不同的相容组织与组件处理；不能把三种风格混进同一套。展示前，既看整页缩览，也看实际显示尺寸的模块和组件，特别核对背景→卡片→按钮、标题→内容、任务条→独立按钮的关系。对每类启用组件做一次“暂不看配色”的核对：只看形态、表面层次和文字组织，是否仍能说明它属于本方案；再恢复颜色查看真实对比与层级。检查无需额外生图。某件放回页面显得来自另一套设计时，记录具体失配与修改方向，不能写通过，也不能仅靠改色或给所有元素加同一切角修补。返工按三套样张流程与用户反馈执行，不擅自追加出图。用户仍手动选定样张；背景和轻量示意在展示前完成；完整前景只在选中后为该方案生产，未确认不整理正式交付文件夹。

正式交付直接采用所选方案的工作背景、组件和布局，保持其实际轮廓、转角、光感及字形关系；不以截图为输入再次生成PNG。用户指定局部改稿时只编辑对应工作文件与必要环境关系，重新实际回填和截图后再冻结；状态变化沿用既有同组母版。

用现有`component_comparison`展示背景、代表组件、母版与最终回填的关系，保留足够周边背景，不能仅展示脱离底景的透明PNG。在`component_craft.observation`逐类说明套餐、奖品、按钮、任务等已启用对象与底景的具体造型／表面／字形联系及各自结构；某一类失配就记`revise`，不能以其他组件精致或背景通过抵消。在`export_fidelity.observation`记录拆分是否保留。无须新增形式化评分或字段；实际看图发现前景与背景失配时仍记`revise`，不能凭颜色统一、规则已填写或文件规格通过就交付。

## 背景自动设计与返修

本节由执行者自动执行，不要求用户懂设计、填写背景设计表、指出纹理密度或先选择测试模块。沿用既有业务配置和A／B／C整页选择；不增加中间审批。当前仅反馈背景问题时，保持已认可的卡片、按钮、主体及其位置和尺寸，用它们检查背景。新活动仍依现有轻量示意流程定位前景，不提前精细生产三套素材。

### 从当前视觉依据推导背景

从本次KV与已经实际查看的相容参考提取背景的可见做法，结合最终内容位置，在现有design/analysis.md为各模块简要记录：主形状及其尺度与方向、色面与明暗面积、纹理集中和减弱的区域、前后虚实、主体承托与相邻区过渡。由执行者把这些具体关系写入本轮背景生成／编辑输入，附实际视觉依据和布局上下文；不向用户追问如何设计，不以“高清、有氛围、统一”代替设计指令。

背景同时服务主题表达与信息阅读。按[内容区背景的亮面与视觉主次](#内容区背景的亮面与视觉主次)先控制前景周边的亮面、反光和局部对比。依据参考决定哪里有主题细节、哪里留出安静区域、哪里用局部对比衬托主体；不是把所有背景都做暗、做空或减少纹理。轮廓清楚与有意的远景柔和可以共存；不能为了“高清”给所有区域加密纹理、锐化或提高反光。不得把某次海浪、金属或游戏案例的处理硬编码为通用风格。

### 内容区背景的亮面与视觉主次

本规则从首轮背景和样张开始执行，不只用于选定后的气氛继承。模块背景用于衬托标题、卡片、奖励和操作，不另造一个争夺注意力的主视觉。先以本套实际前景示意／已有合格素材的位置、明暗及可见轮廓为依据，记录内容后方、周边和远景各自的亮面面积、局部对比与细节分布，写入背景生成输入。不能只分析空场景好不好看，再让卡片迁就它。

- **分块的浅色面不等于过曝场景。** 按KV配色规划出的浅色或强调色模块允许大面积明亮承托，通过较安静的纹理、清楚的内容对比及统一组件保持主次；不能因暗色KV就将其压回深底。以下环境光约束用于实际采用场景照明的区域及无依据的提曝光，不禁止有意设计的深浅色面分区。
- **按KV区分环境光与主角受光。** 暗色KV中人物、装备或标题的高光属于焦点，不把这些亮度铺到内容区的整面墙、雾、天空开口或地面。延续KV的环境中间调、暗部与有限亮点，保留材质可辨性；不为了看清空背景而自动提曝光、抬黑位或扩大反射。明亮KV仍可用明亮背景，但内容附近要有安静的纹理与明确前后层次，不机械改成深色主题。
- **亮度、面积和对比一起控制。** 亮墙、雾光和地面反射连成大块高对比区域时，即使单点不比按钮亮，也可能成为视觉中心。内容后方避免大范围抢眼光斑、强光束、密集反射和高对比纹理。需要局部反差帮助深色卡片或盒体显形时，只在有作用的位置适量保留，不扩大成包围内容的发光舞台；周边亮点也须检查是否把视线引出内容。
- **高清不等于处处明亮。** 保留结构与材质的清楚边缘，同时压低非重点区域的局部对比和过强反射；不以全局锐化、曝光提高或铺满细节换取清晰，不用整体模糊／黑色蒙层代替局部设计。

展示候选前必须恢复实际比例的标题、卡片、盲盒、奖品和按钮，在整页缩览看视觉重心，再在正常显示尺寸看内容边缘、文字与相邻底景。观察并具体说明最抢眼的区域在哪里；若首先突出的仍是无业务作用的亮墙、亮地面或雾光，而内容像贴在场景里，background_design和content_composition记revise，修复对应背景区域后再展示。空背景只能用于查画质，不能单独证明前景突出；纯背景阶段未叠入前景时，不宣称主次已验收。

返修优先缩减过亮区域面积、降低该处中间调／反光／纹理对比，或调整光线位置和衰减，保持已合格前景、原有场景与空间连接。此处针对已合格前景，不禁止按[丰富背景下的前景力度](#丰富背景下的前景力度)完善本身不足的组件；不要加亮卡片、加粗描边、扩大按钮或添加光圈来与错误背景竞争，也不自动把全页压黑。分块模式每对相邻模块的明显底色差异仍须保留，在KV范围内设计不同基础色面并同时让内容突出；不靠每隔一章升曝光完成分区。候选按[样张阶段的工作边界](shared-assets-workflow.md#样张阶段的工作边界)计入整套集中修正，不能为亮度问题另开轮次；正式阶段保留最终质量验收。记录实际观察，不设通用曝光值或固定亮度百分比。

### 在实际背景上完成设计

先以实际尺寸的前景示意或已有合格素材定位内容，生成背景后立即同屏查看；背景构图、光感、密度或承托不合适时修改实际背景文件，再叠回同一前景比较。背景与前景分层存储，组合图仅作定位、判断或必要局部编辑上下文，不把整张组合图去除前景再重建背景。

按最终模块显示尺寸安排生成范围，结合工具实际输出尺寸检查可用像素；需要分段时带上相邻区域上下文并在共同坐标中完成交界。整页母图是这些实际背景的统一设计与导出来源，不等于先生成低分辨率长图再放大或重画每区。最终宽度为1920px不自动证明细节足够；样张展示前必须看实际像素，不能以将来“高清重制”补交质量。背景返修保留已经成立的区域，不反复重生成整页，不因空出内容区域而擅自增加景物、背板、舞台或高频纹理。

### 自动看图、定位和返修

候选展示前将以下三个尺度合并到每套的一批检查中，使用同一版本的背景和前景及已有预览；不为每个检查项另拍整页或另起返修：
- 原尺寸背景局部：结构轮廓、表面材质与纹理是否可辨，是否出现无意义碎片、重复花纹、涂抹或放大糊感；有依据的景深柔和不判为缺陷。
- 恢复前景的模块及整页：大形状、明暗面积、纹理密度与留白是否延续KV及参考，主体和操作是否突出，背景是否抢眼、过空或让内容像贴上去；不能只验空背景漂亮或平均亮度。
- 相邻模块的实际组合：检查全宽过渡、图形延续、重复与裁断、标题净空；按模块区分同时核对每处大面积底色差异。

问题必须落到具体区域和原因，再选对应背景修法：背景抢亮时先缩减对应亮区、雾光和反射的面积与对比，不改亮已合格前景；密度过高调整纹理尺度与分布；缺少氛围恢复参考支持的色面、虚实和主题层次；主体割裂修复背景侧承托、接触与局部光影；边界断裂编辑跨界上下文。不要泛泛追加“更高清、更好看”后重新抽整页，不重做已合格前景，不用全局模糊、压暗或CSS蒙层掩盖问题。

候选返修统一按[样张阶段的工作边界](shared-assets-workflow.md#样张阶段的工作边界)：每套先汇总问题做一轮集中修正，关键问题最多再一轮定点修复；按整套累计，不按每个问题重置。保留较好版本，仍有关键问题时如实报告并停止重抽，不冒充合格，也不要求用户给美术解决方案。候选观察简记到现有analysis；正式阶段再完善background_design、content_composition等最终视觉记录，不提前为三套填写成品验收。

展示的候选直接使用上述检查通过的实际背景文件；用户选中后复用，禁止重新从示意提取或整页高清重绘。最终盒体出来后的背景修改仅限必要承托、接触阴影与反射等局部融合，依既有冻结与背景继承规则保存对照并重新检查受影响模块和交界。

## 同一KV下的三套设计区别

A／B／C是同一KV画风下的不同设计做法，不要求三种截然不同的风格。品牌、媒介、配色职责、材质气质、光感和用户指定素材继续由KV约束；模块顺序、V1尺寸、文案、按钮位置与文字安全区不为制造区别而改动。区别由执行者设计，不要求用户指定三套美术方向，也不固定为极简／华丽／科技等通用套餐。

生成前在现有design/analysis.md简短并列三套的设计决定：主要参考及采用的具体方法、背景组织、卡片的信息区与轮廓、标题组合、按钮和任务条的形态及层次。既写共同保留什么，也写哪些具体做法不同；“更高级、更明亮、更有质感”不能作为方案区别。每两套应有可直接指出的主要形式差别，不强制改变全部组件或大幅改变背景；优先检查最显眼且容易重复的卡片、按钮和任务条。

- 卡片可在既定内容层级与尺寸内改变排版、边缘与主体的关系、图形和表面的组织；套餐底图仍遵守连续主面、最多两块且辅助色面靠下的限制，任务条不得新增按钮包裹区，不能靠增加分色制造方案差异；不能三套沿用同一个框体与相同分区，只替换填充色、角部装饰或切角大小。
- 按钮、标题和任务条按本套设计独立组织轮廓、文字周边、层次及行动关系；不强迫全部类别复制同一边框。已有V1位置和文字净空继续有效，任务条不增加被禁止的固定竖向分割，不以巨大按钮外圈或装饰挤压文字。
- 背景可采用不同的主形状、疏密与内容关系，但仍承接同一KV和已选背景模式；不为了扩大差异更换媒介、主题或整体气氛。用户已认可并要求保留的前景直接保留，区别集中在获准修改的范围。
- 深／浅底、金边／银边、纹理方向、局部高光、几处切角或小装饰的替换只能算细节变化。若三套均为相同切角矩形、相同上下分区及相同任务行动区，仅改变这些细节，仍属于同一设计的变体；此处不是禁止切角或金属，而是检查是否反复使用相同结构。

参考可以共用，不要求每套找完全不同的网站，也不要求完整活动页。但不能三套都套用同一参考的同一种组件结构：按对象提取相容的不同设计方法，写明哪些方法用于哪套。现有参考只支持一种做法时，针对缺少的组件或模块补搜并实际看图、展示来源和借鉴点，再生成受影响素材；不以换参考链接代替设计区别。

生成各套时把本套具体决定写入提示词，不从A的完整成稿仅改色派生B／C，也不把A作为B／C唯一设计输入；共用KV及已明确保留的素材不受此限制。轻量示意仍须表达实际组件形式，不能因正式前景尚未生成而让三套都使用同一套占位框。

展示前用已有三套真实样张作同尺度并排检查，并查看对应卡片、按钮和任务条局部；不新增生图或组件选择环节。暂时忽略配色与小纹理，观察轮廓、信息区组合和主体／行动关系是否仍有可见区别，再恢复颜色核对KV相容与整页协调。无须机械计算像素差异，也不设固定差异百分比。若两套主要形式相同，先调整其中重复的设计，再更新实际文件及样张；计入该套集中修正与关键问题定点修复的总轮数，不为差异检查另开两轮，不无限重抽、不追加候选数量、不伪称通过。观察记入现有design_summary及analysis，无需新增证据字段。展示每套时用一句话说明具体做法差别，不把它们命名成只有颜色深浅不同的版本。

## 三套样张与手动确认

每轮按[最终背景与轻量前景样张](shared-assets-workflow.md)制作A／B／C三套最终背景及轻量前景设计示意，实际使用本套背景在1920px浏览器拼出三张完整样张。背景已通过执行者自动完成的实际像素、前景衬托、气氛与交界检查及必要返修；前景表达真实造型、表面、字形、内容层级及V1显示比例，暂不生产三套正式透明组件、全部状态或独立装饰。

先按[同一KV下的三套设计区别](#同一kv下的三套设计区别)写清三套背景和控件的具体做法，并检查是否重复使用同一结构，背景与前景示意仍同屏协调；省略的是未选方案的精细输出工作，不降低示意设计判断质量。三套均检查缩览、实际尺寸和全部交界，稀疏配置的承托与留白在固定规格内成立，不让概念里的组件比交付尺寸更大。

一次只展示A／B／C三张完整组合及大图链接，明确背景为实际交付版本、前景为设计示意。等待用户选择具体版本，不把业务配置或内部检查当批准。整轮否定重新找参考再重做背景与示意；局部改稿只更新指定方案并展示，不自动追加三套。用户要求组合方案时，先组合实际背景和前景示意确认，再只生产该组合的一套正式前景。

每套proposal保存background_set，批准approval保存实际user_reply、sample_sha256与background_set_sha256。保留各轮背景、示意、截图和冻结快照，不覆盖已选版本。完整字段及来源方向见[冻结与证据](shared-assets-workflow.md#冻结与证据)。

选择后只为该套精细制作标题、卡片、主体、奖品承托、按钮、任务状态与独立装饰；实际附上所选样张及对应局部，保留造型、表面、层次、字形、比例和位置。背景直接复用，不能通过去除样张前景重建背景；实际盲盒出来后允许对所选背景局部修补底框、承托、接触阴影与反射，不借此改主题、气氛或分区。

恢复全部正式素材、真实内容／授权占位和同一V1布局，再与所选示意同尺度对照；前景独立生成产生的偏差须修正，不能以示意为由接受另一个造型或简化框体。通过全部机械与视觉验收后冻结selected_working_set，交付直接复制这个唯一最终工作集，哈希对应。普通精度修复不新增审批，实质改变已选设计按既有改稿流程展示并确认。

最终预览必须是真实成品截图，review.composition不能使用轻量示意冒充正式验收。背景继承、接缝、盲盒融合及七项视觉检查继续适用；字段齐全、来源和哈希通过不能自动证明真实审美或局部修补范围。

## 套餐背景以信息阅读为中心

套餐模块展示可阅读、比较和购买的信息卡，背景负责延续活动氛围、组织留白与突出价格和行动。默认让卡片直接呈现在整体背景的阅读区域中，不把它当盲盒、实体商品或展品来布置。即使只有一张套餐卡，也不因中心显空而自动增加展示台、托盘、底座、台阶、围绕卡片的杯状／环状承托、背板舞台或专属浮岛；只有用户明确要求此类展示结构时才作为该次例外。参考里有舞台、KV是三维或盲盒区有底框，都不自动授权套餐采用同类结构。

由执行者从本次KV与相容运营参考推导套餐区做法，生成输入正向说明卡片的位置与阅读范围、背景的连续色面与明暗组织、主题元素在周边的分布及与首屏的过渡。可以用局部光感、低对比图形、边缘景物和少量主题元素衬托，但避免将它们围成卡片专属的水平承载面或封闭舞台。环境本身已有的地面、水面、曲线或连续场景可以保留；判断依据是是否额外构造了一个专门托住套餐卡的物体，不按海浪、云朵、圆形或某种材质一概禁用。具体题材和表现随活动变化，不将套餐背景统一退成纯色。

单卡或稀疏配置通过背景细节的分布、安静区域、适度的视觉引导以及既定位置的信息层级形成重点，不靠加台子填空，不擅自增加套餐数量或放大卡片突破V1尺寸。多卡以整组内容为中心组织周边元素，不为每张卡复制一个底座，也不画一个共用大托盘把整组包起来。

区分三个对象：package.background是模块环境；package.card的文案填充、轮廓和自身阴影属于卡片；卡内购买按钮的局部承托属于既有卡片／按钮设计。后两者继续保持完成度和可读性，不因取消模块展示台而删除卡片内部底板、按钮承托或正常阴影。盲盒的包裹、落地、底框及接触关系只约束对应盲盒角色，不能从通用“融合／承托”措辞推导出套餐也必须有实体底座。

每套候选展示前及正式回填后，查看完整套餐区并临时隐藏套餐卡：若露出一个明显等待放置展品的独立台子、托盘或包裹舞台，且没有用户明确要求，记为revise，自动修复对应package.background区域。恢复同一套餐卡检查：允许周边衬托，但视线应先落在套餐内容和购买入口，不能让台子成为主体。保留已有合格卡片、按钮、相邻转场、清晰度及分区底色；不通过把台子移进卡片PNG或装饰层绕过检查。沿现有background_design与content_composition记录观察，不新增用户配置或审批。

## 背景承托与组件的分层归属

**保留设计也要保留各层职责，不能为了细节齐全把背景和组件合成一张。** 本节适用于所有主题、所有启用模块和两种背景模式；不以颜色、是否位于物件后方或整页样张的裁切框决定归属。识别一个元素是在组织模块空间、衬托整组内容，还是构成组件自身的外形与表面，还是需要单独定位的底板／装饰。样张可以呈现完整组合，正式素材按这些职责拆分，重复铺入同一元素或整体烘焙都不算正确还原。

**章节分割线要单独核对唯一归属。** 样张中分隔相邻模块的图形只归背景，不能在前一模块底部、后一模块顶部、标题 PNG 或页面叠层各留一份。拆分前按[模块分割线唯一归属与标题避让](v1-layout.md#模块分割线唯一归属与标题避让)完成共同坐标设计、互补导出和标题可见范围避让；分层记录逐条注明跨界位置及承接文件。按模块区分不强制分割线，仅对样张实际采用的线条检查唯一归属；无线交界沿用色面或留白转换，不补线；整体衔接的同源切片不能豁免母图本身已经画出双线。

附属设计与场景承托有时外观相似，应结合完整模块、参考局部、遮挡与排布关系判断，不只看一张紧裁局部。卡片自身的翻页、插片、徽记、精确边缘叠层等可属于卡片，不能为了去掉衬景而一律抹成空白面板；判断不明确且影响设计时才逐项向用户确认。用户明确指定某元素归背景或独立层时以该要求为准，不重复询问。

光影也按职责拆分：物件表面的高光与明暗留在物件，组件自身的近边阴影可随主体；落在公共舞台、地面或其他对象上的环境／投射光影按接收层和样张组合处理。遮挡或依赖主体位置的效果需按既定布局补全和定位，不烘焙主体轮廓形成残影，也不将环境光圈或大片地面阴影带进小组件后一起缩放；按[光影逐项归属与回填](#光影逐项归属与回填)落实接收层和关联层，不能因清理主体而让光影无文件承接。不能机械地把全部光影归背景或全部归组件。

### 拆分前建立归属与遮挡记录

在现有design/analysis.md的元素记录中增加每项的归属层、目标文件、与其他层的遮挡顺序、定位依据以及主体移动／重复时是否随动；覆盖本次所有启用模块，不增加正式素材角色或新的配置表。先确定背景（盲盒底框包含其中）、其他有独立职责的底板、业务主体、独立装饰及文字的职责，再制作各层。分层关系不要求各类组件共用边缘，也不改变固定尺寸和数量。

每个实际生成／编辑输入同时提供所选母版的完整模块和相应组件局部，标清“本层保留什么、邻层由哪个文件承接”。从整页样张裁出局部仅作为参考，不能直接把裁切框内所有内容当成一件透明素材；自动去掉最外围底色，也不能证明剩下的衬景属于该组件。背景制作时保留指定衬景，去除前景和文字并补全遮挡区域；组件制作时保留自身结构与细节，隔离应留在背景、底板或其他组件中的元素。移出某层的元素必须在正确层恢复，不能为了清理而丢失。

背景在固定布局中通过留白、对比和周边元素突出套餐信息；套餐数量、排列或尺寸适配变化时，协调这些背景关系，不默认新增实体承托，不把环境元素绑到卡片PNG，也不为每张卡复制舞台。连续模式先完成各层正确分离的完整母背景再切片，分块模式在各自背景内完成归属，所有层同屏回填后保持已确认样张的整体关系。

### 隔离各层再验收组合

正式拆分后按本次启用对象逐项执行，不只检查套餐或盲盒：

1. 在深浅纯底上看独立PNG，并在分析记录其应含／不应含元素。套餐卡不带模块舞台，盒体不带底板或地面，按钮不带任务条承托，独立底板不带主体或奖品；图内有透明像素、文件尺寸正确不能证明归属正确。
2. 在真实页面临时隐藏业务卡片、盲盒、按钮及独立底板，核对本次实际采用的主题造型和环境层仍在正确位置且无控件、文字或主体残影；套餐区同时按上节检查没有未经要求的专属展示台，不能因分层验收而补画舞台；再恢复组件及装饰确认各自完整；盲盒底框始终随背景保留，其他有独立交付职责的底板才单独恢复。该检查只用于验收，不交付额外候选方案。
3. 临时单独移动或重复一张组件验证是否带走／复制了不属于它的背景造型；验收后恢复正式布局。单独隐藏按钮时卡片／任务条的连续底面保留，任务条右侧不得残留专属包裹区，隐藏盲盒盒体时背景内底框与舞台仍保留；其他需要独立底板的对象隐藏底板时模块舞台仍保留。属于组件自身的附属设计应随组件，不以所有后方图形必须不随动作为标准。
4. 恢复最终组合，与所选样张同尺度对照：原有衬托仍成立，主体大小符合规格，遮挡顺序、承托位置和边缘正确，既无缺失也无重复图形／阴影、贴图残边或双重底板。

沿现有component_comparison与background_comparison保留各层及回填的清楚对照，在export_fidelity.observation记录归属／隔离检查，在background_design.observation记录背景承托的保留和补全结果。背景并进组件、独立底板并进主体、重复烘焙或隔离后缺失均记revise，修复并重新回填查看后才能交付。校验脚本能检查角色、尺寸、透明度与来源，不能自动识别画面里哪个蓝色造型属于哪层；实际图像与浏览器检查是必要验收。

## 底板与背景成组制作及融合验收

**通用的是组合继承方法，不是某张图的结构、材质或效果。** 所有活动主题、品牌、媒介与启用模块，均从本次确认样张识别主体、承托及背景之间的具体关系，再在最终规格下完成组合、按职责分层、回填验收。实体／场景设计检查实际空间与接触关系，平面设计检查图形延续、色面组织与叠层，其他表现按其真实视觉依据判断；不要求每个页面都有三维、墙面、地台、弯折、落地、阴影或发光，不预设历史案例的构图。

**独立交付、成组制作、组合验收**用于需要分层的对象，不能把背景舞台变成组件附件，也不为每种组件新增独立底板。按既有角色执行：套餐背景的环境、色面及周边衬托与套餐信息共同设计而分别归background和card，默认不生成组级实体台子；盲盒背景与局部底框共同归background，盒体独立归art；任务条连续底面与独立按钮成组但各自分层，不添加按钮专属承托区；标题、奖品卡及礼包按现有职责保留自身附属设计与所在模块的关系。同类组件可按既有规则复用，不同类不共享框体或边缘。后面的盲盒角色、包裹与中心要求是该模块的具体规格示例，不套到其他模块。

### 盲盒底框并入背景后的专项验收

底框和场景共同归 blind.background，最终盒体 blind.art、奖品卡及按钮仍独立；文件合并不代表融合关系已经成立。制作须绑定实际最终盒体，不能只对齐背景里底框的矩形中心。实体承托先按[盲盒与承托面的透视和落点](#盲盒与承托面的透视和落点)验证共同视角、台面深度和盒底接触，再补光影；样张阶段也须执行，不能留到交付才检查。

1. **先固定最终盒体。** 从用户确认样张沿用盒体设计，完成317×300导出及317×296显示适配，检查完整alpha轮廓、盒盖、突出部分、受光与透视，冻结实际PNG。先生成的背景只能作为工作底景，不在盒体未定时把其接触、衬托和光影当最终成果。
2. **以实际素材建立最终尺寸组合基准。** 在V1实际坐标叠入冻结盒体、奖品、按钮和背景内底框，同时附已确认样张完整模块与清楚接触局部作为图片输入。核对真实可见边缘、承托比例及透视／图形关系，不按透明画布中心或一组计划矩形代替。底框可包裹、居中，但这些只是几何条件。
3. **在背景侧恢复样张的交互作用。** 从样张逐项识别实际存在的接触／闭塞阴影、投射、局部反射／染色、承托面明暗和衬托图形，分别标明落在哪处接收面、如何连接实际盒体，以及由blind.background哪段承接。只保留本次确有的效果；平面样张用图形叠层与衬托关系，不强加写实阴影。贴近实际受支撑边缘的暗部、向外衰减的投影及环境受光共同成立，不能只给底框自身补一圈阴影；底框背后的灯光也不能代替盒体与承托面的接触。
4. **最终背景编辑必须参考冻结盒体。** 使用冻结blind.art，或明确包含它的实际尺寸组合基准作为真实图片输入，再修正背景侧接触、光影和原有衬托。来源链须从最终blind.background经真实母图／组合输入追溯到本次最终blind.art；只共同来自同一样张，或位置修正仅参考旧空背景，不能证明它们成组制作。盒体不得依赖这个最终背景形成循环来源，必要修改另存版本后重新建立组合。
5. **移除物件时保留接收面的作用。** 制作干净背景只移出盒体、奖品、按钮和文字，不连同接收面上的真实阴影、反光及衬托一起擦掉。“无主体残影”指无盒体图像／重复轮廓，不指消除其落在承托上的阴影。保留的交互效果须按实际冻结主体的位置与轮廓注册，不能有旧盒体的错位投影；不为让空背景单独干净而让最终组合脱离环境。
6. **立即回填再决定是否成立。** 将同一冻结盒体按原坐标叠回修好的背景，恢复奖品和操作，比较“确认样张 → 最终尺寸组合基准 → 真实浏览器回填”。检查箱底／受支撑边缘是否有亮缝、阴影是否偏离或全部被遮住、衬托比例和原有图形是否保留、局部受光及透视是否矛盾、奖品压边与留白是否成立；悬浮／贴片感或接触弱于样张仍须返修，不能仅凭位置、包裹、颜色相同或阴影文件存在写pass。

主体位置、大小、轮廓、透视或奖品排列变化时，旧背景侧接触与衬托都须重新注册和检查；冻结盒体文件变化后原融合报告失效。优先修复背景侧失配及必要交界，不移动／缩小盒体迁就错误底景，不以通用CSS投影、全页暗化或新光圈掩盖原有关系丢失。背景修好后在共同母图重新导出，既有分区与明暗气氛要求同时成立。

按[V1包裹与居中验收](v1-layout.md#底板包裹与居中验收)保留局部底框测量，并在fusion_review记录冻结art_sha256、实际三阶段comparison图片、以及contact／support／lighting三个交互检查的实际观察与状态。contact核对接触或样张采用的平面连接，support核对原有衬托元素及关系，lighting核对作用在背景接收面上的光影；不存在写实效果时说明样张的实际替代关系，不补造。任一未恢复写revise，并保留真实1920×806完整组合截图。机械校验只检查绑定、证据与声明状态，不能自动证明阴影、衬托或画面融合，仍须实际查看。

### 盲盒与承托面的透视和落点

当盲盒采用实体空间与落地承托时，先验空间，再处理阴影；仅有相似材质、居中包裹或一圈软影不算融合。平面图形式衬托或已选设计中的有意悬浮按其原有关系验收，不为所有主题添加台子。

- **区分背板与接收面。** 背后的局部底框负责与其类型对应的图形衬托或包裹关系，脚下台面／地面负责接住盒底，两者都可属于blind.background，但不是同一个定位对象。完整包裹、同中心规则仅用于对称包裹框；平面图形衬托按构图、视觉中心及遮挡关系验收；台面按真实接触位置定位，不把水平台面拉成包住整个盒子的矩形，也不把台面中心与盒体中心重合。
- **先锁本套可见的视角和支撑关系。** 在最终V1坐标放入本套实际盒体示意或已认可PNG，记录顶面／侧面的可见程度、盒底可见拐点及受支撑边缘、承托面的前后界与可用深度，并明确盒子是落在平面上还是采用其他有依据的关系。由执行者从图像判断，不要求用户输入相机参数。生成承托时附上这个实际组合及清楚局部，禁止只用“金属箱＋台子、透视一致”等文字让两件各自猜测。
- **检查共同视角，而不是强迫边线平行。** 盒子与台面可有不同水平朝向，但必须能处于同一相机视角与支撑平面；检查俯仰、可见顶面、近大远小和深度关系。盒体明显俯视、台面却近乎没有可容纳盒底的顶面，或盒底越出台面且无合理承托，都须修正。不可仅因盒体边线斜、台沿水平就判错，也不能从单张图编造精确焦距或相机角度。
- **用可见盒底对位。** 盒体画布底边和alpha包围框最低点不必是完整接触线；去除透明留白、阴影干扰后，在实际317×296显示和既定位置核对盒底的可见拐点及接触轮廓。台面深度应容纳合理的盒底占地，近侧／远侧承托边与盒底的前后遮挡应成立，不能只有一个角贴住，其他底边仍悬空或陷入台阶。不要以阴影、光圈、挡板遮住这些错误。

样张阶段先用本套轻量盒体锁定上述视角与落点，再制作背景中的承托；不增加三套正式盒体输出。选中后正式blind.art继承同一视角、轮廓和V1落点。若正式盒体无意偏离样张，先修复盒体到已选设计；若它符合已选设计而背景失配，保持盒体文件和位置，局部编辑承托面的视角、深度和接触高度。用户明确认可或要求保留的盒体直接作为基准，不重抽来迁就错误背景。几何成立后才恢复接触暗部、投射及反射，背景仍独立于盒体，不把盒子烘焙进去。

正式阶段每次局部编辑后立即按原V1坐标叠回同一盒体；候选阶段同轮修改合并回填一次，纳入该套集中检查。在真实1920px浏览器同时检查完整盲盒模块和包含完整盒底、台面前后边的清楚局部；只看空背景或裁掉接触区域不能验收。将视角、台面深度与占地结果写入现有support.observation，盒底贴合、缝隙／穿插与遮挡结果写入contact.observation，光影写入lighting.observation。空间不成立时support／contact记revise，即使阴影漂亮也不能通过；现有脚本仅检查证据结构，不能证明透视正确。按既有有界返修规则处理，不新增用户审批或证据字段、不重生整页背景。

### 从样张记录连接方式

在现有design/analysis.md的归属记录中标出实际采用的连接方式：光照方向与软硬、局部明暗／色温、透视和所处平面、纹理尺度、边缘与环境交界、接触及投射光影、前后遮挡与奖品压边。记录来自样张和KV的可见依据，不为每张底板强制添加这些效果；平面设计可通过图形延续、叠层与色面关系连接，不强加实体接触阴影。底板与背景可以不同材质、不同明度，验收看这些差异是否维持已确认组合的承托与主次，不要求两层纹理完全相同。

### 整体关系先于局部效果

融合不是单件漂亮、颜色统一或光影齐全的总和。先在同尺度的确认样张与最终布局组合里核对以下实际关系：主体／承托／环境的面积与留白、镜头及透视、背景前中后层次或平面叠层、表面与纹理尺度、形状及方向的延续、交界处的承接与遮挡、视觉重心和主次节奏。元素与光影是其中的组成部分，不能用“补了阴影／装饰”替代整体协调。按本次媒介选择有依据的关系，不强迫每种主题具备全部结构。

尺寸适配须联动修改相关环境：主体和承托缩小后，原有承接位置、平面深度、图形延续及留白不能留在旧坐标；不要只把小底板贴到原来的大空景。先说明哪些关系必须保留、哪些位置因规格需要改变，再在同一组合中解决。无法在既定尺寸下继承时，修复该组合的构图与连接，不能以尺寸已符合为由接受各层各自成立、整组脱节。

组合工作母版也必须对照确认样张验收后才能拆层：如果它本身已经丢失环境承接、把连续结构变成孤立面板，即使随后拆分与回填完全一致仍是失败。对照须分别说明“样张→组合适配”和“组合适配→正式回填”的变化；只证明后半段一致无法证明忠实还原。关键关系未恢复时继续修复同一已选方案，不自动生成新候选，也不靠追加灯光、模糊边缘、统一纹理或背景烘焙合图掩盖问题。

### 先完成空间结构，再从同一组合拆层

先判断样张里的承托实际是什么：场景连接的局部空间结构、平面图形的连续叠层，还是有意独立的面板。前两类不能在拆分时变成一个新面板；后一类也不强行做成场景地台。判断依据是完整样张里的几何关系与使用效果，不只依据颜色、纹理或独立PNG角色名。场景式承托的竖面、弯折、承载面和环境连接共同构成结构，平面式承托的延续形状与遮挡共同构成结构；仅当样张实际采用时才保留，不为其他主题新增。

1. **先在最终布局建立组合基准。** 以已确认样张的对应完整模块为主要视觉输入，先适配该模块的既定主体位置、承托规格与排列，完成背景与承托的实际组合结构，再拆分。退化的成品只能提供最终坐标／尺寸和已认可单件，不能代替确认样张成为视觉基准；否则会把已有贴片感、空间断开和构图损失继续保留下来。盲盒按动态底板与奖品布局，任务按条内按钮位置，其他模块按各自规格，不相互套用。记录连接位置、承载／接触线、折转或图形转折、边缘、透视、光照及遮挡所在的模块坐标。样张中已成立的连接不能只因组件中心或位置校正而断开；在同一组合内协调承托及背景连接，不只挪动独立PNG。用户认可的主体直接沿用，不重新生成；盲盒包裹与同中心仅用于该模块的对称包裹框。
2. **两层来自同一已成立组合。** 在现有design目录保留最终布局下的组合工作母版及必要的干净背景／承托工作图，并记录现有来源链；不覆盖冻结的确认样张，不作为新增候选图。先保留上述结构与连接，再按本模块的既有角色制作配对层；例如blind.background（含底框）与blind.art、task.row与task.button，不能强制所有承托都单独输出。场景与组级舞台仍归背景；盲盒局部底框并入blind.background，其余有独立交付职责的衬板仍独立；拆分边界是文件边界，不是新绘制的一圈装饰边。承托不退成重新设计的通用面板，背景不改成与原组合无关的底景。
3. **拆层采用隔离与遮挡补全，避免各自重新抽图。** 从组合实际图像编辑各自所属内容，背景只补全被移出层遮挡的区域，底板保留自身完整曲面／折转／边缘或图形结构及必要的连接细节。不能将补全目标误写成让整个环境铺满同一种纹理，也不能将原有空间、曲线或图形承托归纳成一张通用矩形底图；具体保留哪些结构取决于本次样张。局部结构跨归属层时在共同坐标中分别承接，原有连续关系不能因去背而被裁断；盲盒底框与环境可共同保留在blind.background，但不能把盒体、奖品或按钮也烘焙进去；其他对象按各自分层职责处理。确需重新制作时以完整组合和配对层作为实际图片输入，只编辑目标问题，每次回填验证。
4. **在共同坐标中立即重组。** 两层导出后即按组合基准的位置、比例和遮挡顺序回填，在相同尺寸比较基准与重组，先验证相关背景／承托层，再恢复本模块主体、内容及操作验证最终组合；盲盒恢复盒体和奖品，其他模块恢复各自卡片、任务文字或礼包等。纹理与材质相似不能代替折转、承载、接触及空间／图形连接相同。连接断开时返回这对层及其交界修复，不用移动盒体、拉伸底板、扩大亮面或补通用阴影遮盖结构变化。适配尺寸后需同步更新配对层与定位，不能只缩放底板再贴到未经适配的背景。

盲盒模块的底框入背景、按底板类型验收、奖品压边及V1间距继续适用；对称包裹框仍须完整包裹、同中心且允许零额外余量，其他模块保持各自原有分层和几何规格；这些几何约束不能作为改变承托类型或空间结构的理由。光影按原归属处理：自身高光／明暗随底板，环境上的光影按接收层及真实位置承接；盲盒底框及其环境效果共同保留在背景，主体／排布变化时同步编辑；其他独立底板的关联效果随其显隐／定位，不留残影或重复阴影。不增加正式素材角色，不以通用CSS光圈或默认投影代替母版细节。

边缘依据本次真实材质和图形处理：可以是精确硬边、撕边、柔和轮廓或其他有依据的形式，不统一模糊、羽化、降低透明度或中心镂空；用已有光感、图形与空间承接恢复关系，不以加效果数量作为融合程度。样张本来采用明确面板边界时保留该边界，不擅自将其抹成无边缘背景。

### 光影逐项归属与回填

已确认样张中实际存在的光影是设计内容，不能仅保留物件和纹理。对所有启用模块，在现有元素归属记录中逐项标出可见光影的位置／范围、明暗与软硬、产生对象、接收对象、实际归属文件或页面层、随动关系以及回填结果；只记录本次确有的效果，平面主题无对应光影时不补造。

| 样张中的实际效果 | 制作归属与保留方法 |
| --- | --- |
| 环境照明、整体明暗、背景局部亮面或光束 | 在对应背景／连续母背景中保留原有分布、方向、色温和衰减；移除组件仅补目标遮挡处，不以抹平曝光、均匀纹理或统一底色替换环境照明 |
| 物件表面受光、边缘高光、正侧面明暗 | 保留在对应组件自身；尺寸适配与去背不重新改成统一亮度的材质图，不把高光误认为底色或白边抠除 |
| 物件落在衬托面／环境上的接触与投射阴影 | 按最终组合坐标保留在接收层或与主体关联的配套叠层中，保持接触位置、方向、软硬和衰减；不能随物件擦除后无人恢复，也不把整片环境带进组件PNG |
| 层与层的遮挡暗部、反射或局部反光 | 明确与哪两个对象及哪段交界相关，沿同一组合基准恢复；调整位置／尺寸后同步更新，隐藏关联对象时不留固定残影 |
| 平面／插画中原有的明暗叠层或光感图形 | 按实际图形职责保留，不改成写实投影；若样张没有这些处理，沿用精确图形与色面关系，不强加效果 |

**清理物件不等于删除其所有作用。** 底图移出某主体时，记录并转交其阴影／反光等交互效果；最终组合必须恢复。隔离检查中的“无主体残影”指不应保留的物件形状／重复图像，不是将环境亮面、真实接触阴影或遮挡暗部一并清空。光影需要随主体显隐时按对应层处理，不因单独看背景希望完全干净而让最终场景失去作用。若现有素材分配暂不能承接，记录缺失并修复分层或准确实现该设计，不能直接删掉后称还原；保持既有素材角色，不用默认CSS投影、统一渐变或整页调亮来代替具体光影。

拆分后在相同页面宽度、相同显示条件下并列核对“确认样张→最终布局组合基准→正式层回填”：样张到基准就丢光时修复制作／尺寸适配，基准到独立层丢光时修复去背／补全／归属，素材齐全但浏览器不见时检查引用、透明度、滤镜、混合、遮挡及层级。逐项指出每处原有亮暗处理在成品的位置，不以配色、来源链、某个高光仍在或物件精致代表全部保留。

样张具有实体压接时，在真实显示尺寸核对主体可见接触边与接收面：紧邻接触处的暗部、向外衰减的投影及周边受光应共同恢复其重量感。阴影文件存在、坐标随动或部分暗部被主体盖住都不能证明压接成立；不可仅按透明画布中心摆一片软影。箱底／物件下缘与暗部出现亮缝、暗部偏离、全部被遮挡而看不见，或最终压接明显弱于样张时，返修轮廓注册、层级或强度后再看实际组合；不强加给原本没有实体接触的平面主题。

检查光影承担的主次关系与空间／图形作用，而不是只比较全图平均亮度；可以适配尺寸与位置，但不能将样张局部受光、接触暗部及景深层次整体抹平。沿现有对照证据记录缺失区域与修复结果；关键光影缺失或明显变弱导致承托关系退化时，background_design、component_craft或export_fidelity对应项须记revise，实际回填复查后才能交付。以上为通用制作与验收方法，不把本次灯光方向、强度、材质或具体阴影固定为模板。

### 样张的明暗气氛与前景层级继承

**保留的是本次确认样张的明暗与视觉重心，不是所有活动一律压暗。** 暗色、明亮、摄影、三维、插画和平面主题都按各自样张建立基准；背景应以样张已经成立的方式承托卡片、主体和操作。物件、配色、材质齐全，不代表气氛和前景突出程度已经保留。

制作正式背景前，从已确认样张记录各启用模块的具体关系，放入现有 design/analysis.md 元素／画风记录：

- 大面积暗部、中间调与亮面的分布、面积关系及过渡软硬；区分有意压低的背景与不可丢失的可见细节。
- 光源位置、亮面尺度、反射／雾感、远近虚实及纹理对比；微小灯光或地面反光不能在拆分后扩成大面积亮地面，原有安静区域不能变成清楚而高对比的满屏纹理。
- 标题、卡片、主体和主按钮与其紧邻底景的明暗／色彩关系及轮廓辨识；记录背景在哪处退后、重点在哪处突出，不只写“深色”“高级”“有氛围”。

背景编辑以确认样张或已经对照通过的最终组合基准为实际图片输入，将上述关系写成具体空间约束。移除卡片、盒体和文案时，只补其遮挡区域，延续附近实际色面、明暗和纹理尺度；不因需要看清空背景而提升曝光、抬高暗部、强化反射或锐化整片底景。工具支持局部遮罩时限定实际需编辑区域；不支持时仍限定目标变化，并检查未要求修改的外露背景有无漂移。提示词已写保留气氛也不能豁免生成后的对照。

每次正式背景生成或影响光影的编辑后，先将所选样张与正式背景按同宽、对应模块和实际布局位置对齐查看。挑选两者都未被前景遮挡的墙面、地面、色块、边缘或其他代表性区域，核对黑位／底色、中间调、亮面面积、局部对比和纹理密度；不要用整页平均亮度判断，因为移除白卡、黄色按钮或深色盒体本身会改变统计和观感。前景曾遮挡的区域对照周围真实底景与完整组合基准，不能编造原样张不可见的细节或亮度。像素统计只用于定位变化，不能代替视觉判断，也不设跨所有主题的固定亮度阈值。

随后必须叠回本次实际标题、卡片、主体、奖品和按钮，按最终V1显示尺寸与原有光影及布局恢复完整组合，再与确认样张同尺度比较。纯背景用于查漂移，恢复前景用于判断突出程度；两项都通过才继续导出或交付。重点检查背景亮面与纹理有没有与卡片／主体竞争、主体轮廓是否清楚、局部接触及空间／图形关系是否仍成立，不能凭空背景细节漂亮或颜色相近写通过。

发现暗部抬起、亮地面扩大、纹理过强、背景失去虚实或前景层级变弱时，在共同母图内只修复漂移区域的明暗、亮面尺度、局部对比及必要光影，保留原有场景、材质、前景与已确认的分区差异。重新回填、对照通过后，再从修好的母图原像素导出。不要通过全页黑色蒙层、统一降低背景透明度／亮度、增强全部对比或额外发光让画面暂时显得更突出；这些方法容易破坏样张的局部层次，且不能用CSS掩盖母图漂移。

按模块区分仍须保留每对相邻区明显的大面积底色／明度差异，这一要求与样张气氛同时成立；可以在样张设计阶段按KV配色建立明显的深浅色面分区，不能在选定后擅自将原场景提高曝光来假装分区，也不能为恢复气氛把所有模块压成同一种暗底；已确认的浅色／强调色模块应保留。分割线仍按实际样张选择，不能用它替代色面层级。

沿现有 background_comparison、component_comparison 和最终整页证据保存“确认样张 → 正式背景／组合基准 → 实际回填”的明暗与前景层级对照，覆盖所有启用模块；不增加候选样张或额外审批。在 background_design、color_hierarchy、export_fidelity 的观察中写出实际漂移区域、恢复方法及回填结果；任何关键关系未恢复则记revise。几何、来源与切片校验通过不能代替气氛验收，校验器不能自动判断审美或观察是否真实。

### 隔离通过后还须组合通过

按既有深浅底色与隐藏各层检查独立文件职责，再恢复本模块背景、原有承托、主体、内容及操作，在实际显示尺寸与整页缩览中对照已确认的完整组合。保存组合工作基准与拆层重组的同尺度对照，能直接看清承托类型、环境连接和转折是否保留；最终验收须包含本模块完整主体与内容；盲盒须包含盒体，不能用空底板加背景的截图代替，可临时隐藏对应主体辅助检查遮挡，但恢复完整组合后再下结论。

核对底板是否仍处于样张中的空间／图形层级，边缘、明暗、纹理尺度、环境承接和遮挡是否成立；检查悬浮、贴片感、突兀亮板、接触脱离、光照矛盾、局部透视失配及尺寸适配后的环境断开。单层有质感、配色相同、包裹和透明度通过，都不能抵消组合关系退化。只修复失配层和它的必要交界，不随机重做已认可盒体或整页风格。

沿现有component_comparison与background_comparison保存样张组合、相关独立层及真实回填的清楚对照；在component_craft、background_design和export_fidelity的实际观察中记录采用的连接方法、保留情况与修正结果。样张融合成立而最终变成孤立贴片、原有落地／折转／图形连接消失，或承托类型被改为新面板时记revise，明确指出丢失的结构与修复位置，修复后重新回填查看再交付；来源链、相似材质与包裹报告通过不能豁免。该检查不增加A／B／C候选或额外审批；确需改变已确认设计仍按原改稿流程确认。机械校验无法判断视觉融合，不能仅凭独立文件与来源记录就写pass。

## 样张到成品的设计保留

**此规则适用于所有活动主题、品牌和表现方式。** 保留对象来自本次实际确认的样张，按设计职责核对背景组织、图形／场景、肌理、光影、组件结构、承托和装饰；不要求每张页面都有这些类别。文中景物、花草或云层只说明可见元素如何被遗漏，不是通用素材清单。摄影、三维、插画、平面或其他风格均沿用本次样张自己的内容与完成度，不固定春日、游戏或任何历史案例的具体元素。

**规格适配与设计保留分别验收。** 套餐、标题、盲盒、按钮和任务等按既有V1输出／显示尺寸适配是正常制作；不要求成品与概念样张每个物件像素大小、位置完全相同，也不为保持概念图大小擅自突破固定规格。记录必要的尺寸、间距及布局适配，在允许调整中保留母版的具体造型、图形层次、承托关系、表面、光影和细节。尺寸变化本身不判失败，但不能以尺寸正确解释其他设计丢失，也不能用放大控件补偿背景或装饰缺失。

### 先记录每个可见元素的去向

选定母版后，先按[背景承托与组件的分层归属](#背景承托与组件的分层归属)确定职责，在本次`design/analysis.md`记录其各模块的可见设计元素、所在区域、归属层、目标文件、遮挡／随动关系与回填情况。覆盖背景场景／图形、肌理和光影层、章节转场、标题配套图形、卡片表面及边缘、局部底板和承托、按钮细节，以及样张中实际采用的独立装饰。每项对应正式背景中的区域、独立素材文件或实际HTML／CSS位置；拆分后逐项核对“已保留”“按规格适配”或“缺失待补”。这份记录用于防止遗漏，不扩大交付素材角色、不增加样张或审批数量。

样张中已出现并获确认的装饰属于成品设计，不能因“装饰可选”“少量使用”而全部删掉，也不能只放进`decorations/`后不回填页面。额外交付、未在样张中使用的装饰仍可保持可选。连续景物、地形、云层、肌理等属于背景设计；需要自由摆放的物件作为独立透明PNG。按实际职责分层，不因某个花草、光影或承托细节没有现成业务素材角色就丢弃，也不将业务控件和文字烘焙进背景。

### 拆分继承设计，清理只处理目标区域

提取、编辑和分层重建均以所选母版的完整模块与对应局部实际图片为输入，针对尺寸、透明边缘、文案和遮挡作必要处理，不只拿母版分析出的几个色号从零重画。背景移除控件时按归属仅移出前景／文字目标层并补全原有底景，保留应属背景的场景、纹理、曲线、光影和叠层；盲盒底框留在blind.background；其他有独立交付职责的底板、组件内部名称承托及独立装饰转入各自素材，不为保留细节而重复烘焙进背景或主体。不能大面积盖纯色、整区模糊或改成普通渐变，也不能在隔离时把应移交其他层的设计直接删掉。

按规格缩放后仍要检查实际显示下的表面与边缘完成度；需要高清制作时以母版编辑或延展保持细节，不借高清重制另换设计。素材文件已存在但页面漏引用、被裁切、层级错误、被其他背景覆盖或全透明，同样算丢失，须在实际页面恢复。某项无法可靠重建时如实标记问题并继续修复，不悄悄删除后称为已还原；确需改变可见设计时按既有选定方案改稿流程确认。

### 背景沿母版扩展，再按模块切片

整体衔接沿已选样张的场景、色面、肌理、边缘曲线及上下关系制作覆盖头图到页尾的完整连续母背景。为适配模块高度可在同一母图内延展或调整留白，不能逐区新画一套简化底景再拼接，也不能将母版中有云层、景物或叠层的区域改成空色面。先确认完整背景保留了上述元素，再按全页累计坐标切片。切片来源一致只证明切片正确，若母背景本身已经偏离样张或在模块边界画成硬截口仍须返工。按[跨边界构图与逐缝验收](v1-layout.md#跨边界构图与逐缝验收)让转场形状跨切片坐标自然延续，对照样张、正式母图与真实浏览器定位问题，并为所有内部边界保留浏览器截图和实际观察结果；不能用首条接缝通过代表其余交界通过。按模块区分则保留已确认的独立章节、转场及明显底色差异；允许颜色切换但不允许图形截断，按[两种模式的跨界组合与导出](v1-layout.md#两种模式的跨界组合与导出)先在共同坐标中完成最终组合母图，再原像素导出并检查全部真实浏览器交界。不能把两张有断口的图合成母图后仅凭同源校验通过。

### 选定后的前景精修

用户选择的是设计方向与整页关系，不代表轻量示意中的每件前景已经达到成品完成度。正式制作前在现有analysis简记“仍欠完成度的对象／实际缺口／准备补足的方法”；已完成的对象可直接沿用，但须实际查看，不能把所有示意件一律判为无需精修。背景继续复用已选实际文件，不将本节解释为重画背景的许可。

沿所选样张的主轮廓、信息层级、相对位置、配色与媒介，补足有作用的边缘工艺、表面层次、结构收口、局部光影及所需状态；具体做法由本次KV和相容参考决定，不要求每件增加金属、厚框、噪点或装饰。卡片文字区保持连续，任务条三行容量、奖品实图空间和按钮位置不因精修改变。不能只插值放大、描一圈线、去字或切下示意件就称完成，也不能借精修换款、改主要造型、整体曝光或已选构图。

在现有最终component_comparison内用同尺度代表卡片、按钮及其它实际欠缺对象对照示意和成品，观察具体补足了什么、正常显示下是否成立；有不足写revise，只返修该对象及必要邻接。已精致的简洁设计不为证明精修而加效果，粗糙设计也不因“简洁”“无字交付”或已有尺寸而放行。只有完成精修与回填验收的素材才进入冻结、复用及整理；此检查并入现有正式阶段，不追加三套生产、证明图或用户审批。

### 所有素材的有效画布

从示意到正式回填，区分文件画布、主要可见主体、内部内容承托区。画布尺寸正确不能证明主体大小合适；只靠孤立尖角、装饰或低透明光晕占满，也不能证明主要底板足够大。检查适用于全部启用素材，复用现有实际比例预览及component_comparison，不另开专项生图或重复检查。

- 卡片、奖品底图、任务条、按钮及必要状态：减少无用途的外围透明空边，主要底板按预定显示区设计；异形切角及抗锯齿可局部透明。保持内部文字、图片区和按钮承托空间，不能靠厚框撑满后将内容挤小。
- 盲盒、奖品实图、图标和独立装饰：按有意义的可见主体等比适配，清除无内容外围；保留完整轮廓和必要自身光效，不为贴满固定宽高拉伸、裁坏或补假像素。背景侧投影与环境衬光仍按分层规则归背景，不用于撑大盒体画布。
- 标题：按V1统一母版、同级字面高度和完整配套图形显示；短标题在统一画布中的有意留白不算无用空边，不独立裁紧各标题导致字号与居中关系改变。字效和完整字形不能为填满而拉伸或裁切。
- 背景与头图：按实际切片矩形完整覆盖，不带无用途透明条；仍从共同母图原像素导出，头图保护区不动。

先看alpha及实际主体边界，再把真实文字、图片和按钮按固定布局叠回；不透明底图同样看主要底板，不能只查alpha。可变画布按内容合理紧边导出，固定画布在制作源调整无字外壳或按原设计局部扩展；不裁去空边后非等比拉伸整张位图，不缩字、挪按钮迁就内缩底板。同组状态共用画布及主体位置，不能各自裁边造成切换跳动。自然物件比例与固定槽位冲突时保留比例、明确记录，不伪称必须同时左右上下贴边。

### 用相同尺度检查缺失，允许合理尺寸差异

将所选样张和真实1920px浏览器成品按相同页面宽度并列查看，再以实际显示尺寸查看对应模块局部；不通过单独拉伸某一张图掩盖缺失。逐项核对上面的元素记录，重点查看大面积背景层次、景物与主题图形、底板／承托、卡片和按钮细节、页面实际采用的装饰、各相邻背景接续。按规格变小的按钮或卡片可以通过，其周围装饰和背景消失、纹理变空、底板被简化、接缝断裂不能通过。

沿用现有`component_comparison`与`background_comparison`保存对照，不额外生成候选样张。`export_fidelity.observation`写明允许的尺寸适配、各类元素是否保留、发现及修复的遗漏；`background_design.observation`写明母版背景保留和每条转场／接缝结果。任何已确认的重要元素缺失或接缝问题未解决时记`revise`，补回设计并重新截图后才能交付；同配色、尺寸和来源链检查通过不能代替这项验收。

## 单件素材的设计与质感

本节是适用于不同主题、品牌和画风的通用组件制作方法。新活动或新KV先分析品牌字形、媒介分工、颜色关系和信息需求，搜索近期相容的真实组件参考，再重新确定轮廓、边缘、表面及排版；不默认继承上次活动的任何控件、材质或视觉路线。“质感”按当前参考理解，落实为可辨的表面与边缘处理、图形叠层和精确排版；可采用有依据的肌理、局部明暗、印刷感、插画笔触或体积表现，也可采用精致的平面图形层次，不预设统一效果。纯色只是局部底色，不能单靠色块填充或排字完成整件素材。

只有同一活动中用户已认可背景与配色、此次只要求加强前景时，才以该版本作为局部迭代基准，保留已认可的背景、色彩关系与布局，针对卡片、按钮、任务条或底框改进。不能为了体现变化重新换整页风格；本次认可的具体颜色和材质也不固化为其他活动的默认答案。

### 保留已认可素材，按对象改进

同一活动返工先在本次分析记录“明确认可并保留的对象／文件”和“本次需要修改的对象／问题”，范围来自实际用户反馈，不自行把整页判为认可。用户说原先盲盒不错、卡片按钮需要改善时，保留对应盲盒主体原素材及其完成设计，只对被指出的组件补充参考和改进；用户未要求修改的已认可背景、配色或布局也按既有局部迭代规则保留。若无法确定被认可的是哪个文件或版本，先核对历史记录，仍缺时才请求用户定位，不按印象重画后声称保留。

保留的主体不参与随机重新生成，直接在方案中沿用原素材，位置、显示尺寸与本次布局核对；不为统一风格抹去盒盖、封装、识别图形、表面、层次或已认可的光影。需要调整主体时应有对应用户需求，并以原素材编辑具体问题。重做整页且用户仍明确要求保留该主体时，新的三套方案均围绕它设计；不能三套各抽一个更简化盒体。

“控件不照搬实体物件材质”只约束卡片、按钮等UI的设计依据，不要求实体主视觉改成平面控件；“协调”看媒介分工与制作精度，不把已完成主体降级去迁就基础组件。卡片、按钮、任务继续达到相容专业参考的表面、结构与排版完成度，保持各类独立边缘，不退成填充矩形。

返工对照用户认可的原对象、当前方案和待改组件，在真实显示尺寸检查已认可对象是否保留、待改对象是否实际改善。任何保留对象被无意替换或简化都记录`revise`；不以新配色、新参考或“全套统一”解释退化。素材来源记录继续引用原文件或其无设计变化的处理链。仅维护skill时不自动生成图片；样张仍按既有数量与确认流程执行。

### 轻量样张的信息层级

轻量指减少正式资产与状态的生产量，不减少可判断设计的排版。样张阶段就用本次提供的真实名称、价格、权益、奖品与任务文案；缺失时沿用授权占位，不编造价格或利益。套餐以名称、权益、价格、主行动的阅读关系排版，字级、间距、对比与重点随KV及内容确定，不能每行使用相同大小的“待配置”后据此评价卡片设计。

奖品有实图时按真实可见范围回填；只有占位时明确实图未验收，不能把占位字的小尺寸误认成奖品太小，也不能用巨大外框假装实图饱满。任务按名称1行加说明最多2行核对安全区和按钮关系。先检查信息层级与实际可见尺寸，再判断是否需要增加装饰；维持单件质感门槛，不把“轻量”解释为默认框或粗糙控件。最终素材仍分层，业务文字保持可编辑，选中后回填同一排版验收。

### 组件完成度不能由背景代替

风格协调与设计完成度分别判断。同色、同气质只能说明协调，仍须与本次实际选择的专业组件参考及已确认母版对照信息层级、形态与内容关系、表面和边缘精度。背景、KV或盲盒精致不能抵消卡片停在草图水平。平面组件可与立体主体搭配，不要求材质相同、全部立体或细节同样密集；要达到相容参考的制作精度，辅助组件保持自己的主次力度。

**保留单件完成度门槛，不默认减少细节。** 每件启用的卡片、按钮、任务条和局部底板从本次KV与实际看清的相容组件参考确定细节形式、位置与强度，并写明应用区域、正常显示下的尺度、对比和文字避让。套用默认矩形、随意渐变或细描边，再放上缺少层级的文字，仍属于简陋素材；只有上下色块拼接也不能算完成。不能用“平面”“克制”“单色KV”作为放行理由，也不能因为用户手工稿中有简洁组件就降低本次参考的制作精度。

参考与本次设计方向确需硬朗结构、金属层次或战术质感时，须落实相应结构、材质与边缘精度，不能统一降成普通扁平控件；这些只是条件示例，不因活动属于游戏就自动套用金属或战术风格。细腻肌理、纸张／印刷叠层、插画笔触、精确图形交界等同样按实际依据选择。细节优先用于轮廓、边缘、局部表面及主题识别处，文字区保留连续可读的排版空间，不靠铺满噪点、加厚外框或堆装饰证明完成度。

生成前逐类提取对应真实参考中有作用的设计决定，明确它在本件哪个区域成立，并写入本套工作组件的生成／编辑指令与预览布局。不能只写外框颜色、切角位置和大致填充，再把信息排版交给默认控件；也不以机械增加装饰数量代替设计。三套方案各用最终背景与轻量前景示意在浏览器拼成一张整页样张，组件检查取自实际文件及页面局部，不新增用户候选。

- **套餐是售卖信息设计。** 名称建立识别，权益便于阅读，价格通过字级、字重和文字颜色形成强调，不在上方新增突兀价格色块，购买承托自然收束；字级、字重、间距、对齐和色面比例共同完成层级。内容未定时仍为对应“待配置”文字设计这些关系，不把名称、权益、价格排成同字号同重量的字段清单。没有用户提供或确认的套餐展示图时，不默认增加大型“图片待配置”框占据卡片主要区域；套餐承托与排版本身完成设计，不编造权益、价格、等级或优惠。
- **奖品是展示与名称的组合。** 保留既定上图下名关系，但不强制封闭厚框；可依据KV与参考采用气泡承托、独立名称条、轻卡片或开放式排布。图片区、名称区域及透明留白共同设计，实物奖品为视觉内容，边框不挤小实图或成为主角。缺实图时继续明确占位，不编造奖品；占位说明克制，沿用卡片自身的展示承托，不能让通用灰色图片框覆盖整个已设计图片区，也不能只有上下两个色块便称完成。
- **按钮是完成的行动控件。** 保留对应参考有依据的轮廓比例、色面及边缘关系和文字重量；购买、抽奖、任务与辅助入口按功能分别设计。平面表达也须完成参考中可见的表面和边缘层次，不能把“使用主色填充”作为完整按钮设计，也不能在详细母版上用默认纯色矩形替换表面。层次由轮廓与面、细节尺度和文案共同建立，不默认增加厚金属、磨损、强光或复杂描边。
- **任务条是阅读与行动的组合。** 名称、条件、奖励和右侧按钮按真实功能成组，以字级、间距、留白及独立按钮完成设计，不新增右侧包裹色块；不将字段平均铺在长色块上。保持主体在底景上清楚、按钮右距32px、用户名与次数无底框，各类边缘独立设计。

**单件质量与整页主次都须通过。** 先在正常显示尺寸对照本次相容组件参考，临时忽略奖品实图、盲盒和背景的强视觉，检查组件的信息层级、比例、主题联系、表面与边缘精度，指出实际采用及丢失的设计；不能只凭颜色相近、导出清晰或默认框里填了文字通过。再恢复整页，检查各组件的视觉重量是否符合功能，辅助控件不抢标题、奖品和盲盒的重点，主行动仍突出。单件简陋时完善缺失的结构、材质或排版；单件精致但整页抢眼时，只调整失衡处的细节强度、面积或对比，保留有作用的设计，不统一扁平化或清空细节。轻量样张与正式回填均执行，不因内容待配置或选中后精做而降低门槛；不新增用户审批。

拆分和回填时保持母版的内部结构与表面。工作阶段需要更换文字或校正画布时使用保留设计的编辑、分层重建或精确实现；选中后只为该方案精细生成前景并对照示意；最终验收后直接复用冻结文件，返修先回到工作版本重新预览，不用纯色盖片掩盖旧字、用色块拼按钮中段或套默认占位区破坏层次；明确为可伸缩控件设计的平坦文字区可准确实现，但须在实际尺寸证明完整轮廓、表面和衔接与母版一致。结构变化按既有改稿确认执行；失败按当前三套样张与用户反馈流程处理，不自动加候选、不提前整理正式交付。

### 套餐卡的连续文案区

套餐卡首先服务于用户后续自行排入较多名称、权益和价格信息。默认使用一块连续、明暗稳定的主底面；根据当前KV和实际设计效果，确有需要时最多使用两块明确的背景色面，即主文案面加下方购买区域的一块辅助色面。两块是上限，不是必须做满；不按每个字段分色，不在顶部或中部插入价格带、徽章、嵌套面板、独立标题色块或第三段填充。细腻肌理、自然明暗和外轮廓描边不按颜色数量机械计数，但形成明显独立栏位的亮带／面板属于分区，不能借装饰之名绕过限制。

如采用第二块色面，只能靠下安排在购买按钮附近，按按钮位置和实际信息量决定范围，不横穿名称、权益、价格的正文区，也不默认占卡片一半或居中插入横带。购买按钮继续独立PNG，不将其实体或文案烘焙进底图；没有辅助色面同样可以完成设计，不为追求层次强行添加。

在既定尺寸中先排实际文案或授权占位，按[异形底图的文字安全区](v1-layout.md#异形底图的文字安全区)保留足够的连续排版空间，再在外围设计与KV相容的轮廓、边缘和细腻表面。信息层级由字体、字重、间距和文字颜色建立；不能以增加色块、强反光或厚装饰补设计，也不为图形缩小正文。验收同时看空底图是否能容纳后续文案，以及真实长文案回填是否仍可读；移除文字和独立按钮后，主面应连续，最多仅下部另有一块辅助色面。该限制针对套餐卡底图，不改变奖品卡既定上图下名结构，也不改变模块之间必需的底色差异。

### 组件参考与完成设计

参考按[对象与用途](planning-and-references.md#参考对象与用途)选择：整页可指导全局组合，模块可指导局部关系，清楚的组件可直接指导单件制作；不要求先取得完整页面才允许使用模块或组件。分别检查本次启用的卡片、按钮、任务条与底框是否有看得清的真实界面参考；参考应能说明轮廓转折、边缘处理、表面层次及文字承托，而不只是相似配色。优先从本次已选的相容页面取局部，缺少有效细节再按当前KV补搜近期案例；不把KV中的人物、实体物件照片或精致主视觉素材代替控件参考，也不让不同组件各自照搬不相容的案例。

各类组件依据[整页协调规则](#整页协调规则)保持整体联系，轮廓、边缘及信息结构分别设计；正式拆分各自继承所选母版中的对应组件，不互相套用边缘。为每类实际启用组件写一个完成设计简报：信息怎样分组，轮廓与边缘采用哪种处理，表面是平面色面、细微肌理还是有依据的光影，哪个局部强调功能，放在当前背景上怎样分离。每项方法指出参考区域，不只写“高级、有质感、精致”。有细节的参考不能在制作时被简化为空矩形加一条描边。

质感来自结构和细节的准确配合：线条粗细与边缘转折有节奏，面与边的关系清楚，表面细节和局部明暗协调，文字区与强调区自然衔接，透明边缘干净。生成输入正向写出参考中可见的表面、图形叠层与边缘如何制作，不只规定颜色和填充。按参考选择需要的表现，不机械叠满渐变、内外框、阴影或纹理；精致平面也须呈现经过设计的图形交界、表面或边缘层次，不退成普通色块。具体处理适配本次KV，不强迫写实、金属、发光或立体，也不因照片中有磨损就给所有按钮加划痕。

表中的失败表现结合当前KV、相容参考与实际内容判断。简单不能自动通过，也不能仅因没有复杂效果而判失败：简洁组件仍须有明确的字级、比例、边缘处理、强调色职责与主题联系，并达到对应参考的制作精度；默认矩形或普通渐变加文字、没有这些具体设计依据的组件继续判为未完成。复杂组件同样检查细节是否准确且服务功能，不按效果或装饰数量评分。设计重心仍是内容与行动，不靠无意义文字、图标或等级标签补精致感。所有改进在V1固定画布、文字分层和布局内完成，不能通过放大控件、增加套餐或改变任务间距补设计。

### 任务条与按钮的成套制作

任务条和按钮通过与KV相容的材质、轮廓气质、视觉重量及排版协调，分别输出task.row和task.button。任务条是一块连续的信息底面，自然延续到右侧独立按钮下方；不为按钮另画包裹色块、斜切行动面板、按钮槽、外框、底座或第二个按钮轮廓，也不在CSS、模块背景或装饰层补回这些形状。按钮自身的正常边缘、质感和轻微阴影可保留，不延伸成包住按钮的第二层容器。

选取能看清任务信息和操作关系的真实组件参考，具体借鉴文字排布、间距、轮廓和表面完成度；即使参考带按钮槽，也不沿用这部分。按[任务条的连续文案区](v1-layout.md#任务条的连续文案区)保留自由排版的文字区，不画固定列线或用色块切成左右两块。右侧操作已由独立按钮表达，不用再加一层底图强调。连续或单色底面不因没有额外分区判定为缺少设计，完成度由真实轮廓、表面、间距、阅读与KV协调判断。

先按[任务条正文高度与上下留白](v1-layout.md#任务条正文高度与上下留白)在700×120内保证名称1行＋说明2行的三行容量、段间距及行距及上下约14～18px起排净空，检查真实内区而非总画布；内区不足先加厚中段信息面、减薄边层与装饰，简单款已满足时不改变高度。锁定160×60按钮右距32px、top30px的位置，再按[任务按钮位置与底图配合](v1-layout.md#任务按钮位置与底图配合)生成与回填。外围异形和少量端部装饰须避开正文及按钮，不挤压名称和条件行，不移动按钮迁就底图。两种状态保留同套制作精度，已完成只减弱按钮强调并更换文案，不整体淡化任务条。

样张和正式素材都做一次隐藏按钮检查：只看task.row，右侧应是任务条自然延续的底面；若仍看见可被误认为按钮、按钮槽或独立包裹面板的形状，先去掉。恢复按钮后确认只有一处操作视觉、文字安全区充分、整体协调，记录到现有component_craft与export_fidelity。组件局部取自实际样张，不增加候选或用户审批；不能只凭独立PNG或没有按钮文字认定已去除重复按钮形状。

### 先做组件母版，再扩展同组素材

在本次整页设计所用的真实背景上制作包含实际文字或授权占位的组件样张；新活动使用本次拟定的背景，同一活动的局部迭代才使用已认可版本，不要求新活动预先存在旧背景。样张中：各类启用控件先取一个代表，任务包含可操作与已完成状态。优先将参考局部、原组件和改进母版并列，指出保留的识别特征与改进的边缘、表面、分组。样张阶段只做必要前景示意；用户选中后才扩展这一套交付所需的同组工作素材和状态，实际回填验收后直接复用，同组任务允许复用；避免逐件从零生成导致细节失控。

图片输入包括KV的界面／字形依据、清楚的对应组件参考、当前组合母版及相关背景。已经认可背景的局部修改还输入原组件进行编辑，明确保留颜色与布局，修改具体缺陷。提示词正向描述该件的分区、边缘、表面及强调位置，后列必要尺寸与禁用项；不用一串笼统质感词重新抽一套设计。

最终以实际显示尺寸核对组件，放大仅用于检查抗锯齿、透明边缘、断线及裁切；高清素材缩回201×280卡片、160×60按钮、700×120任务条等实际尺寸后，有作用的细节仍应清楚。看不见的装饰不当作改善，细节糊成噪点则调整尺度；若正常尺寸下表面与边缘只剩普通均匀色块，即使放大图里有纹理也不算完成。检查每类组件采用的具体质感是否仍可见，并与本次专业组件参考对照，不能由精致背景或盲盒代为通过。回填文字后检查主体与文字不是两层互不相关的拼贴，主行动清楚、正文安静、各组件精度协调。精致的主体与平面控件可以搭配，但其他控件不能停在占位草图的完成度；浅色、渐变、圆角或直角均须来自本方案的具体设计，不因易实现而自动采用。

在既有`component_comparison`里展示参考局部、组件母版及最终回填；`review.visual_review.checks.component_craft.observation`说明本次各类组件采用的处理、实际改进及仍有的问题。观察分别说明“与整页是否协调”和“相对对应组件参考是否完成设计”，逐类列出信息层级、结构与表面精度的实际结果。若设计只在大图里成立、正式素材又退成空框或色块，或质感妨碍内容阅读，记录`revise`并修正，继续按既有交付门槛执行，不新增形式化打分或用记录代替看图。

## 背景设计直接借鉴参考

背景与标题、卡片一样需要完成设计，不只是为前景选一块底色。从本次实际找到、看清且与KV相容的运营整页、模块或背景设计局部提取肌理及表现形式，并作为真实图片输入；不要只留下颜色和主题词，再自行画成惯用的烟雾、散景、星点或渐变。参考中确有这些表现且与KV相容时仍可使用，问题是无依据地重复模板。

KV决定整页的活动身份、色彩重量、光感及媒介关系；参考可以提供KV中未出现但与之协调的网页底景处理，例如底层肌理、色面组织、局部衬托及章节收口。不能因“KV优先”就把参考删到只剩配色，也不能把KV摄影中的烟雾或景深当作所有模块唯一的背景语言。借鉴处理方法并适配主题，不复制第三方角色、标志或完整成品画面。

### 从完整模块提取背景方法

选择能说明本次背景问题的模块或足够上下文的背景局部；有完整模块时可附其组合与底景局部，没有完整页面不妨碍采用有效背景设计。完整模块用于观察背景与标题、奖励、卡片的关系；局部用于观察细节，不能把奖品光效、卡片材质或标题高亮误作背景。局部优先选未被内容遮挡的位置；不能凭空修补或重新生成一张图后声称它是原参考的纯背景。

| 设计层 | 从参考观察什么 | 本次制作如何落实 |
| --- | --- | --- |
| 底层肌理 | 实际纹理类型、颗粒／纹样的尺寸、疏密、对比和方向；无肌理也如实记录 | 按最终1920px显示尺度适配，保持细节层级；不把原图的低清噪点当肌理，不把细纹理放大成粗糙花纹 |
| 色面与明暗 | 大面积色块、亮暗分布、冷暖面积及过渡方向 | 以KV颜色关系适配，保留参考的视觉重量与分布；不是仅替换几个色号 |
| 图形与叠层 | 开放图形、局部衬底、边缘形态如何支撑内容，层与层之间如何区分 | 围绕本次真实内容组调整位置和比例，不将参考的局部衬托扩成巨大的装饰外框 |
| 光影与虚实 | 亮部、暗部及细节怎样引导视线，哪些位置清晰或模糊 | 保留有作用的分布与虚实节奏，结合KV光感；不无依据地增加强光、粒子或透视舞台 |
| 章节与留白 | 标题前后、内容组周围、模块顶部／底部的密度变化和收口 | 适配已确认模块高度与内容数量；文字位置可低对比但仍有协调底层，不把整区中央统一挖空 |

每个启用背景在分析中写出实际采用的参考区域、关键方法及KV适配，并将这些正向描述用于生图。可以由同一主要参考统筹多个模块，但售卖、抽奖和任务的视觉密度、局部承托与收口按各自内容安排，不把同一张底景换位置重复铺满页面。没有合适的背景依据时补充搜索参考，不用无关装饰填空。

### 背景纹理、装饰与前景的尺度校准

保留背景原有画风、材质和设计丰富度，分别判断重复纹理的颗粒大小与密度、装饰元素的占地，以及前景的可见尺寸。合成预览用于校准比例，不默认降低背景对比、删除装饰、压暗或简化设计；本节不改变模块底色差异、既定素材规格及已认可的构图关系。

生成前把实际页面宽度、模块高度和前景显示位置／尺寸作为布局依据，结合参考描述纹样单元相对卡片的大小、重复疏密与装饰占地，写入现有分析及生成输入；不能只凭空背景铺满后是否饱满来确定尺度。按本次主题判断，不设跨活动通用的缩小倍数、纹理密度或装饰面积阈值，也不让用户另填设计参数。

- **重复纹理：** 网格、网点、三角纹样等单元偏大、重复疏松时，在原有覆盖区域收细单元并增加重复数量，保留材质表现、清晰度、方向和疏密变化；不连带放大覆盖范围或提高对比，不把所有区域均匀加密。正常显示下应形成细腻纹理，不能糊成噪点或产生明显摩尔纹；本来合适的纹理不强制加密。
- **装饰元素：** 几何块、笔刷、主题物件按其构图职责单独校准尺寸、数量和占地；仅修正相对内容过大的部分，保留有作用的大色面、主形状、主题层次及局部装饰力度。不把全部装饰统一缩小，也不通过缩放整张背景来修正图内元素，否则留白与模块交界会一起改变。
- **前景可见尺寸：** 卡片、奖品、按钮显小时，先核对既定显示尺寸、主体实际可见边界、透明留边及组内留白。显示或留边错误先修正；本身比例不合适时按对应V1规格及允许的动态布局规则调整，不擅自放大固定规格、不破坏文字安全区，也不压弱背景来迁就错误的小前景。已认可且尺寸正确的前景保留。
- **页面缩放：** 若原素材比例合适而回填后才偏大，检查容器比例、背景尺寸设置、铺满导致的放大裁切及图片拉伸，先修正实际显示问题；仅当素材内部尺度确实失配时再编辑背景，不将显示错误当成生成失败重画。

样张展示前必须叠入实际尺寸的轻量前景，最终交付再用正式前景复核：正常显示尺寸检查纹样单元、装饰占地和前景可见大小，整页缩览检查构图与模块节奏。明确问题属于纹理、装饰、前景还是显示缩放，局部修正后同时确认原有质感、丰富度和模块衔接仍成立；空背景只用于查素材质量，不能单独通过比例验收。沿用既有有界返修流程，不新增选样或审批环节。

### 背景对照与生成

先以实际看清的模块／底景局部参考、KV和本次布局做组合设计；背景正式出图沿用通过的组合样张，并继续输入相应参考局部，保留底景方法，去除需独立交付的文字及控件。不要去掉前景后把背景重画成另一套简化壁纸。

选择整体衔接时，将参考的方法统筹到从KV头图到页尾的完整连续母背景，在需要处随内容改变密度和承托，再按V1高度切片；不能照搬参考的分块边界造成断缝。选择按模块区分时，每对相邻区必须有明显的大面积底色／明度差异，保持同一活动身份；隐藏前景及忽略小纹理后仍可辨认起止。肌理、图形密度、留白及标题分组只作辅助，不能靠这些或近似色号代替底色差异。明确的色面变化可以独立完成分区，不强制额外收口或线条。需要分割线时按[分块模式的上下分区](art-direction.md#分块模式的上下分区)说明其作用，在样张中确定，拆分沿用。两种模式都不自动要求每章另画场景，也不自动简化为纯色。

验收用两种尺度：在实际显示尺寸看肌理尺度、叠层边缘与文字可读性，在整页缩览看大色面、密度、视觉重心和章节关系。将实际采用的参考模块或真实底景局部、本次正式背景、最终回填模块并列，逐项指出上表方法在哪处成立。临时隐藏本次前景查看纯背景，再恢复内容检查承托，不单凭空背景漂亮或配色相近通过。背景过于凌乱或过于单调时，对照具体差距编辑，保留参考中有效的方法，不一律删细节或追加特效。

## 配色与组件一起设计

配色首先设计视觉重量，而非增加颜色数量。在本次真实底景上排一张带文字的组件总览，包含统一标题、套餐卡与购买按钮、奖品卡、抽奖主体与主行动、任务条及可操作／已完成状态、辅助入口；仅列已启用的组件。

为各组件决定背景承托、信息、识别细节、行动和状态的颜色职责，并记录填充、边缘、局部强调的大致面积及KV依据。对照参考保留有效的冷暖、明暗、饱和度和面积关系，再适配本次KV；不能把KV的一点强调色放大成所有卡片填充、边框及按钮。单色KV可通过明度、虚实、材质、留白和局部对比建立丰富层次，不强行引入其他色相。

检查标题到内容、内容到行动的阅读次序：主行动有明确重点，价格／权益／名称有字级差异，任务状态能分辨，辅助入口清楚且不会都像主行动。统一不等于每件用同一个描边、同一色面和同一饱和度。若组件看起来只是在同一模板上改长宽，即使颜色取自KV仍须调整；若多个强调色竞争，则集中视觉重点。单调时先修正面积与组件结构，不能把更多颜色、粒子或装饰当作补救。

## 提示词保留设计目标

一条提示词按“本件的完成设计 → KV适配 → 与邻近内容的关系 → 必要制作约束”组织：

- 完成设计写清参考中要保留的字形、信息分段、可见轮廓、边缘处理、表面层次及配色角色，指出具体参考局部；只写与本件有关的内容。
- KV适配明确品牌／字形气质、媒介分工、颜色面积及光感依据，区分参考方法与第三方角色、标志等不采用的内容。
- 组合关系标出文字、价格、图片区、名称区及按钮的位置，让造型承托真实信息；安全区只约束实际阅读和操作位置，不清空整张卡或模块中心。
- 最后列本件尺寸、透明外部、业务文字分层及确需排除项。固定矩形画布不是可见轮廓参考，不把全页禁用清单重复覆盖每件设计目标。

实际附上KV、相关参考局部及通过的本次母版。能看见参考不代表生图工具收到参考；工具无法使用图片输入时如实说明限制，不能用普通代码框体替代正式设计后宣称已按参考完成。布局代码负责位置与HTML信息排版，正式设计素材保持与母版一致；不得在页面实现时用CSS通用细框、色块或默认字替换已设计的PNG。矢量、排版或程序绘制可用于准确实现有依据的设计，不因为使用代码就判差；不能用基本几何占位冒充最终设计。

## 视觉验收与返工

在组合阶段及最终回填阶段分别实际查看图片，不能只读分析、调用日志或清单。最终检查包括真实浏览器整页、实际显示尺寸的组件局部，以及参考／母版／回填组件的并列图；单独PNG看着精致也不代表放回页面成立。

| 分项 | 通过依据 | 需要返工的表现 |
| --- | --- | --- |
| KV身份 `kv_identity` | 整页色彩重量、媒介关系、光感及字形气质延续KV | 只保留同题材或几个色号，内容区换成另一套氛围 |
| 参考转化 `reference_translation` | 能指出原参考的具体方法在成品哪处成立，并说明必要适配 | 仅背景颜色相近；参考字形、分组或层次在结果中消失 |
| 背景设计 `background_design` | 肌理尺度、色面、叠层、光影与收口采用相容参考的有效方法，回填后承托内容 | 只剩相近配色或惯用壁纸效果；底景细节丢失、过度放大、中央空洞；分块难辨或整体衔接断裂 |
| 组件完成度 `component_craft` | 按单件素材简报及整页协调规则核对轮廓、转角、线条、表面、信息分组及背景关系，在实际尺寸有清楚的完成度；章节标题按正常比例引导内容，功能有区分而整套气质与精度协调 | 参考有明确字形、分组或层次，而成品退成普通字加横线、通用细框空面板或同一组件仅改长宽；边缘粗糙或字效裁切；背景与前景的形态、表面语言互不相容，仅靠同色拼合 |
| 色彩层次 `color_hierarchy` | 颜色职责与面积支持内容及行动层级，状态与辅助入口可辨；回填后保持确认样张的背景明暗、亮面与前景突出程度 | 所有填充与边框同色同强度或多色竞争；背景暗部抬起、亮面扩大或纹理增强，让卡片／主体失去突出程度；用全页压暗代替原有局部层级 |
| 内容组合 `content_composition` | 标题、套餐／奖励、操作与条件成组；留白与实际内容数量相称 | 小卡孤立在巨大空景、信息等大等距、靠无关装饰填空；用占位掩盖结构问题 |
| 拆分一致 `export_fidelity` | 允许按最终规格适配尺寸，逐项保留母版的造型、表面、层次、承托及已确认装饰，素材真实回填且无遗漏，背景承托、独立底板与组件职责正确且不重复烘焙 | 背景舞台并进卡片、底板并进盒体、组件带走环境层；以尺寸适配为由删掉景物、肌理、局部底板或装饰；母版有设计而正式页面退成简化框体；文件存在但漏引用、被裁切或被遮住 |

分割线与模块标题另按[唯一归属与标题避让](v1-layout.md#模块分割线唯一归属与标题避让)逐处核对：background_design 检查原尺寸拼合及纯背景页面中，无线交界未被补线，有线交界只有一次分隔且轮廓接续完整；content_composition 检查恢复独立标题后全部可见部分有净空、没有压线，且内容起点未被挤动；export_fidelity 检查线条没有重复进入相邻素材或页面叠层。对照样张、正式背景与真实回填定位问题，不能因空背景或单件标题各自正常而通过。

任一启用对象出现明显问题，先记录失败处与针对性修正，再编辑对应样张或素材，重新回填并截图；不继续批量生成，不通过添加任意边框、光效或装饰绕过问题。相同问题反复出现时检查参考局部是否清楚、工具是否实际收到附图、正向设计目标是否被通用限制覆盖，以及拆分过程是否丢失母版特征；候选仅在整套剩余修正轮数内改变方法处理，达到上限如实报告，不能借本节无限继续。正式阶段仍须满足交付验收。参考不相容则更换该参考，不放弃KV。

未知奖品图片、价格与条件可以继续使用用户授权的“待配置”，如实说明内容限制；组件结构、标题、色彩和控件设计仍按上述标准检查。全部启用模块均检查，不能只验收最漂亮的抽奖区。少量装饰与简单形状可以通过，依据是有效的设计关系，不按效果数量或复杂度评分。

在`design/design-evidence.json`的`review.visual_review`记录最终浏览器回填检查：

- `stage`固定为`final-render`；`page`指向本次实际浏览器整页截图在`design/`中的副本，对外1920px预览放在唯一正式素材目录旁，制作档案保留证据副本。
- `component_comparison`指向参考局部、设计母版和最终回填组件的并列图，包含本次启用的关键组件与已确认的承托／装饰；按[分层归属验收](#背景承托与组件的分层归属)呈现清楚的独立层及回填对照，区分正常尺寸适配、细节丢失和错误合层。排版可分组，保留能看清细节的分辨率，不用单张空背景代替。
- `background_comparison`指向上节规定的背景并列对照图，覆盖所有启用的内容背景：实际采用的参考模块或底景局部、所选样张的对应背景、本次正式母背景／切片与最终回填；不能只展示首屏或抽奖区，也不能略去样张导致无法判断背景是否被简化。
- `checks`为上表七个英文键组成的对象。每项记录`status`（`pass`或`revise`）、`observation`（实际位置、可见特征与差距）及`evidence`（实际查看的整页或组件对照图片路径）。只有真实查看并成立时才写`pass`，不能照抄通用通过句。
- 总体`status`只有所有分项通过才为`pass`；否则为`revise`。`remaining_issues`为具体问题字符串数组，问题解决后重新查看并更新，不把仍待返工的问题删除以通过校验。授权的内容占位限制写到原有`review.notes`，不冒充设计问题已经解决。

校验器只核对分项完整、证据图片可读及有无待返工结论；缺项、`revise`或未解决问题均阻止完成版文件夹交付。它不能判断页面是否好看或观察是否属实。实际视觉检查先于最终交付，不能为了让脚本通过伪造结论。交付时简述实际保留的参考特点、修正结果和内容占位限制，区分机械校验与视觉判断，不承诺每次生成自动达到某种审美水平。

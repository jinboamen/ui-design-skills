# Photoshop native PSD workflow

Prefer an available purpose-built Photoshop integration. On this Windows machine, when direct app control is unavailable or structured layer editing is needed, use Photoshop's native ExtendScript JSX. This route was verified against Photoshop 2026 and an already-open document; it is independent of mouse automation and can work when the computer-use kernel fails.

1. Identify the intended document from live Photoshop state, not an old screenshot. Write a read-only JSX probe in a writable working folder. Include `#target photoshop`, write UTF-8 status to a unique file, and report `app.documents.length`, document names and relevant layers. Avoid dialogs. Inspect live results before changing anything.
2. Run the script using the installed Photoshop executable, e.g. PowerShell: `Start-Process -FilePath 'C:\Program Files\Adobe\Adobe Photoshop 2026\Photoshop.exe' -ArgumentList '-r','"C:\absolute path\probe.jsx"' -WindowStyle Hidden`. Discover the actual installed executable if this path differs. The command returning successfully only means it was launched: wait for the unique status file and inspect its contents. Report timeouts or script errors honestly. Do not assume COM sees the same running instance.
3. For edits, enumerate nested groups and actual text-layer contents, fonts, bounds and visibility before mapping changes. Work on a duplicate unless the user explicitly requests changing the original. Preserve editable text, original layers, masks, effects and user-requested scope. Never rasterize as a substitute for editable text. Write output to an authorized location without overwriting existing files unexpectedly.
4. For multilingual work, use the user's exact translations and prices. Check glyph coverage and rendering; select a properly licensed free commercial font when needed. Treat each heading, sentence, or price as one typographic unit: use the same appropriate font and actual font variant for its mixed-language text, currency symbol, digits and unit, even across separate layers, unless the user requests otherwise. Size differences may preserve hierarchy, such as a prominent price with a smaller currency and unit. For a heading that should have uniform size, check effective rendered size including each layer's transform, not just the displayed point size. Where the original text was split only to fit, use one editable text layer on one line when the translation fits within the existing decorative boundaries with breathing room; otherwise wrap as needed. A missing translation or slash must be interpreted in context; do not invent copy.
5. Save a layered PSD, reopen or inspect it, verify text and layer editability, and export a visual preview for inspection. Keep the original and user data safe; do not close unsaved documents or disable prompts indiscriminately.

## Required visual review for multilingual PSDs

Review the actual rendered final PSD at full-page scale and at readable close-up scale for every changed section before delivery. Act as a professional designer responsible for the finished visual quality: actively identify and fix any obvious design defects, including issues beyond the examples below. These checks are prompts, not an exhaustive checklist or a substitute for judgment. Look at the composition as a whole, not just layer coordinates or a successful script result. Compare the translated content with the original design and the user's approved direction. Check text correctness, glyph shaping, clipping and font substitution first.

- Check the visual hierarchy and rhythm across the page: sizes, line spacing, relationships between headings, labels, prices and buttons, and consistent spacing among comparable cards. Keep the intended emphasis without making text unnecessarily small or oversized.
- Check text against the actual visible borders, background shapes and neighboring decorative marks, including rotated tabs and diagonal badges. Leave comfortable, balanced space on every relevant side; prevent text, accents or effects from touching or crossing the boundary.
- Check horizontal and vertical alignment within buttons, badges, cards and between decorative marks. Center by visual weight within the shape the viewer actually sees, not mechanically by the layer or shape's bounding box. Account for clipped or off-canvas parts, rounded ends, asymmetric borders, decorative artwork, rotated text, glyph shape and Thai ascenders or descenders. Use bounds only as a starting point; inspect the actual rendering at a useful close-up scale, make small optical adjustments in either direction, and re-render to verify. Compare repeated buttons side by side for consistent perceived alignment.
- Treat each price as a cohesive group: maintain its intended size hierarchy, use the same actual font variant, tune the gaps between currency, digits and unit, align their baselines naturally, and center the complete group within its card. Compare equivalent groups side by side.
- Also use judgment to catch any other evident defects, such as collisions, awkward line breaks, imbalanced density, inconsistent treatments, weak readability, distracting overlaps, unintended color or effect changes, and mismatched repeated elements. Consider the specific design and script rather than forcing generic measurements; do not alter intentional art or expand beyond the requested scope.
- Fix issues within the user's authorized scope, render and visually inspect again, and repeat until the changed areas fit and read naturally and the page feels coherent. Preserve editable text and existing artwork. If the preview or a needed check cannot be obtained, state the limitation rather than claiming visual approval.

For this user, deliver one clearly named final PSD per requested version and avoid leaving intermediate PSD tabs open. Keep original or unrelated documents that the user already had open. Close only temporary working documents created by the task; keep the final PSD active. After confirming the final PSD is saved and usable, remove temporary working backups created solely for the task so they do not consume disk space. Do not delete originals, unrelated files, or discard possible user edits.

# 后台配置与上传边界核实方法

公开版不包含私人后台地址、接口字段、登录数据、活动链接或测量档案。以下为核实方法，不表示已测试任何目标后台。

## 模块配置

先只读核对用户提供的后台行列、模块顺序、数量及可移动范围，再建立离线layout与module_configs。每行单列或双列，两列背景共用较高内容所需的行高。不能将后台允许模块移动解释为可任意重复实例或改变内部定位。

可选example_backend_v2仅为离线示例：Banner可重复，business_line=repeat_packages时套餐模块可重复，其他模块单实例；缩放计算宽度限制在1200至3840。它不是任何真实后台标识。目标规则不同则不要选用该预设，先核实实际约束并调整适配，不向生产接口提交这些离线键。

## 上传与文字字段

逐项记录素材角色、真实上传位置、显示宽高、缩放方式及文字由谁提供。角色包括头图、模块背景、套餐普通态／选中态、二维码背景、抽奖主体／按钮、任务底图及状态按钮、规则／记录入口。不能从设计图层名或默认配置对象猜测上传字段；没有核实的映射标为待核实。

单套餐只有普通态；多个实际套餐才需要普通态与选中态并默认选中一个，二维码面板不计入套餐数。后台尺寸提示不自动等于实际显示尺寸；需查看实际页面或可信设计规范。前端检查不证明服务器不压缩、不转码。

## 上传素材与制作源

默认交付可自行添加文案的无字底图，预览文案单独叠加。无字底图不等于后台会自动补字；仅在核实真实文字字段后才声明可自动回填。用户要求含真实文案的直传图时，依本次完整文案和renderer另合成PNG，不覆盖无字源。独立标题PNG也不等于后台存在标题上传位。

按[素材交付](material-delivery.md)区分正式素材、预览和制作档案，成品统一2倍导出，核对实际上传尺寸及回填效果。尺寸、清单和来源链校验不证明真实登录、购买、支付、抽奖或兑换成功；本技能不自动修改后台。

## 二维码收银台背景

二维码背景独立于套餐卡及整模块背景，使用package.qr-background角色。核实二维码、名称、金额、备注和支付图标是否由前台动态叠加；动态内容不能烘焙进无字底图，扫码区域保持简单干净。200×280显示、400×560导出及120×120二维码内容区仅为尺寸示例；实际大小、白边和定位需由本次目标页面验证，不混用弹窗规格。CSS证据与DOM实测分别记录，未显示的节点不可声称已测量或支付测试。

## 新增翻牌与积分兑换的证据边界

按[PC规范](pc-flip-points.md)核对结构、数量和状态。参考预设不证明目标后台具备对应上传字段或真实交互；先记录当前用户有权提供的设计与renderer证据，移动端另行核实。

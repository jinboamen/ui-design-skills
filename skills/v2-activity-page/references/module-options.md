# 模块可选配置与变体

本节提供通用模块配置示例，不包含私人设计稿或节点标识。实际选项、数量、组合和尺寸必须按本次目标后台核实；示例不代表任何后台已支持。

## 待核实的配置示例

| 模块 | 配置示例 | 使用方式 |
| --- | --- | --- |
| 套餐售卖 | 1个套餐、2个套餐；整行及半行版本 | 读取本次实际套餐数、收银台模式与状态；1/2是示例，不擅自定义最大值；扫码区域不计作额外套餐 |
| 盲盒抽奖 | 无中奖播报／有中奖播报；整行及半行版本 | 奖品数量、名称、顺序、抽奖次数独立配置，不因图中展示若干奖品而固定数量 |
| 翻牌抽奖（PC） | 2／3／4／6／8张；整行与半行；正反面及高亮、抽奖／选牌提示、中奖弹窗 | 用户选择后启用，牌数与奖池数量／抽奖次数分别记录；按[新增PC规范](pc-flip-points.md)制作，移动端暂不纳入 |
| 积分兑换（PC） | 1～15个奖品样例、整行版本；库存角标；兑换／已抢光／已兑换三态 | 独立可选模块，不替换默认抽奖；真实积分及限额不编造，15不是已验证后台上限；见[PC规范](pc-flip-points.md) |
| 跑马灯抽奖 | 8、10、12个奖品格；整行及半行版本；有／无中奖播报示例 | 奖品格数不等于抽奖次数；不把所有格数与播报组合都声称已逐个验证，按本次选项核对实际实现 |
| 大转盘抽奖 | 无中奖播报／有中奖播报；整行及半行版本 | 属于已识别的抽奖形式；目前技能脚本尚未实现该分支，选择后按下方[大转盘切图分层](#大转盘切图分层)补齐旋转盘面、固定的指针与按钮组合、预览和校验，不静默换成盲盒或声称已完整支持 |
| 抽奖任务／获取抽奖机会 | 1、2、3项及多个任务；整行及半行版本 | 多个任务可用4项作为排版示例；不能继续沿用V1最多3项限制，也不能把示例4项当作最大值。实际数量与类型取后台已启用任务 |
| 礼包领取 | 1～6个礼包的展示变体；整行及半行版本 | 按本次启用及数量确定排布，已展示范围不自动等于后台硬上限；未启用不询问、不生成 |
| Banner／头图 | 整行及半行版本 | 每个实例单独跟随后台位置；高度按本次线上规则和内容确定 |
| 套餐升级、扫码支付 | 可选独立模块／状态 | 核实其存在，不把未实现模块当作已支持；扫码收银台可影响套餐区域内容占用和状态素材 |


## 大转盘切图分层

大转盘按旋转与固定两层制作，从样张开始采用同一结构：

| 独立素材 | 内容与行为 |
| --- | --- |
| 转盘盘面.png | 随抽奖旋转的盘体、扇区及所属盘面装饰；不得烘焙指针、中央抽奖按钮或固定指向标记。奖品图文是否独立叠加按实际后台核实；默认无字交付不变。 |
| 转盘指针与抽奖按钮.png | 指针和抽奖按钮合为一张独立透明PNG，保持两者正确相对位置，固定叠在盘面上方，不参与盘面旋转；不能拆成两个交付文件，也不能另在盘面或模块背景保留一套相同指针／按钮。默认按钮无业务文字，预览文字另排。 |

这是切图归属要求，不是禁止指针在最终组合中覆盖盘面。指针与按钮的外形、位置、共同画布、盘面中心及旋转轴按本次后台真实槽位核实，不凭截图猜固定尺寸，也不通过移动指针迁就错误切图。盘面旋转轴与固定按钮定位分别记录，不能将组合PNG的裁边中心误作盘面圆心。组合PNG只在完整组合外沿去掉无用透明空边，指针与按钮之间为保持真实相对位置所需的内部透明区域保留；不能为了填满画布拉伸或移动两者。

样张和正式预览使用真实分层素材回填，检查固定层在上、盘面在下，并做一次轻量旋转检查：只改变盘面角度，确认指针与按钮位置／朝向不变，盘面内没有第二个跟着转的指针或按钮；无需新增整套动画或一轮生图。正式仅对选中方案按同一结构2倍导出，放入唯一的平铺正式素材目录。发现指针／按钮已经合入盘面，应从分层源关闭固定层重新导出；只有扁平图时针对盘面恢复被遮挡区域，不能仅盖住旧指针而保留旋转残影，也不能用硬擦破坏盘面细节。

现有自动生成／校验脚本尚无完整大转盘分支，此分层规则不代表已实现该分支；启用时分别核实上传字段、旋转层级和实际尺寸，缺口如实记录，不能拿盲盒或跑马灯的通过记录代替转盘验证。

## 播报选项的默认值

有／无中奖播报属于可选变体，不表示必须询问或默认展示。所有抽奖形式默认采用无播报版本，不生成播报元素、不保留其占位和额外间距；只有本次用户明确要求才启用。开启或关闭后重新计算模块自然高度，并列时按较高者同步更新两张背景。中奖记录和抽奖次数属于独立功能。

## 配置读取顺序

先使用用户已指定或实际后台的模块布局；没有指定时先说明第一行“头图／Banner＋套餐购买”、第二行“盲盒抽奖＋抽奖任务”的默认布局，用一个问题询问是否采用，明确确认后再制作；不逐项询问模块或列数，已明确确认过则不重复问。再按模块读取实际选项：套餐数／状态；抽奖形式；对应奖品数量或格数；仅用户明确要求时读取中奖播报内容并启用（默认关闭、不例行补问）；获取机会的任务数、类型、顺序与奖励规则；可选礼包数及状态。用户本次已提供的直接使用，仅逐项补问缺失值，不把整个选项目录变成每次必填问卷。默认盲盒只适用于用户和后台都未指定形式时。

明确区分三个数字：任务数量是列表有几项；奖品数／跑马灯格数是展示多少奖励；抽奖次数是用户当前拥有或某任务／购买规则发放的机会数。三者不能互相推算或代填，不因3个任务就写3次抽奖。发放频率、次数和显示初值使用后台真实规则；未知时明确待配置。

每次改变数量、抽奖形式、播报开关或内容，先计算该模块完整内容所需自然高度，再与同行另一模块比较取最大值；同排两张背景均按共同高度设计并2倍导出。不能只替换标题或拉伸同一张背景来应付不同内容量；较矮模块只延展背景与合理留白，内容尺寸比例保持。

目录表示已识别的设计选项，不等于全部生成分支、后台上传字段和线上尺寸已经验证。Figma提供功能变体，后台提供本次实际选择，线上页面提供尺寸与渲染依据；三者缺口明确记录，不混同。当前可完整执行分支仍以入口和校验器为准。


## 套餐状态交付

按同一套餐模块的实际可购买套餐数量启用状态，二维码／收银台面板不计数。只有1个套餐时仅制作、展示和交付普通态package.card，不生成package.card-selected，不显示对号、已选中标识或选择专用高亮，不配置initial_selected_id，也不要求state_contrast。2个及以上套餐才制作默认／选中两态，样张和正式组合恰好一张选中，其余普通态；优先本次指定初始项，否则第一张。以下双态、角标及状态差异要求仅适用于多个套餐。完整要求见[套餐状态](../SKILL.md#套餐卡必须有默认与选中两态)。

## 扫码背景素材

套餐使用内嵌扫码收银台时，另交付一张独立package.qr-background，上传字段须在目标后台核实；与本套套餐卡风格统一但更简洁，扫码区域不计作第三个套餐。按[二维码背景规则](../SKILL.md#独立二维码收银台背景)制作，尺寸预设200×280、2倍400×560；候选表达面板与卡片的关系，选定后只制作该套独立高清背景。不生成真实支付二维码，不把未实现的支付业务当作素材交付的一部分。

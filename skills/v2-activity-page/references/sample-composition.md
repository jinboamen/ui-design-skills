# 1倍样张合成入口

用于已完成设计的独立前景与已查看的整行背景回填。使用全局`scripts/sample_composer.py`，不在活动目录复制或改写技能脚本。它不生成图、不测后台、不改变设计，也不是美术评分器。

## 上下背景先检查，再合成候选

每套上下背景出图后先运行同一全局合成器的只读预检查模式，A／B／C分别执行，不制作三套高清包：

```text
python <全局技能目录>/scripts/sample_composer.py <本套sample-composition.json> --output <本套背景检查.png> --background-review-only
```

只需rows与width／height已填好；前景可以尚未制作。脚本验证背景来源与原生整行尺寸，原像素组合整页背景，不缩放、不修图、不贴KV；输出组合图和`.transitions.pending.json`，所有视觉状态均为pending。实际查看该图的整页明暗关系与每条横向交界左、中、右，按[上下环境与明暗接续](design-quality.md#上下背景的环境与明暗接续)判断，不能从独立素材或轮次名称推断通过。

将生成的vertical_transitions模板合入该套manifest，逐项填写实际观察：每对相邻行包含upper_row／lower_row零基索引、upper_sha256／lower_sha256及review，review的left、center、right、overall_tone各含status与observation。先按本轮background_mode判断：segmented的left／center／right分别记录上下章节是否清楚，continuous分别记录空间是否连续；每项同时检查明暗协调，overall_tone再看整页关系和下方大面积基调。任何一处模式不符或明暗跳变均填写revise并仅返修该下方；无问题才写pass。检查覆盖所有实际相邻行，不限默认四模块。明显分区仅右侧成立、左侧或中间道路／地面／色面无意贯通，同样不通过；有意章节边界不当作技术接缝抹平，同行左右仍须连续。上方深暗、下方突然通亮，整片变亮、边缘亮带突起均不得因“明显分区”或背景单独漂亮通过；具体用户明确指定该色彩章节的，按其实际要求判断并如实记录，不能从推荐选项推定授权。

正常合成现在要求每对相邻行的四项均pass且非空，并绑定当前两行文件SHA256；少一项、失败或换图沿用旧记录都被拦截。单行无上下交界不要求凑记录。三套分别绑定自己的实际背景，不用A的通过结论代替B／C；更换任一行后重新生成本套检查图并实际查看，不批量重写pass。脚本只拦缺检查、错来源和已记录失败，不能判断光影是否自然或文字记录是否真实，不能把通过脚本当视觉验收。

## 制作顺序

新一轮A／B／C按[三套首图分别延展](selected-design-reproduction.md#三套首图分别延展各自定稿)各自固定首图，三个manifest的首行分别引用对应方案的真实母图／1920派生图，不将同一首图默认复用给三套。布局骨架仍共用，用户已有明确固定首图时按其范围执行。

首图按[第一轮首图直接定稿](selected-design-reproduction.md#第一轮首图直接定稿)固定用户认可的完整扩展原始输出，未指定时默认第一轮；校验只读，不修补或替换源图。原始母图与1920整行预览派生图分别记录路径、尺寸和SHA256；这里只接受该预览图作为首行背景，不能重新回贴原KV或重建左右背景。原画保持、接缝自然两项实际查看并记录观察；有问题如实登记而非自动重画或伪造通过。

已有真实尺寸配置直接复用。每个方案在制作档案写一份`sample-composition.json`，由助手从实际文件、SHA256及本次布局自动填充，用户不用写配置。只记录1倍组合必需的代表前景，不制作三套正式素材包。重复组件复用同一源。

按同一套餐模块的实际可购买套餐数量启用状态，二维码／收银台面板不计数。只有1个套餐时仅制作、展示和交付普通态package.card，不生成package.card-selected，不显示对号、已选中标识或选择专用高亮，不配置initial_selected_id，也不要求state_contrast。2个及以上套餐才制作默认／选中两态，样张和正式组合恰好一张选中，其余普通态；优先本次指定初始项，否则第一张。以下双态、角标及状态差异要求仅适用于多个套餐。清单中单套餐登记count:1及package.card，省略initial_selected_id和state_contrast；多个套餐登记实际count及唯一选中项和真实状态观察。二维码使用`package.qr-background`，不计入套餐选择。套餐两态与二维码面板源图必须先按[端正结构要求](design-quality.md#同一套控件的斜直与方向统一)实际查看：主边水平／垂直，切角仅在角部；不能以画布矩形、无变换参数或内部文字端正代替外框检查。选中卡按[双态与角标安全区](../SKILL.md#套餐卡必须有默认与选中两态)显示小型辅助角标及明显色面差异，角标整组含底片／描边／阴影均须克制，不做大徽章或抢正文注意：隐藏对号后仍可辨认选中，完整角标在正文安全区外，不直接悬贴名称旁；未选中卡和二维码不带对号；用户明确取消对号时按其要求使用清晰替代标识。state_contrast观察须指出实际对号位置、可见性及两态差异，不能只因role命名为selected就填pass。状态不能只靠不同文字或文件名冒充；记录实际视觉检查。

原KV／适配KV只能包含在已固定背景里，原KV哈希登记在`protected_kv_sha256`以防误当装饰回填。脚本不接受hero/banner/background前景角色，不接收额外KV图层，不缩放背景。文字和标题先校对、按真实字号排版后以透明前景输入；卡片/按钮外壳按实际比例制作，不用非等比缩放修尺寸，不从整图按亮度阈值抠字或擦掉背景蒙混成独立前景。

## 盲盒前景不得携带场景色块

先按[通用融合方法](selected-design-reproduction.md#盲盒与环境的通用融合方法)在实际画风中建立主体与环境关系，再分层；environment_match记录本套实际采用的承托、光影或图形呼应及拆分回填结果，不默认要求绿色光圈、写实地面或通用椭圆影。

从1倍样张开始执行，不推迟到正式切图：`blind.art`仅保留盒体、盒体表面受光及贴合轮廓的自身发光；地面、承托区域、投射／接触阴影、反射、雾气和外围氛围写入对应整行背景，围绕真实盒体落点设计。不能把生成图的矩形场景裁块作为盒体前景，也不能靠整体降透明度、羽化矩形或加模糊遮掉色差。独立装饰角色不得用来绕过环境归属。

必须先按[接触关系制作步骤](selected-design-reproduction.md#先建立接触关系再拆分输出)完成实际盒体与环境的共同组合，再拆出干净透明盒体，并把环境保留在整行背景；禁止压扁整盒alpha加模糊／翻转压扁盒体的通用阴影反射后处理，也不得由脚本预填融合通过；以同一位置回填检查后才固定背景。若已固定背景缺少环境，只修该背景中盒体对应局部并重新检查、更新来源；不得额外叠一块小场景冒充原背景复用，也不得擦光环境让盒体悬空。

每个`blind.art`登记`environment_row_sha256`，引用本次实际背景行，并在`review`登记`clean_cutout`和`environment_match`，形状与其他检查一样为`status`和`observation`。助手实际查看透明图在浅底、深底以及最终背景上的边缘：不能有矩形底色、残留纹理、灰／绿脏边或一圈不属于盒体的环境；再隐藏盒体，确认整行背景本身有对应环境和落点，恢复后无方形断口且阴影／反光贴合。记录具体观察，不能只写“已通过”。这些查看并入现有集中检查，不增加生图或用户审批轮次。

脚本拒绝完全不透明或完全不可见的盲盒前景，检查环境来源及上述查看记录。存在透明像素不等于抠图干净：四角透明但内部仍夹带矩形底图的素材，必须在实际视觉检查中退回，不能宣称自动检测已覆盖。


## 任务卡比例与盲盒落点必须绑定实际组合

在制作提示词和样张骨架中先固定1倍几何，再生成相应比例的代表件。任务卡不能由模型按“细长任务条”自行猜测：当前已核实双列为600×120（5:1），任务按钮160×60，右距40且垂直居中；卡片主面须占据实际高度，不能把600×60细条塞进600×120透明画布。三套与正式版使用同一已核实比例，比较图仅将完整1920样张统一等比缩小，不能单独压低任务卡或按钮。单列／新renderer／用户明确新规格使用本次实际尺寸及来源，不强套当前双列数值。空间不足先核对行高与排布，不靠压扁卡片或缩字解决。

合成配置增加`task_modules`：确认目标后台适用600×120卡片、160×60按钮、右距40及垂直居中预设后，双列每模块登记`{"profile":"example_v2_dual","count":3,"proportion_and_content":{"status":"pending","observation":""}}`；不同实测规格用`profile:"measured"`，另填`card_size:[宽,高]`、`button_size:[宽,高]`、`size_source`（本次实测记录或用户明确尺寸的来源）。每张`task.card`有唯一id与module_id，每张独立`task.button`以`task_card_id`指向所属卡片。脚本核对显示尺寸、可见主体占画布、数量、按钮归属与位置；素材外沿的切角仍可保留。若设计使用半透明主面导致自动可见范围检查失败，实际检查并有界扩展检测，不伪造尺寸或改角色绕过。`proportion_and_content`实际查看后才记pass：检查主面高度、标题／说明行高与上下留白、按钮颜色和尺寸。Alpha范围检测不能判断内框或内容是否被压细，仍需看图。

每个`blind.art`增加`environment_placement`，与既有环境检查一起记录，不新增用户问答：

```json
{"row_index":1,"row_sha256":"对应背景行真实SHA256","art_sha256":"当前透明盒体真实SHA256","rect":[355,980,250,250],"source_contact":[250,460],"row_contact":[480,530]}
```

上述仅为坐标换算示例：背景行从整页y=680开始、盒体源500×500时，源中盒底参考点(250,460)映射到行内(480,530)。`rect`是整页1倍坐标，`source_contact`是实际源PNG内可见盒底的参考点，`row_contact`是对应背景行内同一接触点；不是盒体容器底边，也不是整片投影的中心。按实际盒底／接收面选点，禁止简单复制公式结果冒充已查看背景。倾斜投影可以向侧方延伸，检查它从真实接触区起；不要求投影中心与盒体中心重合。明确悬浮或平面设计可登记同一组合中的对应配准点，并在environment_match说明空间关系，不强加落地阴影。

先按实际盒体和位置完成共同组合，再拆分，保留源画布坐标与透明边界。透明PNG若trim，必须把裁切偏移计入定位并重新验证；禁止trim后自动重新居中，或把盒体缩到250×250却沿用大场景的影子。样张与2倍输出共享这套1倍坐标及同一个缩放倍率，不分别对背景与盒体执行contain／cover。

合成器把背景行索引与哈希、盒体哈希、显示rect及接触点换算绑定起来；换盒体、裁边、移动或缩放会使旧记录失效，须重新实际回填查看后登记。机械允许最多1个设计像素的取整误差，不替代视觉贴合。先隐藏盒体看阴影起点，再恢复盒体查看接触线和侧向投影，并与拆分前共同组合对照。错位先修坐标，源中关系错误才修对应背景局部；不移动已确认业务槽位迁就影子，不叠通用阴影遮错、不重做已认可首图。最终environment_match须描述实际接触关系，不能仅凭字段齐全记pass。

## 购买按钮的卡内安全区

按[边框净空](design-quality.md#卡内按钮与边框之间保留可见净空)先看真实卡片内沿，排除边框、切角、装饰及应保留的留白后，在每张套餐卡登记`button_safe_rect:[x,y,w,h]`，使用相对卡片左上角的1倍设计坐标。该区域是按钮整张素材含阴影／发光可使用的内部范围，不是卡片外框，也不是描着已贴边按钮倒填的区域。由助手从本次设计与实际布局登记，用户不用填写。

每个独立`package.button`填写`module_id`与`card_id`指向所属套餐卡，并在`review.edge_clearance`记录实际查看后的status／observation，指出左右、底部的净空及正文避让。脚本要求安全区严格位于卡内、按钮完整落入安全区、归属唯一且观察通过；尺寸正确仍不能证明边框形状或阴影没有侵入，实际回填仍须查看。不能通过裁掉按钮透明画布或把按钮烘焙进卡片绕过检查。多个套餐的两态均应用同一安全区，不影响单套餐无选中态规则。

## 奖品文案容量检查

奖品底框源先按[两行名称安全区](design-quality.md#奖品名称默认预留至少两行)核对内部比例，使用实际字号与行高试排一行／两行内容；没有实图／真实名称时沿已允许示意范围检查，不把短占位当最终容量。常态与高亮实际组合都需能完整显示两行名称，底图窄名称条不能靠预览把字放到图片区或条外蒙混通过。该检查并入现有组合记录，不额外制作一套素材或询问用户。

## 跑马灯高亮必须实际回填

跑马灯常态格使用marquee.item或marquee.card，中心使用marquee.center；每个跑马灯module_id在样张中必须有且仅有一个marquee.highlight，与一个外围常态格rect完全一致，图层顺序在该格上方，不能用普通decoration代替。高亮记录normal_source_sha256为该格常态源哈希，并在review.highlight_visibility记录status和observation。文字与实图按可读的正确顺序组合；高亮源自身保护图文可见，不能靠将其藏到常态格下面应付检查。

实际在整页与正常1倍尺寸查看：外围哪格在轮转高亮能否立即分辨，主面／内侧光面颜色及亮度是否明显区别，其余格是否常态，奖品图和名称是否仍清楚。只做alpha轮廓细线、常态框略加亮、中心按钮高亮、CSS临时效果或仅口头说有高亮都不通过。未提供实图时保留已允许示意层，不能把文字区盖掉。

合成器检查是否实际登记一个高亮、是否对准格子、来源是否匹配、图层顺序与可见像素及检查记录；不能判断亮度差够不够或内容是否真可读，必须实际看图，弱描边效果不能凭字段齐全通过。素材尚未完成时如实记revise并制作本套高亮代表件，不省略后展示为可选完整样张。

## 同组标题按实际字级检查

默认双列下方的盲盒与任务标题登记为同一`title_group`，上方套餐标题可另组；布局改变时按已确认分组，不为通过检查把下方两个标题拆成独立组。每个`module.title`登记`typography: {"style_id":"实际文字母版标识", "source_font_size_px":实际源字号整数}`。字号取真实排版源；生图艺术字先校对并建立同组文字母版，不能凭文件高度猜字号或虚填相同值。主标题文字与装饰高度分开看，不能以两张PNG同高推断字体一样大。

配置顶层`title_groups`按组登记，例如`{"lower":{"count":2,"title_consistency":{"status":"pass","observation":"实际查看两标题字级、字高及基线的结果"}}}`。脚本核对同组样式及源字号乘最终缩放后的实际字号，拦截长标题独立等比缩小。它不能从PNG自动识别字形或验证填报字号真实性，仍须实际看同尺寸组合的可见字高、字重与基线，不能只用字段相同判通过。

先以最长标题在真实可用槽位内确定同组字号，再用同一字形、字号、字重和缩放渲染短标题。文字总宽、底板和装饰长度可不同；禁止为统一标题图片宽度单独缩小长标题或放大短标题。长标题放不下时先收敛不必要的装饰与留白；仍不够则在规格允许内两标题共同调整字号。固定规格无法容纳时明确冲突，不挤压文字、不自行改文案或移动业务槽位。基础形态样张也必须遵守，不推迟到精修。

## 配置形状

路径相对配置文件所在目录，以下是字段示例，尺寸、文件及哈希必须换为本次实际值。`foregrounds`按从后到前排列；同一模块中的卡片按后台顺序登记。原生文字也可以先用已有工具渲染为1倍透明PNG，保持实际字号与字形，脚本只负责定位合成。

```json
{
  "width": 1920,
  "height": 680,
  "protected_kv_sha256": ["原始KV文件真实SHA256"],
  "rows": [{
    "file": "source/top-row-approved.png",
    "sha256": "该整行文件真实SHA256",
    "y": 0,
    "contains_kv": true,
    "review": {
      "seams": {"status": "pass", "observation": "填写实际边界查看结果"},
      "kv_preserved": {"status": "pass", "observation": "填写原图保护核对结果"}
    }
  }],
  "foregrounds": [
    {"id":"p1","module_id":"package","role":"package.card-selected","file":"source/card-selected.png","sha256":"实际哈希","rect":[1110,260,200,280]},
    {"id":"p2","module_id":"package","role":"package.card","file":"source/card-default.png","sha256":"实际哈希","rect":[1330,260,200,280]}
  ],
  "package_modules": {
    "package": {
      "count": 2,
      "initial_selected_id": "p1",
      "state_contrast": {"status":"pass","observation":"填写选中与未选中实际区别"}
    }
  }
}
```

继续登记实际启用的标题、二维码、任务、奖品、按钮及其文字，不照抄示例坐标。没有套餐时`package_modules`为空对象。允许的前景角色见脚本ROLES；缺少本次所需角色应在全局入口有界扩展并验证，不另写绕过检查的临时合成器。

```powershell
python <技能目录>/scripts/sample_composer.py <配置文件绝对路径> --output <样张绝对路径>
```

## 配色执行与实际回填检查

此步骤沿用既有集中检查，不另加用户审批或生成轮次。任务卡比例、按钮净空、盲盒落点的机械检查与配色检查是不同结论；更新技能、调用最新合成器、素材尺寸正确都不能证明主辅色相已落实。

1. **先核对修订范围。** 在本次已有analysis中列出用户要求改变的属性及明确保留的属性。不能把保留背景／盒体造型扩大解释为保留所有前景配色，也不能把只修几何解释为已完成所有新版设计要求。明确禁止改色时不越界改色，将未完成的配色问题保留为待处理。
2. **核对实际发送的提示词。** 颜色属于本轮修订时，删除与新色面分工相冲突的旧“保持原palette／only geometry／原色不变”等约束；逐类带入主面、辅助结构面、操作面各自的实际颜色和面积，而非只在总规则写“有色彩层次”。复用旧素材前也按新目标查看，旧素材不是因文件存在就自动合格。未调整的类别如实记录，不得说整套已重新配色。
3. **只评实际回填。** 在1920实际显示与整页缩览中看每套的非KV功能区，再恢复KV同屏比较；不以A为紫色、B为蓝色、C为另一种紫色代替每套内部的色相分工。浅白阅读面与青色按钮可以形成有效的承托与行动关系，但不能只凭它们存在就宣称整套有层次；新增大面积异色也不自动算提升。分别检查前景是否仍单调、颜色是否自然协调、分配是否有功能依据、与KV是否相容，具体判断按[前景色相与有效色面](design-quality.md#前景色相与有效色面)。

将现有color_hierarchy／kv_identity的实际观察写入本套`color-review.json`，而非重新制作证明图；字段如下，初始均为pending，实际查看后才逐项写pass或revise。SHA256分别绑定当前manifest和合成输出文件。多个方案分别查看、分别记录，不用循环为三套填同一句通过结论。

```json
{
  "manifest_sha256":"当前sample-composition.json的真实哈希",
  "preview_sha256":"当前完整样张PNG的真实哈希",
  "palette_coherence":{"status":"pending","observation":"卡面、边框、操作与背景是否相容，有无为了异色而加入的孤立色块"},
  "visual_variety":{"status":"pending","observation":"主面、明暗、饱和度、面积及材质有哪些有效变化，有无整套同重量的单调"},
  "functional_distribution":{"status":"pending","observation":"色面面积、同类复用、按钮与卡面及状态如何分工"},
  "kv_relationship":{"status":"pending","observation":"实际功能区与KV的冷暖、饱和度、面积和主次是否相容"}
}
```

不再要求palette_mode或单色例外授权。协调、变化、功能、KV关系四项分别查看并通过；同色系不自动失败，多色系不自动通过。旧hue_separation记录不能直接改名或继承通过状态，须按当前实际图片重新判断这四项。明确用户／品牌限制仍按其要求执行。配色观察不能由脚本根据提示词、角色名、色号数量或HSV色相阈值自动填pass。脚本只检查是否完成记录及其来源是否仍有效，不判断审美，也无法证明观察真实。

```text
python <全局技能目录>/scripts/review_candidate.py <sample-composition.json> <完整样张.png> <color-review.json>
```

实际查看且此检查通过后才可称配色已验收；合成输出仍可用于待修检查。若失败，按实际缺项修受影响前景并在同一背景、同一布局回填，不重做已认可KV、不为凑差异乱换整页色调，也不只重跑合成器。新图／新manifest／源文件更换后，旧观察失效。仅维护skill时用已失败样张验证检查是否能拒绝漏检，并如实说明没有重生成美术，不能把校验程序测试通过说成设计效果已改善。

## 检查与输出

脚本在写文件前检查：整行尺寸、连续行高、不透明背景、固定来源哈希、禁止KV二次叠加的角色及已登记源、前景坐标/比例、套餐数量、单套餐禁止选中态及多套餐唯一初始选中、相同像素冒充双态、背景人工检查是否尚未通过。出现错误先修源或配置，不在输出后补贴KV、改色或拉伸。

输出1倍完整样张、背景单独回填图及轻量来源记录。背景单独回填图必须与固定整行源一致；这只能防止合成阶段换源或错拼，不能证明源图本来没有接缝。来源记录的`final_visual_review`默认`pending`，实际查看整页及必要局部后再在现有设计证据中记结果；不得把机械检查pass解释为美术合格。

沿既有一次集中选样检查查看中线和原KV边缘、套餐状态、标题字形、盲盒落点及前景清晰度。发现问题只修相应素材再跑一次合成，不增加参考搜索、整页AI重抽、三套高清或用户审批。用户只要求优化Skill时，不运行它修改旧活动样张。

修复仍失败时遵循[同一路径失败后的定位与继续](design-quality.md#同一路径失败后的定位与继续)：先区分源图错误与合成错误，再换对应修法；本入口报错或两次局部返修未改善，不自动意味着整项任务结束。

## 大转盘样张使用真实分层

大转盘按[module-options中的切图分层](module-options.md#大转盘切图分层)组合：旋转盘面一层，指针与抽奖按钮合成的透明PNG固定在上层。不能用含指针／按钮的整张转盘图冒充分层样张，不能把二者分别贴入盘面或背景。预览可展示两层叠加后的完整效果，拆开看盘面时不得残留固定控件；轻量旋转检查仅旋转盘面，指针及按钮不动且无重复残影。该检查并入既有选样／交付检查，不新增三套动效或高清制作。当前sample_composer无完整转盘分支时如实标记能力缺口，不能只添加角色名就声称已完成自动分层或旋转验证。
